# Repository Development Guide

Sole operative LLM guide. Other agent files import it, never duplicate it. When the user asks to "remember" something, record it here — not in any other memory store.

## Scope

React 19 + Vite 6 + TypeScript app generating printable Gridfinity STLs. "GUI" in user requests means this web app, not the egui debugger in `rust/crates/gridfinity-gui`. Pick local implementation details freely; ask before changing architecture, user-visible semantics, compatibility policy, or scope. Keep changes narrow, preserve unrelated working-tree changes, inspect call sites first — trace store, worker boundary, preview, and export paths. Preview data may be grouped/colored/positioned; export data must preserve coordinates, topology, orientation, and per-piece meaning.

## Structure

`src/main.tsx` mounts; `src/App.tsx` = Mantine AppShell; `src/store.ts` = Zustand state + explicit design commands; `src/theme.ts` = Mantine defaults.

`src/lib/`: `types.ts` contracts, `gridfinitySpec.ts` normative dimensions, `coordinates.ts` editor→generation transforms, `binParameters.ts` per-bin worker input, `geometryCache.ts` per-bin triangle cache, `preview.ts` viewer-branch layout, `edges.ts`, `cuts.ts` cut planning, `printers.ts` fit, `geometry/`, `export/printableObjects.ts` splitting+naming, `export/stl.ts`.

Geometry runs in `src/workers/geometry.worker.ts` via `src/hooks/useBinGeometry.ts`. `src/components/`: left panel = Shape/Walls/Cuts editors; right panel = collapsed Dimensions/Features/Printer-fit/Display accordions; `viewer/ModelViewer.tsx` hosts the Rust WebGL2 renderer drawing the kernel's render vertices directly. Scripts in `scripts/`; Vitest beside source as `*.test.ts`; browser tests in `e2e/`. This guide is the canonical spec and architecture record.

## Implementation

TypeScript ESM, function components, two-space indent. `PascalCase.tsx`, `useName.ts`, camelCase helper exports. Shared contracts in `types.ts`, domain logic in `src/lib/`.

Prefer Mantine controls/layout over custom UI. Cross-app control styling → `theme.ts`; global layout and documented library workarounds → `src/index.css`; SVG editor styles → `src/components/sidebar/editor.css`. No fixed design constants in JSX unless data-driven.

Tabs read/write only through `useAppStore()` commands. Keep `Design`, `BinParameters`, `Bin` plain and structured-clone compatible. A shape change resets that bin's openings, walls, and cuts, then reseeds required cuts. The UI alone enforces validity — controls constrain their own ranges and dependent values; no store clamping, no validation layer. The UI derives complete piece groups before invoking geometry. Preview offsets come from `previewLayout()` after generation, never worker input/output.

`generateGeometry()` is the sole production geometry path: takes trusted generation-ready `BinParameters[]`, builds each logical bin once, intersects with piece footprints, returns pieces grouped per `Bin`. Export splits them into named `PrintableObject`s via `toPrintableObjects()`. Author geometry with exact native `manifold-3d` `CrossSection`/`Manifold` ops — never coarse tolerances or padding (caused terraced fillets). Geometry must not plan cuts, name parts, inspect printers, validate input, normalize coordinates, or localize; manifoldness is verified in the Rust kernel only. `manifoldTriangles()` is the one extraction boundary: quantizes to serialized float32 with 1-micron weld and degenerate-facet repair — no other repair exists.

`Design` stays in editor row-down coordinates. `buildBinParameters()` mirrors every bin together across the design's maximum occupied row; parameters, geometry, and echoed `BinPiece.cells` share that generation frame. Partition pieces before mirroring so piece indexes keep editor meaning. The camera is natively Z-up: never transform meshes for orientation; default and reset orbit must face the layout as the editor does. Preview and STL export consume the identical global-coordinate `BinPiece.vertices` buffer, with multipart spacing applied only via viewer transforms after cuts are mirrored into generation coordinates. That buffer is `Tessellation::welded_render_buffer()`: six floats per vertex (position, then the kernel's analytic surface normal), three vertices per triangle, no indexing. Positions are snapped to the 1-micron weld representative and weld-degenerate triangles dropped, so the exported soup stays watertight under exact comparison exactly as the old indexed `to_mesh()` path did — never feed the raw `render_buffer()` to export, whose unwelded per-face samples leak. The viewer shades those analytic normals smoothly through the one shared path, `gridfinity_render::append_smooth_shaded`; there is no flat-shading or normal-recomputation path, and adding one back would fork the debugger and the web app again. Combine solids with manifold booleans; use `CrossSection.offset` for inward 2D offsets.

`useBinGeometry` schedules on the leading edge, not a debounce: a design change with no run in flight starts generation immediately, and a change arriving mid-run only sets a dirty flag that restarts once the in-flight run settles. That keeps the preview live while the user paints — the kernel is fast enough that a held gesture regenerates continuously — while coalescing bursts to at most one queued rebuild, so workers never accumulate a backlog whose tail is stale. Every exit path from a run (success, cache-only hit, empty design, worker error, superseded revision) must settle, or the dirty flag strands and the preview freezes.

The alpha generator assumes every bin is edge-connected and valid. Add no geometry-side component normalization, repair, rejection, fallback, or tests defining disconnected-bin behavior. Enclosed holes stay supported. Full spec/editing/cut/coordinate/invalid-input rules live in this guide; rule changes update it and the happy-path tests together.

Changing the geometry pipeline (`src/lib/geometry/`, `src/workers/geometry.worker.ts`, `src/hooks/useBinGeometry.ts`, `src/lib/{binParameters,coordinates,geometryCache,preview,cuts,gridfinitySpec,edges}.ts`, `src/lib/export/printableObjects.ts`) or the viewer (`src/components/viewer/ModelViewer.tsx`, `rust/crates/gridfinity-render/`, `rust/crates/gridfinity-wasm/src/viewer.rs`) requires updating the matching section of this guide in the same change.

`rust/crates/gridfinity-render` is a shared `glow`+`glam` crate with no egui or wasm deps, consumed by the egui debugger (`gridfinity-gui`) and the web app (`gridfinity-wasm`). Keep front-end concerns out; change its camera, shaders, or vertex format only with both consumers in mind.

`Renderer::paint` is a multi-pass chain, not one draw. Offscreen prepasses first — a front-face-culled shadow map, a half-res depth+normal prepass feeding screen-space GI and its depth-weighted blur, and a planar floor reflection. The reflection is a **genuine second render of the scene at full viewport resolution**, not a cheapened proxy: the geometry is mirrored about `min.z`, front-face culled to compensate for the flipped winding, shaded through the same mesh program with the *mirrored* eye so specular comes from the reflected view direction, and given **its own ambient-occlusion pass from the mirrored camera** — which is why the reflection runs before the main AO and the two share the AO targets, the mirrored result being consumed before the main view overwrites them. Feeding `draw_occlusion` the mirrored `view_proj` is sufficient because `DEPTH_NORMAL_FS` writes un-mirrored world normals and `u_inv_view_proj` recovers un-mirrored world positions, so pairing them with the mirrored eye is consistent. The remaining blur is a **gloss** term (`REFLECTION_GLOSS_RADIUS`) matching `FLOOR_ROUGHNESS`, not a device for hiding upscaling. Both the reflection and the bloom go through one shared separable gaussian (`GAUSSIAN_BLUR_FS`, run twice with `u_direction`), and it blurs **RGBA, not RGB** — the reflection's alpha is premultiplied coverage, and a blur that drops it cannot be composited correctly. Do not replace it with a fixed-radius multi-tap kernel: the reflection previously used an 8-tap ring at one radius, which convolves a silhouette into eight displaced copies of its own edge and reads on screen as ghosting. Then the scene (backdrop, floor, mesh, wireframe) draws into an offscreen `RGBA16F` target, a bright-pass and separable gaussian build the bloom, and a resolve pass applies vignette + ACES tonemap + sRGB before the result blits into the caller's viewport rect.

**Occlusion renders at full resolution** (`occlusion_divisor` is 1). Half-res was cheaper but its background is unoccluded, so bilinearly upsampling across a silhouette blends occluded and unoccluded sides over a two-pixel gap — a halo around the model. The depth-weighted blur made it worse by sharpening the edge inside the buffer, and carrying indirect radiance rather than a scalar made the bleed coloured. A depth-aware upsample would also fix it; not resampling at all is simpler and exact.

**The occlusion buffer carries indirect radiance, not a scalar.** Its `rgb` is `env_irradiance(bent_normal) * ao` plus a colour bounce gathered from the previous accumulation buffer, and `a` is the raw AO the specular-occlusion term needs; the mesh shader adds `albedo * gi.rgb` instead of `albedo * env_irradiance(n) * ao`, so ambient light arrives from the direction that is actually unoccluded. The bounce reads the accumulator, which is the only screen-aligned colour buffer available before the scene draws, so it is suppressed on the first sample after any change (nothing valid is in there yet) and in the reflection's occlusion pass (whose screen space is mirrored and does not match).

**Sampling must vary per accumulation sample or the accumulator cannot denoise it.** The occlusion kernel is a cosine-weighted hemisphere over a golden-angle sequence, rotated by interleaved gradient noise seeded with **both** the pixel and `u_frame`. An earlier kernel hashed only `gl_FragCoord` and the sample index, so every accumulated frame drew the identical pattern and 48 samples of averaging converged to exactly the noise you started with — it read as pure noise no matter how long the camera sat still. Any future stochastic pass has to take the same frame seed.

**The still image is supersampled by accumulation.** While nothing changes, each frame jitters the projection by a Halton(2,3) sub-pixel offset — a clip-space translation pre-multiplied onto `view_proj`, so every camera-dependent pass (SSAO, reflection, the scene) jitters coherently — and blends into a persistent linear-HDR accumulator with `CONSTANT_ALPHA` at `1/(n+1)`, an exact running mean. That is why SSAO's fixed-pattern noise resolves into smooth occlusion when you stop moving. An `AccumulationKey` (view-projection bits, viewport rect, quality, and a `generation` counter bumped by every upload) resets the sample count the instant anything changes, so motion always shows a correct single-sample frame. FXAA only runs while `accumulated <= FXAA_SAMPLE_LIMIT`; past that the image is genuinely supersampled and blurring it would throw away what was just paid for, so the final blit switches to a straight copy. Once converged the scene render and every prepass are skipped entirely and only the resolve and blit run. **A host that repaints on demand must drive this**: the debugger asks `Renderer::is_accumulating()` and requests a repaint while it is true, otherwise it stops at one sample; the web app's `requestAnimationFrame` loop already runs continuously. Two rules hold that together: **scene shaders emit linear radiance and only the resolve presents** — `scene_out()` in the shader prelude decides, from the `u_scene_ldr` uniform, whether a pass writes linear or tonemapped — and **every offscreen colour that feeds shading stays linear**, which is why the floor mixes its reflection before presenting rather than after. **`paint` owns the blend state and must never inherit it.** egui invokes a paint callback with `BLEND` enabled and premultiplied blending set up for its own UI; WebGL2 defaults it off. That divergence is not cosmetic — the reflection's gaussian blur is the one pass whose output alpha is below 1, and its target is never cleared, so under an inherited `dst = src + dst·(1 - src.a)` it composites over the *previous frame* and becomes an accumulation buffer. The symptom is a reflection that ghosts and stays put in screen space, in the debugger only, while the browser looks fine and every e2e test passes. `paint` therefore captures `BLEND` alongside the scissor flag, disables it for the whole chain, and restores it at the end; the wireframe pass is the only thing that turns it back on, and it does so around its own draws.

`Target::ensure` returning `None` is the degradation path, not an error: the renderer probes an `RGBA16F` attachment once at construction and falls back to `RGBA8` + `u_scene_ldr = 1` with bloom off, and a scene target that will not allocate drops the whole chain back to drawing straight to the default framebuffer.

**Layer lines are parallax occlusion mapping over world Z, not a texture.** The kernel hands the renderer exact analytic normals and world positions, so the print's layer profile is a periodic function of `wpos.z` alone — no UVs, no atlas, nothing to author. `layer_march` steps the view ray into the surface until it meets that profile, the hit position feeds shading and the shadow lookup, `layer_slope` perturbs the normal, and `layer_self_shadow` marches toward the key light so the grooves shade themselves. `layer_facing` fades the whole effect out as a surface turns horizontal, because a top face shows infill rather than walls. A 0.2 mm layer is only a few pixels tall, so the profile is **prefiltered analytically rather than faded out**. The bead profile is a raised cosine, which has a single harmonic; box-filtering one over a footprint of *w* periods scales it by exactly `sinc(w)`, so `layer_attenuation` applies that factor in place and the profile converges to its own mean as the footprint grows. That preserves the surface's average appearance at distance, where fading the effect to zero instead pops and flattens it. A squared-triangle profile was tried first and cannot be filtered this way — infinite harmonics leave nothing but a heuristic cutoff. `LAYER_SPECULAR_SPREAD` converts the modulation being filtered away into extra roughness, so lost detail becomes a rougher surface rather than a shimmering one. The derivative must be taken in **uniform control flow** — `fwidth` reached from inside the `lines > 0.0` branch is undefined in GLSL ES — which is why the footprint is measured at the top of `main`. **The relief displaces inward only, so the geometric silhouette stays analytic.** Outward shell displacement is what a stepped silhouette would need, and it is not available here: this is a hard-edged B-rep whose per-vertex normals diverge at every sharp edge, so expanding along them opens a `LAYER_RELIEF`-wide crack at every one. The parallax and self-occlusion are real; the outline is not.

Shading is metallic-roughness PBR with one shared path for both surfaces: GGX + height-correlated Smith + Schlick for direct light, and `ibl_specular()` for the environment — the Karis analytic DFG (`env_dfg`), multi-scatter energy compensation, and Lagarde specular occlusion from the AO buffer. **The planar reflection is not composited over the shading.** It replaces the *radiance the specular lobe samples* (`radiance = mix(env_radiance(...), reflected, coverage)`, then one `ibl_specular` call), so Fresnel and roughness decide how much of it survives. Lerping the floor's whole radiance toward the mirror image instead — which is what it used to do — paints the reflection on as a decal that slides in screen space rather than sitting in the surface, and that is what it looks like on screen. For the same reason **ambient specular is never multiplied by the directional shadow term**: a shadow blocks the key light, not the environment, and the reflection grounds the object by showing its own dark underside where it meets the floor. Both rules have tests.

Two shader-layer invariants exist because desktop GL accepts what GLSL ES rejects, and the debugger compiles the same sources under `#version 330`: **precision qualifiers must precede the baked-in scene constants** (`constants()` emits `const float`s, so `PRECISION` is prepended ahead of it), and **no two samplers of different types may share a texture unit** — `u_shadow` (`sampler2DShadow`), `u_reflection` and `u_occlusion` are assigned units 0/1/2 unconditionally, including when their pass is off, because leaving them at the default unit 0 is a draw-time `INVALID_OPERATION` in WebGL2 that silently drops the mesh. `every_fragment_source_sets_a_float_precision_before_it_declares_a_float` pins the first.

Render quality is a **pinned user setting, never adaptive** — there is no frame-time controller, and reintroducing one would make the preview change appearance under load while the user is judging a part. `Quality` (`low`/`medium`/`high`, defaulting to `high`) gates the shadow map, SSAO, reflection, bloom, FXAA and layer lines together; `low` skips the post chain entirely and draws straight to the screen, so it has no vignette. `store.ts` holds `renderQuality` as presentation state that never reaches `BinParameters` or the worker; `DisplayTab.tsx` writes it, `ModelViewer.tsx` pushes it through `viewer.set_quality()` both on creation and on change, and reads `viewer.quality()` back inside the existing render loop to publish `data-render-quality` imperatively via `dataset` — the same rule as `data-badapple-frame`, since routing per-frame reads through React state is what makes the camera stutter. The e2e spec asserts the read-back value, not the store value, so it fails if the setting stops reaching the renderer.

The `#badapple` route is an easter egg, not part of the design pipeline. It plays through `src/hooks/useBadApple.ts` over a worker pool, and everything about it is shaped to keep the main thread free: workers call `badapple_frame_vertices()`, which bakes colour into the kernel's own analytic normals so the returned buffer goes straight to `Viewer::upload_vertices` as a plain GPU upload — the main thread never expands a vertex buffer. Frames reach the viewer through the feed's `pending` ref, drained inside the existing render loop, and `data-badapple-frame` is set imperatively. Never route clip frames through React state or `add_piece`; either one re-introduces per-frame main-thread work and the camera visibly stutters.

## Validation

- `npm run lint` — Oxlint
- `npm run test` — Vitest
- `npm run build` — type-check + Vite build
- `cd rust && cargo test --release -p gridfinity-cad --lib` — geometry kernel suite, the printability gate
- `cd rust && cargo test --release --workspace` — full gate, including fuzzers and benches (slow; pre-PR only)
- `npm run test:e2e` — Chromium Playwright smoke
- `npm run classify:changes -- <base> <head>` — CI gate classification

Lint + build on every non-trivial code change. Don't add Vitest coverage by default during rapid feature development; run existing Vitest when changing printer, cut-to-part, or export behavior it covers (CI always runs all of it).

Run the Rust suite for every print-affecting change: geometry, cut/part generation, STL serialization, walls, fasteners, worker generation, geometry-consumed config. Watertightness is a B-rep property asserted by `Solid::validate` and tessellation-leak checks; no TypeScript manifold verifier exists or may be reintroduced.

**Always pass `--release` to cargo test.** These are geometry tests over thousands of faces, and an unoptimised build spends most of its wall time in `glam` and the tessellator rather than in anything being tested — the 189-test lib gate runs in 0.17s release against ~1.7s debug.

**Don't run the long targets by default.** `cargo test --release -p gridfinity-cad --lib` is the working gate; it covers the kernel and the model. Leave `--test fuzz` (150 generated bins), `--test scale` (the benches and cost-curve reports) and the `gridfinity-gui` binary's tests (the Bad Apple pipeline benches) for a deliberate pre-PR run or for CI, and say in the report that they were skipped. Run one of them by name when the change is in what it covers — `--test fuzz` for inner walls or blends, `--test scale` when a perf claim is being made.

`--release` compiles out `debug_assert!`, so nothing load-bearing may live in one. `region2d`'s box-prune guard used to, and is now a runtime-gated verification pass (`set_verify_prune`) that its own tests turn on, so it runs in release with the rest of the suite. Hold that line: a check worth having is worth running under the command everyone actually uses.

Use Playwright for every browser-visible change. Locally, equivalent manual browser verification is acceptable if the report names the method. In CI there is no fallback: if classification requires Playwright, a browser-test failure fails the check.

Never run visual or browser verification yourself — no browser automation, no screenshot capture, no ad-hoc scripts that stand in for looking at the app. Always ask the user to perform the visual check and report back what they saw. Write and hand over the test or the exact steps; the user drives the browser.

Complete means required commands finished with confirmed successful exit codes. Timeouts, truncated output, and partial runs are not successes. Final reports list checks run, results, and any required or relevant checks omitted.

## CI Classification

CI always runs lint, Vitest, build. The classifier adds gates fail-safe:

- Playwright: runtime UI, entrypoints, styles, store, hooks, workers, shared types, dependencies, build config
- Rust: geometry, cut/part generation, STL export, geometry workers, geometry-consumed config, anything under `rust/`
- Both: ambiguous shared runtime files
- Neither: docs-only, isolated test-only

Classify unrecognized paths conservatively. Leave `.github/workflows/deploy.yml` behavior alone unless deployment is explicitly in scope.

## Pull Requests

Work in a dedicated feature branch in a new worktree off latest `origin/main`, not on `main`; target `main`. Short imperative commit subjects. PRs describe user-visible changes, list validation commands, link issues, include screenshots/recordings for UI changes, call out printability and manifold implications for geometry/export changes, and carry any `AGENTS.md` updates for pipeline or viewer touches. Use `--body-file` for multiline `gh` bodies — escaped `\n` renders literally.

## Known Limitations

STL is the only wired export format.
