# CLAUDE.md

Guidance for Claude Code in this repo. Keep it current with the code. `../AGENTS.md` owns the web app and cross-cutting policy; this file owns the Rust kernel, model, renderer consumers and test targets.

**The kernel is its own crate.** `gridfinity-brep` is the B-rep engine and nothing else -- `glam` is its only dependency and no module in it names a bin, a cell or a drawer. `gridfinity-model` is the Gridfinity model on top of it, `gridfinity-project` the drawer fitter on top of that. A path below that reads `kernel/x.rs` is `crates/gridfinity-brep/src/x.rs`.

**Write style — mandatory for all agents editing this file.** Terse, telegraphic, high-density. Fragments over sentences. Drop filler, hedging, connective prose. Keep every technical fact (names, paths, constants, measured numbers, test names); cut only the words around them. Contribute new facts in this same style.

**Doc comments carry the information; bodies carry none** — see `../AGENTS.md`. Every fn gets a `///` stating its input→output mapping: argument spaces/units/preconditions, returned topology, what holds of the result. File keeps one paragraph at the top for what the doc comments don't own. No inline comments. In this crate an invariant goes to an assertion message before it goes to a doc comment: one stated in an `assert!` is checked, one stated in prose is not. A fn whose mapping won't state, or a file too big for one paragraph, is split.

**Never launch subagents.** No Task/Agent tool, no fork, no spawning. All exploration and work inline with your own tools.

## Overview

Minimalistic **analytic-surface B-rep CAD kernel** (not CSG) + parametric **Gridfinity** model built on it + **egui** front-end previewing in 3D and exporting binary STL. Reproduces the purpose of the TS app in `../src` (parametric generator + watertight STL) as a small Rust workspace.

## Hard rule: no mesh operations before export/render

**Triangles are a terminal output format, never a modelling medium.** Everything upstream of `tess.rs` is analytic B-rep — exact surfaces, exact curves, closed-form intersections. Mesh produced once, at the end, never read back.

Prohibited anywhere in `sketch` → `build` → `topo` → `fillet` → `round`, plus `gridfinity/`, `region2d.rs`, `rectregion.rs`, `nesting.rs`:

- **Mesh booleans / CSG**, including pulling in a library for them.
- **Voxels, SDFs, marching cubes, point sampling**, any discretised volume representation.
- **Remeshing, mesh healing, decimation, vertex-merge-to-fix-gaps**, any "tessellate then repair". Watertightness is a property of the B-rep, guaranteed by the manifold invariant + `tess.rs` sampling each edge exactly once from its own two vertices outward. Sampling once is half of it: `EdgeSamples::build` overwrites each edge's first/last sample with the stored `Vertex::point`, because `sample_into` evaluates the curve and a vertex is never exactly on the curves meeting there. At `WELD = 1e4` a 10-ulp radial residue on an f32 coordinate near 80 mm is most of a quantisation step — arc endpoint and line endpoint welded to different keys and cracked the mesh open at the vertex. Taking the endpoint from topology is *not* weld-to-fix-gaps: it uses the B-rep's own answer for a point the B-rep already decided the edges share.
- **Numerically approximating a curve or surface** (polyline/facet stand-ins) where a closed-form `Curve`/`Surface` is correct. Missing primitive → add it to `geom.rs`; `Curve::Ellipse` was added exactly this way.
- **Reading a `Mesh` back into modelling.** `Mesh` is write-only downstream of `tessellate`.

Allowed, because at or after the tessellation boundary:

- `planar.rs` from `tess.rs`, final planar-face-with-holes triangulation only.
- `weld_triangles`, `to_stl_binary`, `flat_vertices`, bounds — export + GL upload.
- `Tessellation::welded_render_buffer` — the web app's single buffer for preview *and* STL. = `render_buffer` (position + analytic normal per vertex, unindexed) with positions snapped to the `weld_key` representative and weld-degenerate triangles dropped, so watertight under exact comparison like `to_mesh`. A *quantisation at the boundary*, not repair: nothing reads it back. The raw `render_buffer` (unwelded, per-face samples) must never be exported — it leaks.
- Mesh-based *verification* in tests (`assert_watertight`, `signed_volume`): checking the analytic result, never producing it.

Task that looks like it needs a prohibited op = missing analytic primitive or missing B-rep operator (e.g. blend runout in `fillet/`). **Stop and ask** — never a mesh fallback.

## Hard rule: assert everything, and pay for it at runtime

**Assert to high hell.** Every invariant a function relies on gets a real `assert!`/`assert_eq!` where it is relied on: preconditions on entry, postconditions before return, topology/orientation invariants after each construction step, geometric assumptions (non-degenerate normals, on-surface points, sorted/deduped inputs, index bounds beyond slicing) at the moment assumed. Assert with a message naming the offending values > a silent `if` patching the case up.

Most of the kernel's runtime inside asserts is fine and expected. A slow build failing loudly at the defect beats a fast one emitting a leaking solid. Never weaken/delete an assert to make something pass, never trade one for a fallback branch, never "optimise" one away without profiling evidence it bottlenecks something a user waits on.

**`assert!`, never `debug_assert!`.** The suite runs `--release`, which compiles `debug_assert!` out — a check nobody runs is not a check. Genuinely quadratic check only some callers want → runtime flag checked once per sweep (`set_verify_prune` in `isect.rs`).

**State the invariant, not a proxy.** "non-empty" where the property is "partitions the segment", "non-NaN" where it is "unit length" — passes while the thing it stands for is violated, worse than none because it reads as coverage. Write the predicate a proof would write. `split_seg` is the pattern: thin wrapper whose whole body is the postconditions over a `split_seg_inner` that works. Writing them found a live bug in the arc branch on the first run.

`tests/asserts.rs` mechanises this with `syn`, over the real AST — `assert` in a string/comment/doc example is not an assertion, `#[cfg(test)]` bodies are not production. Four rules:

- **No `debug_assert*!` anywhere.**
- **No bare `.unwrap()` outside tests.** `unwrap` reports the variant found, not the property that was supposed to hold; `expect` with the invariant written out does.
- **Every production assertion carries a message.** Decided by macro *arity* (more args than the comparison needs) — hence an AST pass.
- **Ratchet on functions that assert nothing.** `BUDGET` records per file how many functions of `BIG_FN_STATEMENTS`+ statements have zero assertions. Over fails; *under* without lowering the number also fails, so the table cannot drift. Deliberately no density floor — `assert!(true)` would satisfy one.

**An assert replaces the checking, never the exercising.** A test whose body only restates a now-production invariant loses its body, not its fixture: the assert fires only on inputs something feeds it, so deleting the fixture removes coverage while the suite stays green. Delete outright only when the input is redundantly covered.

Invariants moved out of ~30 hand-picked fixtures into the code: `Builder::build` (manifold invariant, orphan edges excepted) · `orient::normalize` (no misoriented loop survives) · `gridfinity::try_build` (closed manifold *and* audits clean, +37% on a build) · `tessellate` (`tessellation_leaks` empty; ~4× the tessellation itself, still ~2 ms a bin) · `triangulate` (triangles tile their loops) · `build_torus_blend` (blend torus is not a ring) · `to_stl_binary` (file is 84 + 50n bytes) · `region2d`, `uniforms` (`BOX_TOL` + every uniform block's layout, `const` asserts that fail the *build*). Lib gate 0.08 s → 1.9 s across these — the trade the rule asks for.

```bash
# The AST assertion gate above, one per crate over its own BUDGET:

cargo test --release -p gridfinity-model --test asserts
cargo test --release -p gridfinity-project --test asserts

cargo run -- optimize <in.toml> --mode <auto|bins|hybrid|walls> -o <out> [--format <stl|parasolid_x_t>] [--view]  # headless drawer fitting

# Fuzzer (tests/fuzz.rs): random Params → try_build → validate → audit → tessellation_leaks,
# failures grouped by signature, each shrunk to a paste-ready `Params` literal.
# **Every profile is #[ignore]d** — fuzzing is a deliberate campaign, not a routine gate.

FUZZ_SEED=7 FUZZ_CASES=500 cargo test --release -p gridfinity-model --test fuzz -- --ignored --nocapture
# One profile alone (they interleave otherwise — test threads run in parallel):
cargo test --release -p gridfinity-model --test fuzz fuzz_bin_shapes -- --ignored --exact --nocapture
```

`--release` always: lib gate 0.2 s release vs ~1.7 s debug. Run with `--no-fail-fast` — a failing binary otherwise hides the ones after it.

Measuring targets are `#[ignore]`d and do **not** gate: `tests/scale.rs`, `perf_report`, `alloc_report`. A number no assertion reads is not a gate, and they dominated the workspace run.

**The eight fuzz profiles are `#[ignore]`d too, on purpose.** Random search is a campaign tool: you run it when you are working on what it covers, or deliberately before a release, and you read the shrunk repro. Two profiles have stood red on the same undiagnosed backlog for a long time, so leaving them in the routine gate trained everyone to run it and skim past the red — which is the same failure mode `Options::known` had, arrived at from the other direction. Nothing is forgiven and nothing is deleted: `gate()` still asserts zero failures, the profiles still hold every requested blend, and the table below is still the number to compare against. They just do not run unless asked. `-- --ignored` is how you ask.

`default-members = ["crates/gridfinity-app"]` is what makes bare `cargo run` the app and `cargo run -- optimize …` the fitter; it also narrows bare `cargo build`/`cargo test` to that crate, so pass `-p` or `--workspace` as every command above does.

App is **not** `windows_subsystem="windows"` — the same binary prints the fitting report, and a windows-subsystem process inherits no console, so the report would go nowhere in release. Opens a window and blocks when given no `optimize`. Startup smoke test (shader compile / GL context / first mesh upload): `timeout 6 ./target/debug/gridfinity-app.exe`.

## Fuzzing: one path, eight profiles

**One** generator, checker, shrinker, repro printer. A profile is an `Options` value, so an invariant added to the checker is immediately enforced by every profile enabling the feature it covers. The four-way divergence this replaced had `fuzz_split_pieces` asserting shell counts, trespass and cut-plane gaps that `fuzz_bin_shapes` never applied to the same solids, and a repro printer printing neither `open_edges` nor `split_lines`.

`Options` names what a case *generates* (`Shape`, `Walls`, `openings`, `dividers`, `vary_params`, `slope`, `baseplate`, `Split`). It names nothing a profile *forgives*.

Run with `-- --ignored`; the counts below are what a deliberate run should reproduce.

| profile | varies | status at default seed |
| --- | --- | --- |
| `fuzz_inner_walls` | freeform walls on a fixed 2×2 | **red 20/150** — 8 defects |
| `fuzz_tidy_inner_walls` | tidy walls, up to 3 so they cross | green |
| `fuzz_wall_openings` | `open_edges` + `divider_edges` on rectangles | **red 2/150** — 1 defect, new at f64 |
| `fuzz_openings_and_inner_walls` | both at once | green (was 6/150) |
| `fuzz_bin_shapes` | polyominoes, flood-fill pieces | green |
| `fuzz_split_pieces` | polyominoes, `SplitLine`s + `partition_cells` | green (was 1/120) |
| `fuzz_stripped_polyominoes` | polyominoes, **half** the perimeter wall opened | green (was 15/150) |
| `fuzz_params_broad` | everything, incl. reentrant corners, slope, baseplate | **red 8/400** — 4 defects |

Every red was already failing before, on a `known` list or behind a `require_blends` opt-out or both. Nothing is a regression; the counts are the backlog. `fuzz_inner_walls` went 8 → 9 classes at the same 21 cases when the blend-chain kink became an `Err` instead of an assertion: cases that used to abort now report a named refusal, which is a class the old message absorbed. Compare **case counts**. Check the table before assuming a failure is yours. `fuzz_wall_openings` additionally clean at six seeds (default, 1, 7, 13, 42, 99) and at `FUZZ_CASES=600`.

Six of eight green at the default seed; the two reds are **28 cases across 11 defects**, from 44 across 15. At seeds 1 / 7 / 42 the other six are green but for `fuzz_openings_and_inner_walls` (2/0/0) and `fuzz_stripped_polyominoes` (2/3/1), and `fuzz_inner_walls` sits at 25/21/25, `fuzz_params_broad` at 11/12/12. **`fuzz_inner_walls`' 21 are 13 of one class** — the ramp running out into a needle, below — so the profile is one defect from being close.

**There is no expected failure, and there must never be one again.** A profile used to carry `Options::known` — message substrings of pre-existing undiagnosed defects, counted, printed tagged `KNOWN`, excluded from the assert. **Gone**: `Report` holds `failures`, `gate()` asserts it is zero. A forgiveness list is how a defect sits behind a green tick indefinitely, and the entry always outlives the diagnosis that justified it. Do not reintroduce it here or in any other test — a red profile naming a real bug is the correct state, and the fix is the model.

**A fillet that does not land is a failure, on every profile.** `fillet_best_effort` degrades on purpose so the *user* gets a part; the fuzzer takes the commercial-modeller line — `!BlendReport::is_clean()` is `FILLET_FAILED`, full stop. Was a per-profile `require_blends` opt-in, and the profiles opting out were exactly the ones where the model degrades most, so degradation was invisible by construction.

**A refused fillet says why.** `BlendReport::refusal` carries the message `fillet_edges_with` returned for the whole set. Without it the profiles reported only "N were refused" for every cause at once: `fillet_best_effort` throws that message away and salvages subsets, whose own failures ("an artificially cut chain always terminates somewhere") crowd out the one message naming the defect. Distinct-defect counts *jumped* when this landed (90/150 went 1 → 4 defects) — the backlog becoming legible, not growing.

**`Openings` is a *share* of the perimeter, not a flag** — the share is itself a variable. One opening in a rectangle = a single pinch against a straight run; half a polyomino's perimeter puts openings either side of a reentrant corner, back to back along one run, and around a convex corner, in one bin. `Share(1, 4)` for the three asserting opening profiles, `Share(1, 2)` for `fuzz_stripped_polyominoes`.

**`Walls::Tidy` vs `Walls::Freeform` decides how hard the fillet is asked to work.** Tidy = what the editor and the Projects packer emit (axis aligned, cell boundary or centre, spanning the bin, 0.8–3.0 mm) and the model rounds every one cleanly. Freeform sits at any angle/offset and routinely leaves a sliver narrower than the floor fillet. Measured: plain 2×2 is 150/150 blend-clean, as is every canonical wall (centre divider at 1.2/3.0/8.0 mm, free-standing island, partial height); freeform drops 18–28 of 26–42 requested blends, independent of wall width.

Openings/dividers are drawn from `layout::perimeter_edges` / `internal_edges`, not synthesised: the old broad generator pushed `GridEdge`s at random cell coordinates with random orientation, and `effective_walls` consults the divider set *only* for `EdgeClass::Internal`, so most of those dividers were no-ops.

### `fuzz_split_pieces` asserts what "split" means

- `partition_cells` reproduces an independently derived chunking of the cells,
- each piece is as many separate geometries as its cell set has islands (union-find over the welded mesh) — a chunk falling into two arms must come back as two shells,
- no piece keeps material over another piece's cells (the reentrant fillet's 8 mm overhang into *empty* cells is `REENTRANT_FILLET_OVERHANG` and allowed),
- pieces sum back to the whole bin's volume,
- pieces whose cells adjoin **touch** on the cut plane; pieces whose cells do not adjoin are measurably apart. Both distances from XY footprints quantised to 0.05 mm.

**That last one is `Split::Lines` only, and generalising it was a mistake worth recording.** It measures distance between the two meshes' *vertices* — a valid proxy for "the surfaces meet" only when every piece is a grid slab, where two abutting cut faces share an outline and land vertices in the same places. A ragged flood-fill piece breaks it: a three-cell row cut against a single cell genuinely abuts at y=42 (both meshes reach exactly 42.00) yet the nearest vertex pair stands 0.5 mm apart, because the row's cut face is subdivided differently. Applied to `Split::Flood` it reported a defect that is not there. Volume conservation holds the flood pieces to meeting exactly.

### `fuzz_bin_shapes` targets `carve_to_cells`, not the model

Grows a random connected polyomino, severs a random subset of internal adjacencies, flood-fills the remainder — same construction as `web/src/lib/cuts.ts`'s `partitionCells`, so pieces are arbitrary connected polyominoes, not the grid slabs `layout::partition_cells` produces. Builds the bin **once** via `build_bin_solid`, checks that whole solid first (failures prefixed `whole `, so a model defect never reads as a split defect), then carves and checks each piece (`piece N `). Sharpest invariant = **volume conservation** within `VOLUME_DRIFT`: caught the bounding-box carve bug at 125% and the reentrant overhang at 0.2%, in either direction, where per-piece manifoldness passes straight over.

Went **47/120 → 0/120** (clean at eight seeds, 1/1500 at `FUZZ_CASES=1500`) across four defects: a cut splitting one face into disjoint regions read as a hole (see `emit_trimmed_faces`); the cavity escaping the wall at a rounded corner below ~1.1 mm wall (see the corner clamp); the reentrant-corner fillet overhanging the grid, ~54 mm³ per corner (see `carve_to_cells`); a piece enclosed on all four sides refused rather than mangled. Fixing them moved `fuzz_inner_walls` 27 → 30/150 with **no new defect class** — the corner clamp shifts every cavity slightly (rc 2.5 → 2.55 at default wall), so the same six defects catch a few more random placements. One rarer defect survives at 1500 cases (~0.07%, in `trim`): a 4-leak tessellation failure on a cut plane. Undiagnosed. The second, `no closed-form section curve for a face the cut crosses`, is retired — see `curve_plane_params` below; it was never a missing curve.

**Measure a suspected volume loss against tessellation density before believing it.** Every number is a coarse mesh's estimate. The reentrant-overhang loss was confirmed by converging on −209 mm³ from segs 4 to 48 while a rectangular split stayed at 0.01 mm³, then pinned by correlating drift with reentrant-corner count (rect 0, L 1× −54, T and S 2× −104) and parameters (flat in every cavity parameter, linear in height). A vertex-only containment check will **not** see it — the fillet's tangent points sit exactly on the grid lines, only the arc between them escapes.

The generator and shrinker produce **edge-connected** bins only. `gen_small_rect` could delete the middle of a 1×3 and `shrink` could delete any cell, either handing the model a diagonally connected bin, which `AGENTS.md` puts out of scope. Changed no counts, but the printed repros are trustworthy now and were not before.

### `opening_keeps_the_fillet` — the check `FILLET_FAILED` cannot make

`FILLET_FAILED` holds the model to blends it *asked for*; an opening's loss happens one step earlier (`plan_piece` zeroed `loop_fr` for any cavity loop `resolve_open_runs` touched → 0 requested / 0 refused, audits perfectly clean). So: build the same bin twice, as generated and with `open_edges` cleared, and compare. Found **80/150** of `fuzz_wall_openings` on arrival.

**Compares the solid, per compartment.** `floor_fillet_coverage` returns (cavity floors, floors meeting every wall sharp) by reading tangency off the B-rep: a rolling-ball blend meets the floor along their shared edge with the floor's own normal — that is what the blend *is* — while an unblended wall meets it at a right angle, so a floor edge is rounded exactly when the face across it has `|n·Z| = 1` there. A cavity floor is a `Plane` with vertical normal at `BASE_TOTAL_HEIGHT + FLOOR_THICKNESS`, and nothing else in the model sits at that height. Three consequences, each a hole in the old count-based check: `EdgeId`s and request counts do not survive an input change, so nothing but geometry could compare two builds of two different bins at all; a compartment the closed bin rounds and the opened bin leaves sharp now fails even when every other compartment kept its blends (the old check fired only on losing **every** blend); degradation present in both builds cancels, so it is safe on shapes where the fillet legitimately struggles — it runs on every profile now. `a_cavity_floor_is_rounded_exactly_when_the_model_filleted_it` pins the predicate against a 2×2 with/without a divider and with `floor_fillet` on/off; both failure modes (finding no floor, calling every floor rounded) are otherwise silent passes.

**It also compares the report, because `is_clean()` is vacuously true at zero requested.** A change that stops `plan_piece` asking scores *better* on `FILLET_FAILED` than one that asks and is refused, so tuning the cavity against that gate alone rewards deleting the request. Not hypothetical: a cavity change aimed at reentrant notches took `fuzz_stripped_polyominoes` 31 → 26/150 while taking one 5-cell bin from 13 requested / 2 refused to **0 requested**, and every gate called it an improvement. So the check also fails when `made()` falls to nothing on a bin whose closed build lands anything — deliberately the crudest form (`before.made() > 0 && after.made() == 0`), since the per-compartment geometric check is the precise one and this only closes the floor under it. Cost `fuzz_openings_and_inner_walls` 1 → **6/150** and `fuzz_params_broad` 20 → **24/400**, all pre-existing, none previously visible; worst reads *0 blend(s) where the same bin closed asks for 38 and lands 38*. Clean profiles stayed clean.

**Never judge a cavity change on `FILLET_FAILED` counts without also reading `made()`.**

Three things had to change for `fuzz_wall_openings` to go clean; only the first is the model:

- **The blend request follows the wall, not the loop.** A touched cavity loop blends its non-coincident segments (the ones the outer walk did *not* replace, i.e. where a wall still stands), and `blendable_segs` drops one segment at each remaining sharp corner so the chain terminates there instead of continuing through a corner it has no tangent across. Dropping the *loop* cost a 2×2 all 8 blends for one open edge.
- **`fillet/` can cap a runout** (`RunoutEnd::Cap`, below).
- **The blend's side is decided locally.** `s` came from `face_centroid`, which means something only for a face whose centroid is inside it. An L-shaped cavity floor — or any floor with an opening's mouth in it — pulls the centroid far enough to flip the choice on *one* edge of a chain, landing its tangent points 2r from its neighbour's and tearing the loop open. Now from the direction fa's material lies in at that edge, `outward normal × edge tangent`, guaranteed by the orientation invariant. Two traps: `Curve::tangent` (new, closed-form for all four variants) differentiates in increasing `t` and an edge whose stored range runs *backwards* traverses `v0 → v1` the other way; and the reference point must be the **curve's** midpoint, not the chord's — on a semicircle the chord midpoint is the circle's centre and every normal there is meaningless. That one cost `fillet_cylinder_top_is_watertight`.

`OPENING_LOSES_FILLET` survives only on `fuzz_params_broad`. `fuzz_openings_and_inner_walls` retired it (6/150 → green at the default seed, 6 → 2 at seed 1, 1 → 0 at 7, 6 → 0 at 42) on **one rounding minimum shared between the two entry points that round a corner**. `round_sharp_corners` reverts a radius under `MIN_ARC_R` to a square corner; `rectregion::shape_loop` did not, and emitted whatever its fit-scaling left — 0.066 mm on the case that found this. A hair-thin *arc* is not a chain terminator the way a sharp corner is, so `settle_blend_radii`'s one-sided clamp pulled the whole compartment's 2.48 mm floor fillet down to it, and one opening on the far side of a 2×3 bin took the bin from 23 blends requested to **0**. Squared, the corner terminates the chain (`blendable_segs`) and costs one segment, which is the behaviour the opened path was built for. `MIN_ARC_R` is `pub` in `round.rs` now; any third rounding entry point honours it too.

**The clamp itself is one-sided on purpose, and relaxing it to a band is wrong.** In theory a ball wider than the convex arc it rolls into is an ordinary spindle torus and only `|R − r| < MIN_TORUS_MAJOR` is unbuildable, which is exactly what `blend_radius_along` says for a notch ramp. Making `settle_blend_radii` agree with it takes `fuzz_wall_openings` **0 → 9/150** and `fuzz_stripped_polyominoes` **0 → 26/150**: blends across a 0.066 mm corner come back as `blend torus degenerates to a ring`, self-intersecting faces, and tessellation leaks at the corner's own coordinate. A compartment carrying an arc the ball cannot roll along still gives up its fillet entirely; making that arc a corner instead is what fixes the case.

Cost: one class, at non-default seeds only — `fuzz_stripped_polyominoes` 3 → 10/150 at seed 7 (4 → 5 at 1, 4 → 6 at 42) and `fuzz_params_broad` 16 → 21/400 at seed 1, all of it the **torus runout refusal below**, reached because a chain that used to be deleted now terminates at the squared corner. Its two pre-existing classes are unmoved and no new class appeared. Default-seed `fuzz_inner_walls` and `fuzz_params_broad` byte-identical.

One thing before touching the opened path: `opening_keeps_the_fillet` builds each bin twice, so both builds must come off the **same** cavity planner. Wiring only the closed path to the walk put `fuzz_wall_openings` at 20/150 immediately — not a defect in either path, the check correctly reporting that the closed build got better and the opened one did not.

### The blend-runout backlog, and what retired most of it

**A blend chain now always ends somewhere.** Terminating where the landing face cannot take the curve used to be nearly the whole backlog. `plan_runout_end` tries three ends in order: `Absorb` (fold the trim curve into a neighbour's loop), `Cap` (close against the pair of neighbours either side of the corner), `Flat` (stop in the blend's own last cross section — always available). The three worst profiles went 26/55/26 → 23/31/20 across the two new ends.

**"Always" was not true, because the ladder aborted on a plane it should have skipped.** Both `Absorb` and `Cap` are trimmed by the blend's exact section of the chosen plane, so `plan_runout_end` asks `land` for it — and propagated `land`'s error instead of trying the next rung. `fillet_best_effort` drops a chain that errors, so one unreachable plane cost the whole chain its blend where a flat end was sitting right there. A plane whose section does not exist is a **rejected candidate**: the refusals below (terminating plane past the narrowest ring, oblique plane's quartic, blend running along the plane) all mean "not this end", never "no end". `plan_runout_end` returns `RunoutEnd` rather than `Result<RunoutEnd>` now, which is the statement that it cannot fail. Retired the whole `past the narrowest ring the trim curve crosses` class: `fuzz_inner_walls` 3 of its 7 defects, `fuzz_stripped_polyominoes` 10 → 3/150 at seed 7 and 5 → 2 at seed 1, `fuzz_params_broad` 16 → 15/400.

- **A chain terminating on an arc** is supported. Cylindrical blend rolls along a straight axis → plane cuts it in an ellipse; torus blend rolls around a circle → a plane's section of a torus is a quartic, which is why the runout refused every one. A plane **parallel to the torus axis** is the exception and the case the model produces: fixing minor angle `t` fixes ring radius `major + minor·cos t`, and the plane meets that ring where `cos u = offset / rad` — exactly `Curve::TorusSection`. `runout_torus` reads the section's parameter range off the two touchdowns, because a torus blend's tangent circle is a circle of **constant minor angle**: running one out to the plane changes `u`, leaves `t`. Three things it must get right, each a bug first. Ring radius is **signed** — on a spindle torus (`minor > major`, every corner blend tighter than its own corner) it goes negative past the axis, and reading a touchdown's minor angle off the unsigned radius puts it half a turn away (same distinction `Surface::signed_distance` makes). `branch` picks which of the plane's two crossings the blend runs into: the nearer one measured around the axis is always the one on the blend's own side of the plane normal (for `u_v`, `u_p` in `(0, π)`, `|wrap(u_v − u_p)| <= |wrap(u_v + u_p)|` reduces to `u_v <= π`), with the chain's heading breaking the tie when the ball centre sits square in the plane. And tangent curves are **circles**, so moving a touchdown moves it *along* its own circle: `respan` moves the parameter range with it, keeping the sweep's direction and taking only magnitude from the new endpoints. Without it the edge spans the arc the blend used to and misses its own vertex by however far the touchdown ran — `audit` reported `EdgeVertexGeometry`, 4.15 mm out.
- **A flat end whose stub covers a whole edge swallows it** (`Runout::swallowed`, `swallowed_end`). Retired `fuzz_stripped_polyominoes` outright — 15/150 → **green**, all three of its classes — and took `fuzz_params_broad` 22/400 → 16/400. The case is an opening beside a reentrant corner: the cavity steps by `HALF_TOL` where the opened run meets the outline, leaving a 0.25 mm run for the chain to end on against a 0.48 mm retreat. The stub from touchdown to corner covers the whole of that run, so the face emitting it walked out to the corner and straight back along the same line — a zero-width spur, reported two layers downstream as `half-edges N and M leave vertex V in the same direction` from `planar.rs`. The face drops the swallowed edge; the flat cap, whose plane the stub runs in by construction, **splits its own stub** at that edge's far end and takes it, so the edge keeps both its uses and its id. Decided per *edge* from the touchdown alone, so the face dropping it and the cap taking it decide identically. Two new assertions name the spur at its source instead: `chain_loops` for a 2D boolean that produces one, `Builder::intern_loop` for any face loop that retraces itself.
- **A blend reaching past the terminating face's edges** goes flat instead of refusing. Trim curve crossing a real edge and split between two non-coplanar faces is still unbuilt and still the better end where it applies — the `fuzz_params_broad` case is a partial-height inner wall clipped by the perimeter, terminating face = the wall's *end cap*, 4.006 mm wide after the clip against a retreat of 5.74, with the wall's own **side** face past that edge. Whatever does it must decide per *edge*, not per face, or the two faces sharing an edge disagree and the seam opens.
- **Three candidate terminating faces** goes flat too. **Relaxing the cap to allow them was tried and changed nothing** — worth knowing before trying again. A cap is one planar face on `fa_side`'s surface, so it needs the two neighbours *either side of the corner* coplanar, not every candidate, and `cap_at` states that itself rather than leaning on the coplanar-absorb branch. These cases fail earlier, in `pick`: the corner offers more than one candidate across `fa`'s or `fb`'s edge, so which face the blend runs into is genuinely undecided. That is the question to answer, not the cap's plane.
- **The passage width is the distance to the segment across it, not the length of the ray that found it.** `max_inward_radius` cast a ray inward and took the ray's own length; the two differ whenever the ray leaves at anything but a right angle to what it hits, always in the generous direction. A 1.2 mm wall finger tilted 2° against the cavity wall opposite measured its 3.0496 mm gap as 3.0518 and passed r = 1.5259 where 1.5248 fits — the fillet then self-intersected, `face N's boundary crosses itself`, ×15 on `fuzz_inner_walls`. The ray now only picks *which* segment is across the passage; `point_seg_distance` measures it, halved, which is exact for the disc touching both. Samples are the true segments including both endpoints (a rounded tip's nearest point to the wall opposite is the corner where the end cap meets the side, and interior sampling walks past it) and are taken on the real arc, never a chord.
- **A blend chain is not bounded by its own run length.** Tried: clamp a notch ramp's radius to half its contact run. `partial_wall_one_end_on_boundary_is_watertight` builds a radius-4 ramp on a 3 mm run, so the rule is simply false — a chain whose ends *absorb* into neighbours retreats into them, not back along itself. Reverted; the ×10 `fuzz_inner_walls` ramp case it appeared to fix is the spike below.
- **A ramp running out into a spike** (now ×13 `fuzz_inner_walls`, ×3 `fuzz_params_broad` — the largest class left) — a partial-height wall crossing a rounded cavity corner leaves the corner cylinder split in two by a seam, with the wall-top face a sliver whose end is a ~140° spike. The chain terminates on that seam and the runout crosses the spike at **every** radius, down to 0.12 mm, so no clamp reaches it. Merging the two cocylindrical faces first (extending `same_plane` to cylinders, with the material side read radially at a boundary point) does remove the seam, and was tried: it breaks `featured_bins_stay_watertight`, `freeform_floating_divider_is_filleted` and `partial_wall_one_end_on_boundary_is_watertight`, and turns this case into a torus-runout refusal rather than geometry. Reverted. The seam is real work, not a one-liner.

It does not land: `same_cylinder` (one axis line, one radius, one `sense` — a cylinder's normal is radial, so the material side needs no sample point) leaves `featured_bins_stay_watertight` at 16 `LoopContainment` errors and `freeform_floating_divider_is_filleted` with 2 blend faces where it wants 4, and **the case still fails with the merge in**. `partial_wall_one_end_on_boundary_is_watertight` does pass with it now.   **What the case actually is**, off the widened refusal (which now names the surface and the two crossing runs, not just the face id): the wall meets the compartment boundary at **19°**, so the notch's top face has a needle where its side meets that boundary, and the *touchdown line* — the run offset `r` inward, which is where the blended face retreats to — crosses the face's far side. Repro is `cells [(1,0),(1,1)]` with one `InnerWall { x1: 83.0, y1: 81.0, x2: 59.5, y2: 14.0, width: 1.0, height: Some(4.0) }`: at `TRANSITION_R` the touchdown stands 4 mm inside a 1 mm strip, and at 0.2 mm one of the two ramps still crosses, by 0.04 mm, at the needle's tip. **No radius bound separates it** from `partial_wall_one_end_on_boundary_is_watertight`, which builds a 4 mm ramp on a 64° crossing.

  Two feasibility predicates were built for it and both are wrong, in the same way. `max_inward_radius` over the notch's top face reads 0 at a needle tip *and* 0 at every contact run's own endpoints, so it cannot tell the two cases apart. Nor can containment of the touchdown: at **any** corner under 90° the inward perpendicular points out of the wedge between the run and the side, so requiring the touchdown to lie in the face refuses the 64° case as readily as the 19° one — which is correct arithmetic and the wrong question, because a chain ending at a corner retreats onto the *neighbouring* face and is not required to stay in its own. The distinguishing quantity is the **far** side of the face, not the adjacent one: the offset run must not cross the boundary anywhere except at the two corners it ends on. And where it does, the fix is not a smaller radius but a chain that **stops short of the corner** — a blend running out in a face's *interior*, which is the same capability `piece_is_enclosed` is refused for and which `trim` cannot do.
- **A floor whose boundary self-intersects** (×7 `fuzz_inner_walls`, ×1 `fuzz_params_broad`, down from 13) — fillet wider than the compartment, touchdowns from the two sides cross. `max_inward_radius` bounds what `plan_piece` asks for: a ball of radius `r` touches down `r` from the wall, so across a passage `w` wide it needs `r <= w / 2`, `w` measured by casting a ray **inward** from points along the loop and taking the first crossing. Inward matters — distance between two nearby segments clamps on a thin finger of material whose sides are close but which the ball just rolls around. It samples, so it can only miss a narrow spot, never invent one; what remains is passages narrowing between samples, or self-intersection with a cause other than a straight passage's width.
- **An opening costing a compartment its floor fillet** (×7 `fuzz_params_broad`, ×1 `fuzz_openings_and_inner_walls`) — model-side, invisible to `FILLET_FAILED`; `opening_keeps_the_fillet` is what sees it.
- Four manifold panics and one `TRIM_SECTION_CURVE`, undiagnosed.

**Still unsupported:** runout onto a **cylinder** (`runout face N is not planar`) needs a blend-cylinder ∩ corner-cylinder section curve — quartic for perpendicular axes, outside the analytic curve set. Torus runout onto a plane **not parallel to the torus axis** — the quartic again. And a chain that **stops short of its run's end**, running out in a face's *interior* rather than at one of its corners: the three ends all terminate the blend at a corner, and the needle case above is what needs the fourth. Same capability `trim` lacks for `piece_is_enclosed`, from the other side.

**Absorbing a runout is about the terminating face's *edges*, not its area.** `plan_runout_end` returned `Absorb` for a lone candidate without checking it could take the curve. Absorbing retreats that face's two edges at the corner back to the tangent points, so it is available exactly when those points still lie *on* those edges — `absorb_fits`. Past an edge's far end the face ran out before the blend did, and splicing there emits a loop doubling back over ground the blend never covered; reported 4–7 mm downstream as a loop that does not close. A partial-height inner wall meeting the perimeter is the case: the corner sits exactly on the wall's top, so the tangent point up the perimeter stands above the wall's side face altogether. Gating on `planar_face_contains` is **not** the same question and refuses `partial_wall_one_end_on_boundary_is_watertight`, whose runout lands *on* its face's boundary and absorbs fine. `absorb_fits` turns these into a cap where the neighbours allow one and an honest named refusal where they do not — not yet into geometry, because `cap_at` draws its neighbours from the candidate set and at a partial-height wall's top they are coplanar with the blended faces and excluded. Same missing capability as the overshoot above.

**`RunoutEnd::Cap`.** A chain dying on an opening's mouth has no face to absorb the curve — on a 2×2 opened at `(0,0,H)` the runout lands at `(40.775, 0.25, 9.425)`, above the lip at `z=8.2`, inside the open span, on no face at all. So emit one: a planar cap bounded by the end ellipse and the two stubs between the tangent points and the corner. Neighbours either side keep their corner and have their edge **split** at the tangent point rather than retreating to it; each of the cap's three edges is interned by its endpoints, so it pairs without being told its neighbours. Winding comes from the blend face's own traversal of the shared ellipse, reversed — one comparison fixing all three edges, since `orient::normalize` cannot re-wind a single face against its own component. `plan_runout_end` also settles the older ambiguity: several coplanar candidates are the outer wall cut into bands by the peg profile, so the plane was never in doubt, only which band's loop takes the curve, and `planar_face_contains` picks the band the runout lands in.

**`RunoutEnd::Flat` — a chain that can end nowhere ends flat.** Tried after `Absorb` and `Cap`, never unavailable: the blend stops where the chain stopped, closed by a planar face in its own last cross section. That plane always exists (the ball's two touchdowns and the corner they retreat from are three points of the plane the connect arc already lies in, whatever the blend rolled along), normal oriented by the chain's heading so the material it closes lies behind it. A commercial modeller's flat-ended fillet — looks worse than folding the curve into a neighbour, which is exactly why it is last. Reuses the cap's three-edge loop (two stubs + the arc) and nothing else, because a flat end trims *nothing*: tangent points and connect arc stay as built. What is new: an edge at the corner decides for itself whether it is involved. `Runout::on_edge` retreats an edge only when a touchdown lands **on that edge**, strictly between corner and far end; every other edge keeps the corner and the blended face's loop gets a straight stub from touchdown to corner. That test is a property of the edge, so the retreating face and the splitting face across it still agree on the point. The stub is checked against the face's own surface before emission — it is a straight line inside a curved face only because touchdown and corner share a ruling of it.

The case that forced `Flat`, pinned by `an_opening_into_a_reentrant_corner_keeps_every_blend`: L-shaped bin opened onto its reentrant corner. The cavity's rounded corner there is an arc → floor fillet is a torus; the wall that arc rolls against tapers from `wall_thickness` to **zero** where the opened cavity meets the outline, so cavity wall and outer surface meet in a knife edge. 0.6 mm of face for a 2.45 mm blend to run out along, the plane past that edge bounds nothing, and extending the blend surface further leaves the material entirely. All ten of that bin's blends were refused before.

### Blend geometry that had to be shared, not recomputed

**Two blends of one chain must agree exactly on the vertex they share.** Each derived the meeting point from its own faces' normals there — equal in exact arithmetic, differing in the last bits in f32, ~2e-4 mm apart = four times `topo`'s weld quantum. Builder interned two vertices; the face both blends border was left with an open loop (`face 49: loop not closed`). No weld tolerance fixes it: the gap is real, and loosening the quantum welds genuinely distinct things. `reconcile_shared_ends` derives the ball centre and both touchdowns **once per vertex** and hands them to both blends. Leans on a chain running along the boundary of one face, so the two edges at a shared vertex have a face in common: that names one touchdown and the two tangent neighbours, which share a normal there, name the other.

**One shared face is the usual case; two is a chain running straight on, and refusing it cost the drawer 24 fillets.** A requested edge is held back from `merge_coplanar_faces`, so a run of the boundary between two faces reaches `reconcile_shared_ends` still cut in two wherever a *seam* crossed it whose own edge the fuse dissolved — both halves requested, both then bordering the **same** pair. `shared.len() != 1` read that as a junction and refused. It is not: each corner's two faces are distinct (`check_edges` admits nothing else, now asserted), so naming a touchdown by the face it lies on is a bijection whichever face is picked, and the three-point agreement check below is what decides whether the two really continue one chain. Only an *empty* intersection is a refusal now. `examples/drawer.toml` went **259 of 283 floor fillets to 283 of 283** — its collinear pair was the floor/wall run under a socket column, split at `y = 203.64999784708445` and refused 24 times over. Build time 0.68 → 0.07 s with it, the salvage bisection being what the refusal was paying for. `a_chain_running_on_across_a_fused_seam_still_blends` is the fixture: a box with one side sketched as two collinear segments, which is that topology and nothing else.

The bound is an **angle**, `MAX_JOIN_KINK`, not a distance: a kink of `d` radians moves the ball centre by ~`r·d`, so a fixed distance would tighten with the radius exactly where the blend has most room to absorb error. Half a degree = two orders above f32 noise at model scale, two orders below any real corner's turn. Not a formality — the drawer bin's generated dividers meet the cavity with a 0.13° kink = 5.4e-3 mm of disagreement, far past float noise, and `a_drawer_bin_partitioned_into_compartments_is_watertight` says so.

**The arc where two blend faces meet takes its plane from the touchdowns, not from the edge.** `connect_arc` rolled it about the blended edge's tangent at the vertex; two edges of one chain agree on that tangent only to float noise, and 8e-5 rad over a 2.4 mm radius moves the arc's midpoint past the weld quantum — shared edge interned twice, each blend face holding one (`edge N used fwd=1 bwd=0`). Both touchdowns are a radius from the centre, so the two plus the centre fix the plane exactly; the edge tangent now only chooses the sweep's sign, a binary call nowhere near flipping.

**A torus blend's tangent circles take their parameter range from their own tangent points** (`circle_span`), not from the blended edge: once blend radius exceeds corner radius the tangent circle lands on the far side of the axis, so the inherited range needed rotating by π and reversing. Only the sweep *magnitude* comes from the source — a full-turn blend's endpoints coincide and cannot tell 2π from 0.

**A fillet that would build a face whose boundary crosses itself is refused**, and `fillet_best_effort` drops it (unfilleted corner, not a build failure — the policy already there for blends that fail to build). `face_loops_self_intersect` runs over *every* face the rebuild touched, not just blend faces: the runout rewrites neighbouring walls' loops too, and the bowties left there were the larger half of the defect.

**A `HashMap` keyed by edge must not decide a value keyed by vertex.** `fillet_edges` filled `vinfo` (vertex → moved tangent points) by iterating `bm: HashMap<EdgeId, Fillet>`. A chain has two blended edges per interior vertex, so both wrote it and **the last writer won** — `RandomState` seeded per process and thread, so which one changed run to run. The two agree only to an ulp, and an ulp at a `weld_key` boundary is the crack under `topo.rs`, so `fuzz_inner_walls` failed on about half of all runs (at `RAYON_NUM_THREADS=1` too — a seeding bug, never a threading one). Iterates sorted keys now, like lines 188 and 332 of the same function already did. **Any iteration order reaching geometry must be sorted**: a std `HashMap` here is a random number generator, and `--workspace` vs `-p gridfinity-model` build different binaries, so "passes alone, fails in the gate" is a determinism smell before it is a feature-unification one.

**Blends are observable.** `program::run_reporting` returns a `BlendReport` (`requested` / `unresolved` / `dropped` / `refusal`) beside the solid; `gridfinity::try_build_reporting` / `build_bin_solid_reporting` pass it through, `run` / `build_bin_solid` are wrappers so no existing caller changed. Without it a regression that stops rounding corners near an opening or inner wall passes every gate — solid still manifold, still audits clean, still tessellates without leaks. Both counters are outcomes the model chooses on purpose (`find_seg_edge` → `None` leaves a selection unblended; `fillet_best_effort` prefers a sharp corner to a failed build). The fuzzer accepts neither: both are `FILLET_FAILED`.

### The outline's seams are not geometry

Took the three worst profiles 52/126/90 → 31/26/55. The case that showed why: one-cell bin, one open edge. `split_outline_at` cuts the outline wherever the peg profile or an opening needs a point, and every cut runs the wall's full height, so a flat wall reaches the fillet as a row of narrow bands — faces 25, 26, 27 of that bin are one plane `y = 0.25` facing the same way, with 26 a 1.55 mm sliver between the others. A runout retreating 2.4 mm along that wall's top crosses two of them, and every mechanism it has works within one face. Refused.

`Solid::merge_coplanar_faces` fuses neighbouring faces on one plane facing one way; `fuse_collinear_edges` then fuses the collinear edge pieces the seams left along their tops. Both keep vertex and edge numbering, so blend edge ids resolved before the merge stay valid, and both hold back the blended edges themselves. A simplification of the B-rep, not a change to it — same space, fewer faces describing the same surface, which is why nothing downstream needed touching.

Three findings worth keeping for any similar pass:

- **Coplanarity is not transitive in f32, and the union-find treats it as if it were.** A row of bands grows one neighbour at a time, so far members drift off the plane the merged face carries. The assertion that every member lies on the representative's plane caught exactly that — and the *bound* was wrong, not the merge: two faces 73 mm apart whose normals agree to 2.6e-6 rad are 1.9e-4 mm out of each other's plane with nothing wrong. Allowance carries the lever arm now: `SAME_PLANE_DIST + |Δorigin| * SAME_PLANE_SIN`.
- **Collinear is not enough to fuse two edges at a vertex; the run must pass *through* it.** Two edges leaving one vertex in the same direction lie on top of one another, and fusing them describes a span neither covers. Showed up as two vertices in one weld cell.
- **`Builder::resume` indexed only the vertices of the faces it was rebuilding.** Fusing edges leaves dissolved junctions on no face at all, so a later `vertex()` there minted a second id. Indexes the whole array now (the builder had already cloned it) — a fix standing on its own, since nothing guaranteed an untouched face's vertex was indexed either.

Two single-case panics are newly *reachable* because bins that used to refuse their fillets now build them: `edge 314 used fwd=2 bwd=2` in `fuzz_stripped_polyominoes` and a `build_half_edges` same-direction assertion in `fuzz_inner_walls`. Neither is a merge defect as far as the merge's own assertions can tell; both undiagnosed.

### The angular sort at a vertex cannot go through `atan2`

`planar::build_half_edges` orders half-edges leaving each vertex so `next_in_face` can step "one clockwise". It sorted on `(b.y − a.y).atan2(b.x − a.x)` in f32. A diagonal running the length of a face, a hair off a boundary edge it passes over, differs from that edge by ~1e-8 rad — under one f32 ulp at π — so the two compared **equal**, `sort_unstable_by` ordered them arbitrarily, and the face walk left the face it was tracing. Triangulation then covered part of the region twice: 2307 mm² returned for a region of 837. `angular_cmp` replaces it with a sector test and one cross product, exact to the last bit the coordinates justify.

The shape that found it: `four_compartments_either_side_of_the_centre_line` — a 1×3 bin's rim cut into four compartments by two tidy walls, the vertical one on the exact centre line so the two holes of a column share their whole extent along the sweep. Verbatim `tess.rs` output; loops simple, disjoint, properly nested. Nothing about the input is degenerate, which is why this was the triangulator's defect and not the model's.

### A wall's material side comes from its loop's winding, not from a flag

`wall_between` builds the surface normal to the right of travel, so a region wound material-on-the-left needs `outward: true` for every loop it has, **hole loops included** — the winding already carries the orientation. `plan_piece` had `outward: loop_area(sl) > 0.0`, flipping the normal on every hole of the standing wall. It agreed with the base's outer wall below `floor_z` as long as the two never shared a ring; **an enclosed hole is where they do**, and there base and standing wall met at `floor_z` with opposing normals — 56 leaked edges on a ring bin with one opening. The sector loop asserts what it relies on instead: signed areas sum to the material's own area, so every hole is wound against its outer loop.

### `fuzz_stripped_polyominoes` — four classes on its first run

Half a complex polyomino's perimeter is the first thing to reach openings meeting a reentrant corner in quantity. Started at 66/150. All four classes verified **pre-existing** against `749a3a5` (the tree before this session's kernel work): configurations nothing had fuzzed, not regressions.

- **42 open-run panics** (`no pinch for run`, `wall-sector chain stuck`, `arc before/after the run`) — retired outright by the boolean reformulation below.
- **36 cases handed the triangulator a face whose loops do not tile** — same assert as `CROSSING_WALL_TILING`, reached through openings. The loop had a **spur**: ran a fraction of a millimetre along one edge and straight back over itself. Author was the cap runout, splitting an edge at a point not on it. `plan_runout_end` now projects the cap point onto the edge it means to split and refuses unless the parameter lands strictly inside — a dropped blend is geometry the model handles, a backwards spur is not.
- **2 cases left an edge unpaired** (`used fwd=0 bwd=1`), both at a **diagonal pinch**, where the outline visits one lattice point twice — rounding the corner on one visit, squaring it on the other — and the peg welded only to the rounded visit. `SharedWithPegs` records the squared visits in `squared` and subtracts them from `corners` after authoring, and `split_peg_profile` splits the peg's corner *arcs* by angle about the corner centre as well as its lines, so the peg carries a vertex per visit.
- **1 case built a `Plane` from a zero-length normal**, from a zero-length segment a boolean left behind; `drop_degenerate` discards those before `wall_between` sees them. Caught where it is made now, not four layers downstream: `Surface::plane` asserts its normal finite and non-zero, because `normalize` on a zero vector yields NaN, `sin.max(1e-9)` then hides the NaN inside the blend's ball-centre solve, and it surfaced only as `vertex at a non-finite point` in the builder. `fillet_edges_with` asserts the same of each blended edge's four face normals, so a NaN from anywhere else is named too.

**A split may not leave a piece shorter than the distance `chain_loops` welds with.** Last case standing was a `region_difference` returning *nothing* — 717 mm² of wall vanished. A vertex both regions already agreed on, `(44.153893, 84.0)`, sat 1.8e-4 mm off the outline arc it was supposed to lie on, so the sweep found the true arc∩line crossing at `44.15371` and split the 1 mm line beside it there. The 1.8e-4 mm sliver is longer than `EPS` (so `chain_loops` will not weld across it) but the two regions now disagreed where that vertex is, the chain ran off the end, and an unclosed chain is silently dropped. `split_seg`'s line branch measured its margin as a *fraction* of the segment — generous on a long one, vanishing on a short one — and measures it in millimetres against `SLIVER` now. `SLIVER > EPS` is a `const` assert. `SLIVER` **is** `sketch::COINCIDENT`, the one 1e-3 every reader of a sweep's output has to agree on — `on_seg` accepts it as "on", `chain_loops` welds across it, and `round`'s hair-dropping and run-merging use it. It existed as three separate literals.

`split_seg` states two postconditions: the pieces **partition** the segment (first starts where it starts, last ends where it ends, each begins where the last left off), and none is shorter than `SLIVER` unless the whole segment already was. Writing the second down immediately caught the arc branch making the line branch's mistake — its angular margin scaled by the arc's own span, so a short arc got a vanishing margin. Margin is `SLIVER` millimetres of arc, full stop.

### The long campaign

`FUZZ_CASES=6000 fuzz_params_broad` + 3000–4000 on every other profile is the census these counts come from. Started **243/6000 across 15 distinct defects**; three fixes took it to **170/6000 across 11**, each a real model defect only a long run reaches:

- **A partial-height wall's ramp asked for a blend the size of the arc it rolls along.** `plan_cavity_banded` took `r = min(total_h − top, TRANSITION_R)` with no reference to the cavity corner it lands on, so `cavity_corner_radius: 4.0` against `TRANSITION_R` 4.0 put the blend's centre on the arc's own axis and `build_torus_blend` asserted `major 0`. Exactly `rc == 4.0` failed while 3.9 and 4.1 built. `blend_radius_along` pulls any requested radius clear of the segment's own by `MIN_TORUS_MAJOR`, per contact segment rather than per notch — one run can mix straight pieces with arcs and only the arcs constrain it.
- **A sloped bin with a thin wall escaped its own rounded corner.** A sloped floor builds its cavity square, and a sharp corner sits `sqrt(2)·(OUTER_R − wt)` from the outer arc's centre while the arc reaches only `OUTER_R`, so below ~1.1 mm the cavity left the rim face it is a hole of and `plan_piece` panicked `total_h hole without a containing face`. The flat path rounds the cavity concentric with the outer arc; the sloped path **could not**, because `ring_on_plane` named an arc on a tilted plane with a Z-axis circle when the true section is an ellipse — rounding there swapped the panic for eight `EdgeOn` audit errors. So the wall is clamped to `SLOPED_MIN_WALL`, the same kind of clamp already applied at 0.4 mm and `PEG_TANGENT − 0.6`. Tangency is not enough: 1.0983 (the exact algebraic threshold) still fails, 1.10 builds — hence 0.05 of clearance. **`ring_on_plane` emits the ellipse now** (below), so the reason for leaving the sloped cavity square is gone; the clamp and the square cavity are still in place and re-rounding it is untried.
- **A sloped bin took no inner wall at all** — not a rare one, *any*, plain straight spanning divider included. The wall is carved as a z-prism island whose bottom ring sits at a flat `floor_z`, and a tilted floor is not at `floor_z`: `audit` reported `EdgeOnSurface` and `EdgeVertexGeometry` in equal numbers. The partial-height branch already skipped walls on a slope; the full-height branch does too now, so a sloped bin builds without dividers rather than emitting unsound geometry. **The one fix that drops a feature the user asked for** — revisit whenever the sloped cavity stops being a special case.

  **The partial-height branch only *half* skipped them.** Its guard sat between `band_partial_walls`'s two branches, so the *island* branch — a wall lying wholly inside one compartment, which is the common case for a long diagonal across an L — reached a sloped bin regardless, and left an edge running the length of the wall unpaired at the rim (`edge N used fwd=0 bwd=1` at exactly `total_h`). The guard is the first statement of the function now. Both of `fuzz_params_broad`'s remaining sloped classes: 15/400 → **12/400**, 6 defects → 4.

At 170/6000, biggest first: **124 (73%) are one family — openings meeting geometry that is not a straight perimeter run** (the open-run panics + a non-tiling face + the enclosed-hole `total_h` case, that last share since retired). Then 14 of the `wt = 2.700` manifold coincidence, 17 free-form-wall tessellation leaks, 15 sloped audit failures.

Two more from that rewrite, both pre-existing, neither diagnosed:

- **Two inner walls crossing at a cell centre hand the triangulator a face whose loops do not tile** (`CROSSING_WALL_TILING`), ~1–2% of tidy configurations. Characterised: **independent of tessellation density** (identical at segs 2 through 24, so a bad loop, not a sampling artifact — matching the `triangulate` note that a firing is a defect in whoever built the face), and knife-edge in position and width — on a 1×3 bin `h@84 w2.4 + v@21 w2.8` fails while `h@63`, `h@42`, `v@10`, widths 2.4 and 3.2 are all clean. A 5-loop face each time.
- **`fuzz_params_broad` is not reproducible run to run**, at `RAYON_NUM_THREADS=1` as well — a seeding issue, not threading. Confined to `tessellation leaks` findings: same case lands in a different group between runs, moving counts (13 vs 14 distinct defects at 2000 cases). `tessellation_leaks` builds its `Vec` by iterating a `HashMap` and `TessLeak`'s `Debug` carries `faces: [..]`, so the failure message is hash-ordered. The gating profiles are stable across five runs.

## Openings and the cavity walk

**Rounding a reentrant corner takes a wall on both of its edges.** The arc is struck about a centre `OUTER_R` inside each inset line, so it stands `OUTER_R − HALF_TOL` = 3.5 mm past both **pitch** lines, over a cell the bin does not occupy — the overhang `carve_to_cells` reserves with `REENTRANT_FILLET_OVERHANG`. That bulge is the outside of the wall that turns the corner and is legitimate only as such. `same_side` in `author_outer_loop` already squared the corner when *one* edge was open; with **both** open it held (both unwalled), so the corner stayed rounded while the cavity, which subtracts no wall strip for an open edge, ran out only to the pitch lines. `cavity ∩ outline` then clipped away every other scrap of wall and left the bulge standing alone: measured on an L at stock params, a curved triangle with 2.154 mm legs, 1.66 mm² of section, rising 19.8 mm from floor to rim with nothing attached above `floor_z`. Reads as one connected component only because it merges into the base below the floor, which is why a shell-count check walks past it. Guard is `corner_walled` now.

Chosen over trimming the bulge with the cavity, which gives the same voided corner but has to re-derive the blend chain around it — built naively it zeroed one 5-cell bin's fillet outright (13 requested → 0). Squaring costs nothing downstream: it changes the *sketch* the boolean consumes, not the boolean. The rounding guarantee it gives up (a sharp outer corner pokes through the cavity arc once `fr > wall_thickness · (2 + √2)`) cannot bind here — that failure is the rim strip between the two arcs self-intersecting, and where both edges are open there is no rim strip. `fuzz_stripped_polyominoes` **31/150 → 15/150**, 7 → 4 defects, retiring every `FILLET_FAILED` class it had. No other profile moved.

**An opening is a boolean for the cavity and a walk for the wall.** `cavity_inset` is zero at an open edge and `HALF_TOL + wt` at a walled one, so an opened cavity already runs out past the outline to the pitch line. Intersecting with the outline is the whole of what an opening means to the cavity:

```
cavity = shape ∩ outline
wall   = outline where no cavity replaced it  ∪  reversed(cavity runs that keep a wall)
```

`clip_cavity_to_outline` marks a run `coincident` when its midpoint lies on the outline — a span with no wall. Those runs bound no material and are exactly what the wall's authored boundary leaves out.

This replaced a ray-cast pinch: cast from the run's endpoint along the *direction* of the adjacent cavity segment, truncate to the hit, walk the outline between the two hits, rebuild the wall from what the walk left, chain the fragments into loops. It needed the neighbour straight (a reentrant corner offers the concave fillet arc), needed the hit within reach in the right direction, and two openings meeting at a notch produced walks that did not compose. `resolve_open_runs`, `pinch`, `consume_walk`, `consume_all_near`, `plan_wall_sectors`, `chain_fragments`, `seg_on_open` all gone: −216 lines net, `fuzz_stripped_polyominoes` 57/150 → **40/150**, `no pinch for run` and `wall-sector chain stuck` retired.

Three things it does not get for free, all three manifold errors first:

- **One presplit for both booleans.** They share the wall between them and their results must weld, so `presplit_regions` gives the cavity shapes and the outline a single segmentation before either sweep runs. Without it each sweep cuts the shared boundary at its own f32 points and the solid opens at an edge nothing pairs with — the failure `region2d`'s own note warns about.
- **The lip carries the wall's vertices.** Standing wall above the floor and base's outer wall below it meet along the lip, so `split_outline_at` cuts the outline at every vertex of the wall. Without it the base emits one long edge across a span the floor and the wall above already divided (`edge 240 used fwd=0 bwd=1`). That split is also where `peg_splits` stations come from, so the peg profile still welds to the wall's bottom ring.
- **The wall is authored, not differenced.** Material has exactly two kinds of boundary: the outline wherever no opening replaced it, and each opened compartment's wall-facing cavity runs reversed so they wind as holes. The wall is their union, and the two sets meet precisely where a cavity leaves the outline, so `chain_loops` closes them with no synthetic cap and no sweep. `presplit_regions` is what makes the outer half a per-segment midpoint test rather than a boolean: one segmentation means every outline segment lies wholly inside or wholly outside each shape. This replaced `w = region_difference(&w, &[shape])` folded over the compartments, and the fold was forced from both sides — opened cavities are not a region a single difference can take (each runs out to the pitch line at its own openings, so two compartments facing the same empty cell overlap out there), clipping them to the outline first trades that for a pair of long runs coincident with the outline that the sweep resolves to nothing, and unioning them first merges the compartments the divider between them is supposed to keep apart. Containment per segment asks the boolean for none of it: overlap is harmless (a segment swallowed twice is still just swallowed) and a coincidence cannot swallow a run by accident (coincident runs are exactly the ones the inner half drops on purpose). All eight profiles byte-identical across it, ~1300 cases. `chain_loops` **drops a chain it cannot close**, so the count is asserted — every fragment belongs to exactly one closed loop. Without it a boundary that failed to partition leaves the wall quietly missing a piece rather than failing.

### The cavity's boolean was a limit of `trace_rects`, not of authoring

The overshoot keeps cavity and outline **transverse**, so `cavity ∩ outline` is a proper crossing — that is why the boolean works. Authoring the cavity to abut instead (a `HALF_TOL` strip at open edges, the outline's radius on corners landing on the profile) was built and fails, for a narrower reason than it first looks, and the reason names what a replacement must do. Take a 1×1 with the north edge open. Cavity's east wall at `x = 40.55`; outline's NE corner is an `OUTER_R` arc about `(38, 38)`. Where a wall meets an opening *near a rounded corner* the cavity must step from the wall's inset onto the profile, where the two meet:

```
(40.55 − 38)² + (y − 38)² = 3.75²   ⟹   y = 40.75
```

Step belongs at `(40.55, 40.75)`, on the arc. `trace_rects` is **rectilinear** and puts the corner at `(40.55, 41.75)` — a millimetre north, outside the outline it is meant to lie on, so the chain has nothing to close against. Every wall/opening transition within `OUTER_R` of a bin corner is this case. A limit of the *tracer*, not of sketch construction: line ∩ circle is closed form and the kernel solves it in several places.

**So the cavity's perimeter is authored now, on a boundary walk like `author_outer_loop`'s.** Each edge contributes a run at its own inset — `HALF_TOL + wall_thickness` walled, `HALF_TOL` open, `wall_thickness / 2` at a divider — and each corner is resolved by the pair of insets meeting there:

- **both walled** — the compartment's own radius, `rc` convex / `fr` reentrant;
- **both open** — the outline's radius, since the cavity *is* the profile there: `OUTER_R` convex, square reentrant (see `corner_walled`);
- **walled against divider** — square;
- **mixed (walled against open)** — the step, terminated by intersecting the walled edge's inset line with the outline loop. Usually the corner arc; where the wall is thick enough that the inset line clears the arc's extent it is the straight run, so the query is *line against the outline*, not line against a known arc. **The only case needing a crossing solve.**

Not the ray-cast pinch this replaced, and the difference is the point: the pinch cast along a *neighbouring cavity segment's* direction, so it needed that neighbour straight and failed where the neighbour is the concave fillet arc. Here the line is known before anything is cast — the wall's own inset — and only its first crossing with the outline is wanted. Well posed wherever a wall meets an opening.

**Corner construction**, `author_outer_loop`'s generalised off its two magic constants. 90° corner between step `s` at inset `ins` and `s_next` at `ins_next`, blend radius `r`, `c = mm(s.to)`, `d`/`d1` the two directions, `nrm`/`n1` their left normals:

```
convex     centre = c + nrm·(ins + r) + n1·(ins_next + r)
           tangent on s      = c − d·(ins_next + r) + nrm·ins
           tangent on s_next = c + d1·(ins + r)     + n1·ins_next

reentrant  q      = c + nrm·ins + n1·ins_next
           centre = q − nrm·r − n1·r
           t1     = q − n1·r          t2 = q − nrm·r
```

`author_outer_loop` is exactly `ins = ins_next = HALF_TOL`, `r = OUTER_R`, where `ins + r` collapses to `PEG_TANGENT` — which is why that constant reads as a magic number there rather than as the sum it is. A square corner is `r = 0`, runs meeting at `q`; even then the run is trimmed by `ins_next` along `d`, positively at a reentrant corner (`n1 = +d`) and negatively at a convex one (`n1 = −d`), so the cavity legitimately runs *past* the lattice point into a notch.

### The partition the walk runs over

**`layout::compartments`.** The tracer this replaced never named a compartment: it subtracted a strip per divider and per walled edge, handed the lot to `trace_rects`, and the compartments were whatever that fell apart into. The walk needs the partition *before* any geometry exists, so `compartments` states it combinatorially: connected components of the piece's cells under *adjacent, and the edge between them carries no divider*. Components, not a per-edge count — `a_divider_makes_a_compartment_only_where_it_separates` says why: a divider a path routes around separates nothing.

One compartment yields exactly one cavity loop while `2·(HALF_TOL + wt) < GRID_PITCH`, and that bound is the whole argument: under it a compartment always keeps a `pitch − 2·(HALF_TOL + wt)` square at each cell's centre (so it yields a loop), every undivided adjacency keeps a passage that wide (so only one), and every divided one is covered by a full-pitch strip of width `wt` (so two compartments never merge). Above it a bin's walls are thicker than its cells and a compartment may be starved to nothing or pinched in two — neither a defect, which is why the sweep's count equality is guarded rather than asserted flat.

**Where two dividers meet at a compartment's reentrant corner the tracer leaves a staircase; the walk closes it.** A divider's subtraction rect spans exactly one cell edge and reaches `wall_thickness / 2` either side, so at a lattice point where two dividers meet neither rect covers the diagonally opposite quadrant — the cavity keeps a `wt/2 × wt/2` tab of the junction that should be material. Measured on a 2×2 at `wt = 1.2` with cell (1,1) divided off, the L-shaped compartment traces

```
… (82.55, 41.4) (42.0, 41.4) (42.0, 42.0) (41.4, 42.0) (41.4, 82.55) …
```

— two reentrant corners and a convex one where there should be a single reentrant corner at `(41.4, 41.4)`, which is what `q = c + nrm·ins + n1·ins_next` gives for two edges inset `wt/2`. The walk gets it right by construction, and gives the floor fillet a corner it can roll around instead of a 0.6 mm step.

Patching the tracer is the trap: extending each divider rect by `wt/2` at both ends (the trick `web/src/lib/project/walls.ts` uses, where the band is reserved by construction) removes the staircase but bites a `wt × wt/2` tooth out of any compartment a divider merely ends inside — the extension is sound only where *another* divider or a walled edge continues at that lattice point, which is the walk's corner classification done in the wrong place. No test on this; the lib gate is green and the profiles at documented counts, because the tab is small enough to build.

### What is authored, what is subtracted

**The cavity is authored.** `walked_cavity` is what `plan_cavities` calls: one `compartment_cavity_corners` per compartment, returning that compartment's outer loop and the holes inside it, paired by containment. Downstream unchanged — same `shape_cavity_loop` rounding, same islands, and for an opened bin the same `clip_cavity_to_outline`, because an opening is still an inset of *nothing* and an opened cavity still runs out to the pitch line to be pulled back.

`compartment_corners` is the walk: `cavity_inset` per edge (`HALF_TOL + wt` walled, `wt/2` at a divider, 0 at an opening), one corner per turn at `c + nrm·ins + n1·ins_next`. Where the boundary does **not** turn there is still a corner to emit whenever the inset changes — a wall meeting an opening, or a wall meeting a divider, along one straight run. Those two inset lines are parallel and never meet, so the run contributes *two* corners and the boundary jogs across at the lattice point. That case is why `shape_loop` cannot be handed the job as it stands: its one-corner-per-point construction interpolates a diagonal ramp between two parallel inset lines instead of a right-angled step. A collinear pair at one inset contributes no corner — `merge_collinear`.

**A divider finger is subtracted after the walk, not walked.** A divider whose two cells stay in one compartment — the ring routing around it, exactly `partial_divider_finger_is_watertight`'s 2×2 with one divider — separates nothing, so it lies on no compartment boundary and a walk over *cells* can never see it: a slot stopping inside a cell. It is real geometry (a wall stub reaching in from the perimeter, or a free-standing island when neither end touches a wall) and dropping it costs exactly the strip — 48.661 mm² of a 2×2 at `wt = 1.2`, `1.2 × (42 − HALF_TOL − 1.2)`. `finger_strips` collects them, `compartment_cavity_corners` takes them out with one `region_difference`. The split of labour is the point: the **perimeter** is authored, because that is where insets differ edge to edge and corners must land on the outline rather than a lattice point — what a rectilinear tracer cannot do — while a **finger** is a plain rectangle mid-cavity, nowhere near an arc, needing no case analysis. Strips are unioned through `trace_rects` before the difference: two dividers running end to end give two rectangles sharing a boundary run, and a region whose own loops touch is not an operand a sweep can classify — it left a 0.001 mm² sliver on 36 swept compartments.

**Verification, and what is left of it.** The walk was characterised against the tracer by a 4312-case sweep (`the_walk_reproduces_the_tracer_except_where_a_divider_meets_a_notch`, 2724 excluded / 1588 exact): **all** disagreements were one predicate, a divider cutting the cell holding one of the tracer's rectangle-shaped fixups, and the filter came from the tracer's own emit condition rather than being fitted to the failures. **That sweep and its `plan_cavity` oracle are deleted.** What covers the walk now is `a_divider_junction_and_a_divider_by_a_notch_walk_to_a_single_corner`, which never called the oracle and still pins both divergence cases as explicit corner lists, plus the watertightness gates and the fuzz profiles. Restoring the characterisation means restoring the tracer; the two amounts below are kept because they say *why* the walk's answer is the one to keep. Both are the reentrant corner patch:

```
t·(t − wt/2)     patch with a divider along one of its two sides
(t − wt/2)²      patch with a divider along both
```

The patch is a full `t × t` square subtracted at a piece's reentrant corner, existing because the two wall strips there meet only at a point — V wall holds the NW quadrant, H wall the SE, patch is the SW square joining them. The tracer's way of producing the corner the walk gets for free. Where a divider already covers part of that square the rest is a lump of material hanging into the compartment: `1.45 × 0.85` at the default wall. `a_divider_junction_and_a_divider_by_a_notch_walk_to_a_single_corner` pins what the walk gives instead, both cases, as explicit corner lists.

**Measured against the profile table.** `fuzz_wall_openings`, `fuzz_tidy_inner_walls`, `fuzz_bin_shapes` stay green; `fuzz_inner_walls` (23/150), `fuzz_openings_and_inner_walls` (6/150), `fuzz_split_pieces` (1/120) unmoved. `fuzz_params_broad` **24/400 → 22/400** (two `OPENING_LOSES_FILLET`). `fuzz_stripped_polyominoes` retires its `edge 314 used fwd=2 bwd=2` manifold class outright — 4 defects → 3 at the same 15/150, that case now failing in an existing class. Its repro was a divider junction: the staircase was costing a bin its manifoldness.

### An opened compartment takes no inner wall

Both `carve_full_walls` and `band_partial_walls` skip a compartment the opening touched, so a wall the user drew across one silently disappears. It is a real feature loss and it is the `OPENING_LOSES_FILLET` class still on `fuzz_params_broad` (×2/400): a partial wall's *ramp* is the only blend a bin with `cavity_corner_radius: 0` asks for, and dropping the wall drops the request, so the closed build lands 1 and the opened build asks 0.

Both guards are load-bearing, for the same reason and not the one the comment gave. **Full-height:** removing it panics `total_h hole without a containing face` — carving an opened compartment leaves a rim hole the containment pass cannot place. **Partial-height, crossing the boundary:** the band machinery walls the whole loop, and an opened loop's coincident runs have no wall to emit — that is exactly what `emit_open_cavity` leaves to the standing wall — so the stack walls the doorway shut.

**Partial-height, wholly inside the compartment, was tried and does not pay.** That branch makes an ordinary `Island` with a `top`, which needs nothing from the bands, and `emit_open_cavity` was given the tower-to-`top` plus top cap it lacked. The lib gate stayed green and `fuzz_params_broad` went **7/400 → 9/400**: the class above went 2 → 3 and a new `Bin is not geometrically sound` appeared. Reverted. The repro that motivated it is a *crossing* wall anyway, so the branch it fixes is not the branch the fuzzer is failing on.

### An opened sloped bin keeps its ramp

`author_outline` used to do `let slope = if openish { None } else { slope }` — any open edge anywhere on the piece and the whole bin's floor came out **flat**. It built, validated and tessellated cleanly, so nothing but `fuzz_params_broad`'s floor-fillet comparison ever saw it, as a bin going from no cavity floor at all to three unrounded ones (×5/400).

Three emitters have to agree on one plane, so `SlopedFloor` derives it once per piece and hands out `plane()` and `z_of()`; two of them solving it separately would put a shared ring a float apart and open the solid along it.

```
plinth       outline swept  Z(floor_z) -> ramp        (SlopedWall, outward)
wall sector  wall region    ramp       -> Z(total_h)  (was Wall floor_z -> total_h)
floor        compartment    on the ramp               (was PlanarFace at floor_z)
island tower enclosed hole  ramp       -> Z(total_h)  (was WallFaces floor_z -> total_h)
```

The plinth is the load-bearing piece and the reason a prismatic sweep is wrong rather than merely ugly. The standing wall op sweeps a *region* — outline outside, cavity runs inside — so it emits both surfaces at once, and swept from `floor_z` its **inner** surface goes on existing below the ramp, where both sides of it are material. Standing the wall on the ramp instead leaves the outline unclad from `floor_z` up to it, which the plinth clads. Ring pairing then closes: outline at `floor_z` is the outer wall's top against the plinth's bottom; outline at the ramp is the plinth's top against the wall's outer runs where a wall stands and against the cavity floor's own boundary at an opening, since an opened cavity runs out to the outline. A closed bin is untouched — its outer wall already runs `PEG_HEIGHT → total_h` in one sweep and has no wall sectors.

`fuzz_params_broad` 12/400 → **7/400**, 4 defects → 3, and 16 → 11 at seed 1, 18 → 12 at 7, 14 → 12 at 42. It needed `ring_on_plane`'s ellipse first: the outline is *always* rounded, so the plinth and the wall both lift `OUTER_R` corner arcs onto the ramp.

### An opening onto an enclosed hole's boundary is ignored, not honoured

`layout::enclosed_holes` flood-fills the empty cells a bin's cell set surrounds; `effective_walls` drops any `open_edge` touching one, so the wall stays. The bin builds and stays closed; the doorway simply does not appear — the same degradation a sloped bin's inner walls take.

A 0.25 mm mismatch, not a merge. The cavity is built from the piece's *cells*, and an enclosed hole is not a cell — so on the open side nothing is inset and the cavity stops dead at the pitch line, x=42.0 on a 3×3 ring, while the hole's own material loop sits `HALF_TOL` the other way at x=41.75. Island loop (bbox 42.0,40.55 → 85.45,85.45) and hole loop (41.75,41.75 → 84.25,84.25) therefore **cross** instead of nesting; the rim's containment pass cannot put the hole loop inside the island face and it lands on the outer rim face beside the cavity rim — outer 15722 mm², holes 1792 + 15141, net −1209 mm², leaving the face no interior. `audit` reports `LoopContainment` (the containment pass had only ever tested each hole against the *outer* loop, never holes against each other) and `build_bin_solid` asserts the audit, which turned 196 tessellation leaks into a message naming the defect.

Honouring it properly is unbuilt: the cavity region would have to extend through the doorway into the hole void, turning the island into a C-shape and putting a through-hole in the cavity floor. Dropping a hole that another hole contains is **not** a shortcut — `divider_ring_island_is_watertight` has a legitimately nested pair and breaks.

## Determinism

- **Any iteration order reaching geometry must be sorted.** See the `vinfo` `HashMap` note above.
- **Reported leaks are picked by lexicographic minimum, not `leaks[0]`.** `tessellation_leaks` sorts by `(a.z, a.x, a.y)` and ties resolve by `HashMap` order, so `leaks[0]` moved between runs and reshuffled the defect grouping (`fuzz_params_broad` drifted 12↔13 groups). All fuzzers byte-identical across repeated runs at a fixed seed now; keep any new failure message free of hash-ordered content or the grouping stops meaning anything.
- **A run is deterministic per seed, but adding a generator arm reshuffles the stream.** Quote the *case literal* in a bug report, never "seed 7 case 412".
- **A shared cut point must be solved once, not once per side.** `presplit_regions` used to walk *ordered* region pairs, so a crossing was solved twice — `seg_seg_points(sA, sB)` for A's cut list, `(sB, sA)` for B's. The line/line determinant is not ulp-symmetric under the swap, and if the ulp straddled a `weld_key` cell boundary (observed `57.819447` → 578194 vs `57.81945` → 578195) the two segments interned *two* vertices, every edge touching them dangled, `validate` failed `fwd=1 bwd=0`. Unordered pairs now, pushing the identical `pt` into both cut lists. Halving the solves also made it **faster than before the bug was known**: a 32×32 build 19.4 → 17.1 ms (alternating A/B). Resist any fix for this class that reconciles *downstream* — snapping in `Builder::vertex` was tried, cost ~10% of a build, and only hid which producer was wrong.

**The long test targets are `rayon`-parallel and must stay deterministic.** Every profile shares one `sweep()`: cases generated **sequentially** from the seeded `Rng` into a `Vec` (case stream byte-identical to serial), checked with `par_iter`, grouped in `BTreeMap` order, shrunk in parallel. Generating per-case seeds in parallel would reshuffle the stream and invalidate every recorded count.

Three phases, two parallelisable. Measured 8c/16t: check phase alone **7.1×** (2000 cases, 6.22 → 0.88 s); heaviest profile end to end **6.5×** (3000 cases, 12.15 → 1.86 s) — about the ceiling for compute-bound work on eight physical cores, the serial generator being the remainder. Shrink used to be the weak half: `entries.par_iter()` only spreads across *distinct signatures* (often one or two) while each shrink is a long sequential search, so its cell-removal sweep is `par_iter().find_map_first` now. **`find_map_first`, never `find_map_any`** — returns the match earliest in iteration order whatever order threads finish, keeping a shrunk repro a function of the seed alone. The remaining `keep_if` chains stay sequential: each edits the current best, genuinely dependent.

`catching` no longer swaps the panic hook per case — with many threads inside `catch_unwind` that race silenced the harness's own hook. `quiet_panics()` installs one silent hook per sweep, refcounted, and restores the loud one before the report is asserted.

## Debugger handover

**A bin in the debugger can be handed over as a test.** `Params::rust_literal` prints a `Params` as the Rust literal that rebuilds it, omitting fields still at default. `gridfinity-app`'s **Copy config** button puts that on the clipboard (optionally a file) with the `BlendReport` for the same bin — blends requested, blends landed, and the kernel's own refusal message when one did not. The counts alone do not name a defect; that message does, and it is otherwise visible only from inside `fillet_best_effort`.

`tests/fuzz.rs`'s `repro` calls the same function, so a hand-exported bin and a shrunk case arrive in **one** format and either pastes straight into a `#[test]`. Keep it that way — a second printer is a second format to recognise, and the two drift the moment a field is added to `Params`. `an_exported_config_names_every_field_it_changed` is the guard: every non-default field reaches the string, a default `Params` mentions none. A field added to `Params` and not the printer fails silently and lands on whoever tries the export months later.

**`gridfinity-app`'s `broken()` is coupled to the model's failure surface.** Its three failure-path tests need a configuration that genuinely fails, and every fix here retires one — re-pointed twice so far. Needs a **hard** failure: `build_bin` only catches `Err` and panics, so a solid that builds and then fails `validate` reads as success there.

**One `catch`, `main.rs`'s, `pub(crate)`.** `debugger.rs`'s test module had a second copy differing only in dropping the `"panicked: "` prefix. It is the *app's* net (silent hook for the duration, unwind or `Err` alike into a message) and the rollback sweep drives it deliberately — which is not the same as `rolling_back_the_construction_never_crashes_the_viewer` being routed through it. That test still is not, on purpose: the app keeps the net so the window survives, and a fuzzer behind one passes on a viewer that panics at every step.

## Workspace layout

Virtual workspace rooted at the **repository root** (`../Cargo.toml`, edition 2024, resolver 3) — every `cargo` command runs from there, not from `crates/`. Six crates, `default-members` the app:

- **`crates/gridfinity-brep`** — the engine library, whose crate root *is* the kernel. One dependency: `glam`. B-rep kernel and triangulator alike are hand-rolled.
- **`crates/gridfinity-model`** — the Gridfinity model on top of it. Feature `serde` derives the parameter types' JSON; the wasm crate turns it on.
- **`crates/gridfinity-project`** — the drawer fitter on top of that.
- **`crates/gridfinity-app`** — eframe/egui/wgpu app **and** the headless `optimize` command, one binary. Depends on all three plus `gridfinity-render`.
- **`crates/gridfinity-render`** — the shared wgpu renderer, no egui and no wasm.
- **`crates/gridfinity-wasm`** — the web app's bindings.

**There is no facade crate.** `gridfinity-cad`, which held the first three layers as one, is gone; each consumer names the layers it reaches into in its own `Cargo.toml`, so a call from model-level code into the kernel is a dependency someone had to declare. `gridfinity-model` re-exports `Mesh`, `Solid`, `Tessellation`/`tessellate`, `audit`, `to_xt_text` and `Params` at its root, which is what the app and the bindings import for the common cases.

The three, layer by layer:

- `gridfinity-brep/src/` — `math`, `geom`, `sketch`, `topo`, `build`, `fillet`, `tess`, `planar`, `mesh`, `xt`, plus 2D loop and region work: `round` (tangency + corner rounding on a seg loop), `nesting` (which loops sit inside which), `region2d`, `rectregion`. **Nothing here knows about Gridfinity** and now nothing *can*: the crate does not depend on the model, so the one-way direction is the compiler's answer rather than a convention. Paths `crate::topo`, `gridfinity_brep::geom`. Its own tests build kernel solids only — a box, a rounded-rect prism with a blended top rim, a loft with conical corners, that prism cut through two of its corner blends (`xt::fixtures`) — chosen for the node classes they force the writer to emit, since a bin is no longer reachable from here.
- `gridfinity-model/src/` — `gridfinity/` (the model, twelve modules), `layout` (grid cells/edges), `printers` (bed fitting and split planning, pure logic), `subbin` (the insert body, below), `perf` (the model's rows in the kernel's profile, below). `tests/kernel_on_a_bin.rs` is where the kernel properties that want a *bin* to stand on live — `orient::normalize` restoring the invariant and moving no geometry, `region2d`'s crossing-box prune discarding nothing, `split::trim_half_space` conserving volume and leaving every blend on its own surface. They were `#[cfg(test)]` modules inside the kernel and moved here with their fixtures intact, because the check is worth more than the file it sat in.
- `gridfinity-project/src/` — `drawer`, `pack`, `rects`, `settle`, `tidy`, `walls`. Depends on `gridfinity-model` for `GridCell`, `Orientation`, `HALF_TOL` and `InnerWall`, and **on the kernel not at all**.
- `src/region.rs` is **gone**: polyomino boundary tracing that nothing in the workspace called, found unreferenced when the crate was split and deleted rather than given a home.

Inside `gridfinity-app`: `main` (dispatch + the egui `App`, which is the shell: header, two panels, viewport), `theme` (the palette and style, `web/src/theme.ts`'s counterpart), `widgets` (the shared controls, `web/src/components/ui/`'s), `sidebar` (left panel: Shape/Walls/Cuts), `settings` (right panel: Dimensions/Features/Printer fit/Display), `editor` (the grid canvas the three tabs share), `debugger`, `viewport`, `wireframe` — the window; and `optimize` (the pipeline), `grouping` (which objects share a bin), `input` (the TOML), `export` (STL/X_T files), `report` (stdout) — the command.

**`--mode` is mandatory, `FitMode::{Auto, Bins, Hybrid, Walls}`, no default.** `walls` is what the command always did: one drawer-wide `LogicalBin`, one pocket per placement, the leftover material. `bins` is one bin per **object type**, holding that object's whole quantity as its own compartments. `hybrid` is `bins` with objects **sharing** a bin where sharing recovers cells (`grouping.rs`, below). **`auto` is `hybrid` where the drawer holds it and `walls` where it does not** -- a discrete bin is the smaller print and the smaller thing to lose, so the drawer-wide body is the fallback, never the preference. Two types, not one: `FitMode` is what the command line asked for, `Built::{Bins, Hybrid, Walls}` what a finished `Run` is, so `report.rs` and everything else downstream of the plan carries no arm it can never take. `fit` resolves it and nothing else does; `plan_and_check` is `plan_bins`/`plan_walls` **plus `refuse_unplaced`**, because `Auto` chooses on exactly that question -- a plan leaving an instance unplaced has not fitted the drawer whether it said so itself or left the shortfall to be counted -- and a caller holding a `Plan` holds one that places every instance. `Run::fell_back` is the bin plan's refusal an automatic run fell back from (`None` for a stated mode and for an `Auto` run that got its bins); the report's Drawer section prints it as the `fit` field via `fitted_as`. A drawer neither plan holds fails with the **walls** refusal, naming the shortfall against the whole drawer rather than against one bin. Cost of a fallback is the discarded bin pack, which refuses before any geometry. `auto_builds_one_drawer_wide_bin_only_when_the_bins_do_not_fit` is the gate: four 22 x 30 mm objects in a 126 x 42 mm drawer, each rounding up to a cell of its own so the bins want four of the drawer's three, and it asserts `Bins` really is `Err` and `Walls` really is `Ok` on the same fixture rather than inferring either from the automatic run. Two levels of packing in `plan_bins`: `plan_one_bin` finds the smallest `n x m` cell rectangle whose `packing_area` holds every instance (candidates ordered by `(n*m, |n-m|)`, tested at `PackEffort::Quick` and re-packed at the run's own effort -- which cannot place fewer, since `PackSearch::new` runs the same greedy pass at every tier and `step` only keeps improvements, asserted), `footprint_cells` drops every cell no claim grown by `packing_inset` reaches (so an L-shaped object gets an L-shaped bin; the drop is safe because a dropped cell's edge becomes outline and the perimeter wall stands inside it, and it falls back to the whole rectangle rather than sever edge-connectivity), then the bins themselves are packed into the drawer's own rectangle with every margin **zero** -- a Gridfinity bin already stands `HALF_TOL` inside its cells. **Every outer placement lands on the cell lattice** because every part offset, extent and the area's origin is a multiple of the pitch; `cells_of_rects` asserts it rather than trusting it. `place_in_drawer` puts the bin's instance claims through the *same* normalise/rotate/translate the packer put its footprint through -- rotating footprint and claims **as one list**, so `rotate_parts` normalises to the footprint's own bounding box -- and asserts the footprint comes back as the packer's own answer. `compose` adds the two quarter turns. `Plan::result` is the placement of every **instance in drawer millimetres** in either mode, so `objects`/`packing`/`placements`/`object_boxes` read one thing and branch on nothing; `Run::{split_lines, parts, cells}` are unions over the bins (`all_split_lines`, `all_parts` in piece order, the whole drawer's cells) and identity for the single bin `walls` builds. `Run::bins` is one `FittedBin` per object, which the report's **Bins** section prints (cells, grid, mm, compartments, and `built_as` -- the file the model named it, since the model names pieces by position and a `bins` run's reader needs the pairing).

**`subbin` gives an object its own insert, and `optimize` builds it.** `input::Subbin` is the interior the file states (`[width, depth, height]`, empty string = the fit decides); `Object::pack.parts` becomes the **insert's outer box less `2 * floor_fillet`** while `Object::footprint` keeps the object as declared. The deflation is the whole trick: a claim reserves `clearance + fr + t/2` because an object rests on the compartment floor and wants room around it, and an object in an insert does neither -- the insert stands on the floor, its chamfer clears the blend, and the gap around it is a part fitting a part. So `deflate = clearance + fr - subbin_clearance`, giving `pocket = interior + 2*wall + 2*subbin_clearance` and `outer = pocket - 2*subbin_clearance`: walls exactly nominal, insert snug. **`settings.subbin_clearance` defaults to `HALF_TOL`**, the standard's own bin-to-baseplate gap; using the run's `clearance` (2 mm on the ikea drawer, which is a *tool's* room) left it 4 mm loose across. A pinned axis sets `Object::max_size` on the packed footprint, so `settle`/`clamp` pin the compartment through the path that already existed; stating `subbin` and `max_size` on one axis is refused as one measurement stated twice. `optimize::build_subbins` runs over `PackResult::placements` -- one path for all four modes, placements being in drawer millimetres in every one -- and turns each claim into a `SubbinSpec` (pocket inset by `clearance`, interior pinned or `outer - 2*wall`, `floor = max(wall, fr)`, `corner_r = max(cavity_corner_radius, fr + MIN_ARC_R)`). `Run::all_pieces()` returns `Body { name, solid }` rather than `&BinPiece` so inserts reach the writers and Soundness beside the pieces; `piece_files` still reads `run.pieces` alone. Report gets a **Sub-bins** section, a Printing row per insert (measured off its own solid, `insert` where a piece names cells), and two warnings -- standing proud of its compartment, and not fitting the bed. `View::subbins` carries the spec, not geometry; the window builds it in `SUBBIN_AMBER`, labels it name-over-file, and hides it behind a *Sub-bins* checkbox. **`subbin_shift` gives it no band displacement**: a compartment can straddle a cut (the ikea batteries did), its halves then open by `SPLIT_APART_MM`, and an uncut body can only take one band -- which read as a part not fitting. Gaps open lift it clear of the rim (an assembly explode, not a cut); gaps closed put it exactly in place, `an_insert_is_lifted_out_rather_than_moved_with_a_band`. `scene_labels` took a `gaps` flag with it, so every label now tracks the toggle rather than assuming the scene is exploded. Limits: one box per subbin object, and an insert is never split.

**An unplaced instance is an error, not a warning.** `refuse_unplaced` runs before any geometry is built, so a refusal writes nothing; the report's old "N of M instances did not fit" line is gone because it cannot fire. Too-tall objects and a piece the bed cannot take stay warnings -- the first is what `--view`'s red rim and red label exist for.

**The command line is a `clap` declaration**, `optimize::Args`, so parsing, spellings, help text and refusals all come from it and no hand-written usage string can drift from what is accepted. `Args::destination` answers the command line's two output questions in one place -- which format `-o` names, and whether `-o` can hold the format `--format` named -- and returns `None` for a `--view` with no `-o`, which is a complete invocation that writes nothing. `-o` is `required_unless_present = "view"`: an invocation that neither writes nor shows asks for nothing. Only `.x_t` infers, because an STL run writes a *directory* of one file per piece and a directory's name declares nothing; enforcement is the same fact read backwards (`Format::inferred_from` / `check_extension`, in `export.rs` beside the writers, since it is one relationship the command line asks in both directions).

Three rules the command holds itself to. **The output path is checked before any work** (`Format::check_output`, called first in `optimize::run`): STL fills a directory and X_T writes one file, so each is refused by an existing path of the other kind, and discovering that after minutes of packing and building is the same mistake reported far too late. And **the report is read off the finished `Run`, never recomputed** — every stage's result is kept on it, so the numbers printed cannot disagree with the geometry written. And **nothing half-written survives a failure**: `fit` runs under `main.rs`'s `catch`, so an invariant the kernel asserts while building arrives as `error: <the invariant>` and exit 1 instead of a backtrace, and `write_stl_dir` tessellates every piece before writing any, so `tessellate`'s own watertightness assert fires while the directory is still untouched. `--view` hands a `View` — `run.params`, `run.plate_params`, `object_boxes(&run)` and the piece file names — straight to the window in the same process; nothing is serialised between them. The plate travels as its own `Params` rather than as geometry, like the bin, so the window rebuilds both from the declarations the export wrote from; `App::show_plate` and the *Display* section's *Baseplate* checkbox (shown only when there is one) draw it in `PLATE_GREY` under the bin. **Those boxes are the one thing the window cannot re-derive**: it is given `Params`, and a `Params` carries dividers, not the objects they were cut for, so the packer's placements have to travel with it. One solid white box per *part* rectangle of each placement (so an L-shaped object reads as an L, not as the rectangle round it), **deflated by `claim_margin` first** — a `Placement` carries the instance's claim, which reaches the divider centrelines and the packing-area edge by construction, so drawing it raw draws a box lapping every wall in the layout — standing on the cavity floor and rising by the height the object declared, in the bin's own millimetre coordinates — `packing_area` is already in them, and the rotation the packer chose is baked into the rectangles, so there is no transform. White, and **flagged `FLAG_BAD` -- the renderer's pulsing red rim -- where the object does not clear the cavity, still drawn at full height**: that is the report's `is N mm tall, but a compartment is only M mm deep` warning made visible, and clipping the box to the cavity would hide exactly the thing worth seeing. Each box is also cut on the bin's split lines and each part displaced with the piece it lies in (`explode.rs`), so an object crosses a cut the way the drawer does instead of spanning the gap the pieces opened. The *Display* section's *Object boxes* checkbox appears only when there are boxes, so nothing changes for a window opened without `optimize` behind it. **`scene_labels` names every item in the scene** -- each bin, the baseplate, each placed object (red where it does not clear the cavity) -- as `wireframe::Label`s painted over the viewport by `paint_labels`, which keeps the first label in each 34 px cell of a grid, so object labels are pushed first and win a collision. **A body is named once per file it becomes** (`body_labels`): a piece is what gets written, so a bin in six pieces carries six labels, each over its own piece at a point riding the band it stands in (`Explosion::shift_at`) rather than floating in the gap, and each reading the body's name above that piece's own export file name. A body given **no** file names is named once over the whole of it, which is the bin editor -- it exports through a dialog and has nothing to show, and must not start reading "bin" six times. An **object** is not exported and is still named once whatever it crosses. `paint_labels` needs nothing for the second line: `Painter::text` lays out a newline itself, and two lines of the 9 pt face are ~22 px against the 34 px collision cell. **The file names are carried, not rebuilt** -- `View::bin_files` (indexed by bin, then by piece) and `View::plate_files`, gathered by `optimize::piece_files` off the finished `BinPiece`s. `BinPiece::name` *is* the export file name and is built in `gridfinity::pieces`; a second copy of `gridfinity-bin-{ord}-piece-{i}-of-{n}.stl` in the viewer would drift, the more so because the stem is not the label -- in `bins` mode a body reads "AAA batteries + caliper box" and writes `gridfinity-bin-1`. Indexing needs no new agreement: `pieces.rs`, `bin_vertices` and `body_labels` all partition with the same `partition_cells(&bin.cells, &bin.split_lines)`, and `piece_files` asserts every slot was filled, which is that statement made checkable. The name is always the `.stl` one, as the Printing table's is: it says what the piece *would* be written as, which is the only answer available to a `--view` that writes nothing at all. `Label::text` is a `String` for this -- a label names a *thing* as often as a kind of curve, and only the kinds are known at compile time. `ObjectBox` carries the object's `name` and its `instance` so the several boxes of one L-shaped object are known to be one object, and its **`bin`** -- which of `Params::bins` it stands in -- because in `bins` mode two boxes of one scene belong to bodies cut on different lines, and a box exploded on the wrong bin's seams travels away from the bin it is in. `View::bin_names` names each bin for `scene_labels`, so a `bins` fit labels its bodies by object rather than "bin 1".."bin N". **A bin carrying split lines previews as its pieces, not as one solid**: `bin_vertices` partitions on the bin's own `split_lines` and carves each part out of the whole solid the builder returned -- the same pieces the export writes -- then displaces each by `Explosion::shift`. Carved pieces abut exactly, so without it a split bin and an unsplit one are the same picture; the displacement is a preview offset only and nothing downstream of the vertex buffer sees it. **A baseplate previews as its pieces too, on its own bands.** `plate_vertices` is `bin_vertices` for `Mode::Baseplate`: partition `all_cells` on the union of the bins' `split_lines`, carve each part with `carve_baseplate_to_cells` (the export's own call, margins included), displace by `Explosion::new(cells, splits, pitch)`. The plate's lines are staggered off the bin's, so the two bodies open their gaps in different places and a piece of each is seen to lap a seam of the other -- the interlock, made visible. It was one solid however it was split, which is the picture of an assembly that does not come apart. **`explode.rs` displaces per band, not per piece.** `partition_cells` labels every piece with its chunk index along each axis, and `shift` is that index's centred offset times `SPLIT_APART_MM` (3 mm), so every pair of adjacent bands opens by one gap and an axis with no cut moves nothing. It was a radial unit direction from the bin's centroid to the piece's, which spent a middle-row piece's whole 3 mm on x while the rows above and below spent most of theirs on y -- the ikea drawer's middle gap read four times wider than its neighbours. `Explosion::clip` is the same bands applied to a box, which is how the object boxes are cut and moved with their piece. The report's tenth section, **Soundness**, prints each piece's shells / faces / edges / verts / audit warnings, read off the finished solids: a gate that leaves no trace in the output reads the same as one that never ran. It reads `Run::all_pieces()` — the bin's pieces then the baseplate's — as do both writers, so a file that is written is a file that section accounts for. The baseplate is `Mode::Baseplate` over the bin's own cells and **its own split lines**, on unless `settings.baseplate = false`; it asks for no blends, so the `BlendReport` is the bin's alone. `plate_splits` staggers them off the bin's via `compute_staggered_split_lines`, so every seam of each body is spanned by a piece of the other and the stack constrains itself to move as one -- cut on one shared set, every seam lay in one plane and the whole thing parted along it. `Run::plate_parts` is the plate's own partition (the Printing table reads each body's cells off its own), `Run::interlocked()` is the two line sets being disjoint, and `plate_stagger_cost` is what keeping off the bin's lines cost in extra pieces. A fallback to the bin's own lines is a real outcome and is reported, never silent.

**A `--view` object box is the object's own size, not its compartment's.** `object_boxes` deflated the `Placement`'s claim by `claim_margin`, which recovers the object *only while nothing has touched the claim since packing* -- and `settle` absorbs leftover strips into claims after the packer is done, so a settled claim less the margin is the **compartment**. At `examples/ikea-alex-drawer-1.toml`'s `tidy_absorb = 100` that draws small objects as most of the drawer. It draws `rotate_parts(&object.pack.parts, placement.rotation)` now -- the declared boxes, turned the way the packer turned them -- **centred in the compartment**, the compartment being the only thing that says where the object is and the object being free to sit anywhere in it. A layout that settled nothing draws exactly what deflating the claim drew. `an_object_is_drawn_at_its_own_size_however_much_its_compartment_grew` holds both halves and was checked to fail on the old line; `BOX_IN_COMPARTMENT_MM` (1e-6) is the assertion that the object goes in the space the fit reserved, loose only by `Rect::right`'s quantum.

### `grouping.rs` — which objects share a bin

`--mode hybrid`'s whole content, and the only file that decides anything about grouping. `GroupPlan` is one bin's worth of objects (sorted ids = identity and cache key), `plan_group_bin` is the old `plan_one_bin` generalised from one object to several -- same `candidate_sizes` order, same area prefilter, same `footprint_cells` trim, then `project::settle` over the bin's own cavity -- so `--mode bins` is this over groups of one and `optimize.rs` keeps no second copy. `lay_out_bins` is the outer pack and the composition, shared by both modes; they differ only in which groups they hand it.

**Every term is priced in cells.** `score = cells + W_AIR 0.25 * air + W_LARGEST 0.15 * largest + W_CUT 2.0 * cut + W_SHARED 0.5 * shared + W_OBLONG 0.1 * oblong`, each term a number of cells, because the question is "is this worth a cell?". `shared` is each bin's **cells per object, once per object beyond the first** in it. Two normalisations were tried and measured wrong first, and both failures are the reason for the third: **fractions of their own worst cases** (the `Tidiness` form) bury the cells term -- a cell is a small share of a 91-cell drawer, an extra object a large share of five -- and *nothing grouped* on either worked example; a **flat price per shared object** is wrong in both directions at once -- 0.75 cells refuses four 12 mm objects the single cell all four fit in, 3.0 cells still merges five big tools into one 68-cell body, which is what `--mode walls` already builds. Pricing a share as a share of what is shared fixes both.

`better` is `tidy::better`'s shape: **unplaced instances first and absolutely**, then the score. That is what lets grouping *rescue* a drawer -- a partition that fits beats every partition that does not, whatever it costs.

`choose_groups` starts from one bin per object and **asserts it never returns worse** (`better`), which is the whole justification for `auto` preferring hybrid to bins. Two phases over one budget of candidate partitions (**Quick 60 / Standard 300 / Thorough 1500**, an iteration count and never wall-clock): agglomerate the best improving pair while one improves, then move and swap single objects between the groups that survived. Groups are planned at `PackEffort::Quick` while choosing and re-planned at the run's effort once chosen; `Plans` caches every group by its sorted ids, refusals included, because the agglomeration re-forms the same groups every round. `merges` prunes a pair whose `cell_floor` -- claims over `pitch^2`, an admissible bound since a cell holds less than its own area -- says no cell can be recovered; it is a *pruning heuristic*, and what it can miss is a merge that would have won on squareness alone.

**Measured** at these prices: `examples/ikea-alex-drawer-1.toml` 82 -> 75 cells, 5 bins -> 3 (the three small tools share; caliper box and file set keep their own); `examples/drawer-of-bins.toml` 33 -> 24 cells, 4 bins -> 2; `examples/drawer.toml` **fits** -- 61 of 63 cells in 3 bins -- where `--mode bins` refuses it outright. Cost is the discarded packing searches: pack 0.13 s -> 0.55 s on `drawer-of-bins.toml`, 1.45 s on the ikea drawer.

### `subbin.rs` — the insert that drops into a compartment

Open-top box, printed as its own body, `SubbinSpec` in and one `Solid` out. Stated outright (position included, so nothing downstream transforms it); no walk, no boolean. **Five rings, six faces** -- bottom cap, chamfer band, outer wall, rim annulus, interior wall, interior floor -- each ring used exactly twice, which is the manifold argument. 23 faces chamfered, 15 not; asserted.

**Interior bounded, floor sharp.** `Sketch::rounded_rect` inside and out: an object is held at its stated size at every height rather than sinking into a fillet, because the rounding is **vertical corners only** and takes nothing off the interior's own box (`the_interior_is_the_box_it_states_with_rounded_corners_inside_it` measures the reach across the faces). **The walls are a constant width, corners included**: `interior_corner_r` is `corner_r - wall`, which puts the two corner arcs on one centre, and `check` refuses any spec whose corner wall is thinner than its runs (it fired on this file's own first fixture: 0.08 mm against 1.2 mm). That is the one thing a Gridfinity bin does not do -- its cavity radius is stated independently of its outline. `buildable_interior_corner` clamps to a quarter of the shorter side (the shape of clamp `buildable_floor_fillet` applies to a bin), which only ever makes a corner thicker. `the_walls_are_one_thickness_all_the_way_round_the_corners` reads the pairing off the built solid's cylinders, not off the arithmetic. Interior seg count is 4 square / 8 rounded, and the face-count assert reads both profiles' lengths rather than hard-coding either. `corner_r` is never below the compartment's own -- a rounded rect only shrinks as its radius grows, so rounding at least as much is what keeps the insert inside that corner.

**The bottom chamfer is what makes the fit snug.** 45 degrees, leg = the compartment's built floor fillet `fr`. The blend leaves the void inset `fr - sqrt(fr^2 - (fr-z)^2)` at height `z`, the chamfer insets `fr - z`, and `fr - z >= that` for every `z <= fr` (`blend_inset` states the first, `a_chamfer_clears_the_blend_of_its_own_radius` sweeps it). So the insert stands `clearance` inside the compartment at every height instead of `clearance + fr` -- 2.5 mm a side on the worked drawer.

Two constructions are load-bearing. **`outer_profile(spec, inset)` produces both rings of the chamfer band**, so they agree segment for segment by construction (a rounded rect inset by `d` is the same box less `2d` with radius `r - d`, straight runs `w - 2r` either way) -- `wall_between` pairs seg *k* with seg *k*, and a count mismatch is a silently twisted band, not a failure. Hence `corner_r - chamfer >= MIN_ARC_R` and `MIN_STRAIGHT_RUN`, both refusals. And **the floor is never thinner than the chamfer is tall**, so the chamfer lives wholly in solid material; without that the outer surface at `0 < z < chamfer` cuts inside the interior wall and the "solid" self-intersects.

`check` refuses (a property of the request, which `optimize` names against the object that asked); everything else asserts. Postconditions are `carve_to_cells`' four -- validate, audit clean, one shell enclosing material, no orphans -- plus the built body standing in exactly the box the spec stated, since this is where an insert is produced and there is no later place to state them.

### `project/` — drawer fitting, in the model layer

Pure logic beside `printers.rs`, no kernel dependency, six modules: `rects` (axis-aligned boxes, their lattice, `union_area`/`parts_connected`/`rect_covered_by`, boundary runs and `merge_segments`), `pack` (`PackSearch`, the bottom-left first fit over four rotations, restarts perturbed by `Mulberry32`), `tidy` (what the search prefers once everything fits), `settle` (what tidies the layout it chose), `walls` (`layout_walls` → `Wall`/`InnerWall`, extended half a thickness at both ends), `drawer` (`drawer_grid`, `packing_area`, `cavity_region`, `MAX_GRID` 40).

**This is the only implementation.** It used to live in `../web/src/lib/project/*.ts` and was ported here verbatim — `mulberry32` bit for bit, the same tie-break on the instance sort — then verified against it: the same input gave byte-identical placements, counts, iterations and walls at both `quick` and `thorough`. The TypeScript optimizer is deleted; `../web/src/lib/project/rects.ts` keeps only the render-time measurements the SVG canvases take, and the web app reaches this one through `gridfinity-wasm`'s `PackSearch`.

**`Rect::right`/`bottom` quantise.** The TS original did not, and `rect_grid`'s "does one part cover this cell" test compares a quantised lattice line against a raw `x + width`: at `x = 28.65, width = 28.2` the sum is an ulp below the line, the cell reads empty, and `union_area` returns **0** for a plain box. That value is the packer's own sort key, so the defect changed which layout came out. Quantising the far edges is what makes a box's right edge and its neighbour's left edge one number. `union_area` now asserts its result lies in `largest_part ..= sum_of_parts`, which is the check that would have caught it.

`PACK_SEED` + `PackEffort::restarts()` is the whole reason one drawer and one object list always give one layout; the budget is an iteration count and never wall-clock, so the result cannot depend on the machine. Tiers are **250 / 2 000 / 10 000** restarts.

### `settle.rs` — what tidies the layout the search chose

Runs after packing, on the claims, and **only `optimize` calls it** -- `gridfinity-wasm` does not, so Project mode's layouts are unmoved. Three passes. Two are per slab per axis: **absorb** every free band no wider than `Settle::absorb` into the claims facing it (half each between two, the whole of it against the cavity wall), and **even** the slack at the slab's two ends, which centres the claims in it. A slab with no band at one end is given an empty one, and evening `0` against the slack at the far end *is* the centring. The third, **grow**, runs last and takes what the bands cannot see.

**`Settle::absorb` is one lever with one meaning: how far a compartment wall may be pushed out into leftover.** Both the band pass and the growth pass are held to it, so a strip of leftover survives exactly where it is wider than the two walls facing it may travel -- 20 mm between two claims at `absorb` 5 gives 5 to each and keeps 10. `0` still disables the whole postprocess.

**Every move is across a free band** -- a column or row of the slab no claim covers any part of -- and that is the correctness argument, not a simplification: a band separates the claims completely, so absorbing, widening or narrowing it is a monotone remap of the band lines and cannot change which claims touch which, nor make two claims overlap. Adjacent free bands are impossible (a line between two comes from a claim edge, whose claim covers one of them), which is what makes "give the width to the neighbouring band" well defined. `settle_slab` runs both operations on x then y and recurses into the (column-block x row-block) sub-slabs, entering each with strictly fewer parts, so it terminates.

Postconditions, asserted in `Relax::check` and per pass: no part **shrinks** (an object that fitted its compartment still does), no two parts of *different* placements overlap (two parts of **one** placement legitimately do -- each is a box of one object grown by the claim margin, and adjacent boxes overlap by twice it, which is why `owner` is carried), every part lies in the cavity, and the band widths still sum to the slab's own extent. A pass whose result would leave the cavity is **dropped whole**, which is how an L-shaped bin is settled without carrying a non-rectangular slab through the recursion; `drawer::cavity_region` states that cavity as each cell's square drawn back by the inset on every side with no neighbour, and `packing_area` is its rectangular case (`a_rectangle_of_cells_is_the_packing_area`).

**The band argument is strong, and most layouts do not qualify for it.** A free band needs a whole row or column of the slab that no claim touches, and a proper two-dimensional packing has none: bin 1 of `examples/ikea-alex-drawer-1.toml` holds four objects such that **every** row and column is covered, so `settle_slab` correctly reports 0 absorbed while 32 mm of air sits beside the swiss army knife. `Relax::grow` is the third pass for exactly that -- each claim pushed out on each of its four `Face`s into the space directly in front of it, one pass in part order then `FACES` order so where two claims want the same ground the earlier takes it.

Its safety argument is **direct rather than structural**: not that the move cannot change which claims touch which, but that the ground taken is ground the cavity covers and no *other placement's* claim stands on, checked on the grown rectangle itself before it is kept. So the three properties `check` states hold move by move. Two parts of **one** placement may overlap and do by construction, which is why `owner` is consulted and not the part index -- and why `tidy::grouping` had to start measuring an object's coverage with `union_area` instead of summing part areas, its assertion having fired on the first L-shaped object whose parts grew into each other.

`grow_face` picks its distance from the **finite set of distances at which anything changes** -- every cavity rectangle's far edge, every foreign claim's near edge, and the cap -- longest first, so the wall lands exactly on whatever stops it rather than on a bisection's guess. One pass suffices and the code says so: a claim only ever grows, so what blocks a face is never afterwards out of the way.

**What none of the three can reach** is leftover facing no wall squarely -- a pocket of air that is neither a band nor in front of any single face. Growing a claim into a non-rectangular region would need the claim to stop being a rectangle.

**`clamp` is the fourth pass and it undoes part of the other three on purpose.** Growth is right for almost everything and wrong for an object that has to be held *still*: a battery in a compartment 30 mm wider than itself lies over at an angle. An object states `max_size` and its claim is pulled back to it afterwards, about its own centre, every part clipped to the one window so a multi-box object stays the one compartment it was packed as. The space given back becomes material like any other leftover. Nothing grows, nothing leaves the cavity, no two claims can newly overlap -- so `settle`'s properties survive without `clamp` needing to know about them. `Extents` is `[Option<f64>; 2]` in the **drawer's** frame and the limits are the *claim's* (`max_size + 2 * margin`), because the caller holds a `Placement` that has already been turned: `optimize::claim_extents` is where the quarter turn swaps the two, the axis a battery must not roll along being the battery's and not the drawer's.

`optimize::settle_within` is the one path both planners settle through, so neither can settle without clamping. Measured on `examples/ikea-alex-drawer-1.toml --mode hybrid`: the AAA batteries' compartment had grown to 45.9 mm and comes back to the 45.0 mm the file states, everything else unmoved.

`optimize` calls it **after** `footprint_cells`, never before: settling first would let a grown claim reach a cell that was about to be dropped, costing an L-shaped object its L-shaped bin. It then re-derives `PackResult::walls` and `tidiness` from the settled placements -- the one place the rule against re-deriving `tidiness` does not hold, the search's own reading being of a layout that was not built -- and the counts reach the report's Compartments section through `Run::{absorbed, evened}`. `settings.tidy_absorb` is `Settle::absorb`, defaulting to half the run's own pitch.

Measured, as absorbed / grown / evened and the share of the bins the compartments come to: `examples/ikea-alex-drawer-1.toml --mode hybrid` **16 / 3 / 8, 94.8%** (was 16 / -- / 8 and 92.5% before the growth pass -- the three walls are the knife's `+x`, the caliper box's `+y` and the ethernet cable's `+x`, and bin 1 tiles its cavity exactly afterwards); `--mode walls` **4 / 6 / 2, 95.7%**; `examples/drawer.toml --mode auto` **12 / 10 / 6, 93.8%**, where the cap is the default half-pitch 21 mm rather than that file's stated 100. `layout_walls_reporting`'s overhang assertion had to start quantising its bound -- a claim settled hard against the packing area's edge puts a divider endpoint at `right + half`, an ulp past the raw sum.

### `tidy.rs` — what the search prefers once everything fits

`Tidiness` is a finished layout read six ways, every field a fraction of its own worst case with 0 the tidiest; `score` is their weighted sum. `lines`/`runs` come from `merge_segments` over each claim's `boundary_segments` with the runs on the packing-area edge dropped — the same derivation `walls.rs` makes, so **the thing measured is the divider set the viewer sees**. `fragments`/`slivers` come from one lattice of the claim edges clipped to the area, filled per claim over its own cell span (not per cell over every claim) and flood-filled over the *uncovered* cells; a cell counts as sliver when its own width or depth is below the narrowest claim placed, which is exact because the lattice lines are the claim edges. `grouping` is per object id, bounding box less area covered, the coverage a **`union_area`**: two claims of two placements never overlap (`pack_once` asserts it) but the two parts of *one* placement do by construction, and `settle`'s growth pass widens that overlap, so a sum double-counts the shared ground and scores a plain L as though its instances were spread apart. `balance` is the area centroid against the area's centre over half its diagonal. Weights `W_LINES` 1.0 · `W_RUNS` 0.5 · `W_FRAGMENTS` 0.75 · `W_SLIVERS` 1.0 · `W_GROUPING` 0.5 · `W_BALANCE` **0.1** — balance last on purpose, because gathering the leftover into one block *means* crowding one end, so the two pull against each other and balance must only break ties.

**`better` compares placements, claim area, score, spread.** The first two are absolute: a prettier layout can never cost a placed object. On a drawer everything fits in, the first two tie at every restart and the third is what the budget buys.

**The area key must be compared quantised**, and was not. A pass accumulates area as it places, so two passes placing the same claims in a different order differ in the last bit — measured 121146.20680000001 against ...003 on the ikea drawer — and an exact `!=` hands the whole comparison to that noise: the area key fires on a tie it should pass over and every key after it is unreachable. It cost that drawer its tidiest layout at restart 1431, which is how it was found. Harmless before only because the key after it was `spread`. `a_longer_search_is_never_beaten_by_a_shorter_one` is the guard, stated as `better` rather than as a falling score because a restart that places one more instance legitimately takes a worse-looking layout.

**Permuting the instance order is not a wide enough neighbourhood.** A first fit takes the earliest position, so order alone reaches only bottom-left-greedy layouts and `examples/drawer.toml` exhausted them inside **250** restarts — 10 000 found nothing 250 had not. Two more dimensions: `Scan::{Rows, Columns}` (the sweep's grain; no permutation turns one into the other, and the greedy first pass stays `Rows`), and `Jitter`, a per-instance count of leading bands to decline, drawn from a generator seeded from the **restart index alone** so a pass is a function of its index and nothing before it. `skip` restricts the candidate set rather than changing what is chosen from it, which is what keeps the cross-rotation pruning against `best` sound.

**Measured.** `examples/ikea-alex-drawer-1.toml`: 16 dividers before, **14** after, score 0.806 → 0.784 across the tiers, pack 0.15 s at `thorough`. `examples/drawer.toml` (26 instances, 84% claimed): 670 of 10 000 restarts place all 26, and their scores run **min 0.932, p05 1.284, median 1.392, max 1.574** — the objective discriminates strongly, and the winner was found at restart 2, so the extra budget buys the tail rather than the median. Pack time there is 3.0 s at `thorough`, 0.6 s at `standard`. A drawer that tight has essentially one packing; do not read a flat score across tiers as the search failing.

**The fitter states the cavity; it does not divide it.** `drawer_pockets` turns each placement's part rectangles into `Pocket`s (claim inset by `divider_thickness / 2`) and `drawer_params` carries them on the `LogicalBin` with `inner_walls` **empty**. Leftover packing area is material; two compartments are separated by the material their pockets leave. `layout_walls_reporting` still runs, for the report's count alone. Gates: `the_space_no_object_was_packed_into_is_solid` sweeps a 61 × 61 grid of the packing area and asserts no point outside every claim stands on a compartment floor of the finished B-rep (asserting first that it found such points, so a full drawer cannot pass it vacuously), and `every_packed_object_fits_the_compartment_floor_the_model_built` now asserts floor count **equals** placement count rather than merely exceeding it.

**`PackInput::margin` reserves the floor fillet, not just the clearance and the half divider.** An object *rests on the floor*, and a concave blend of radius `r` between a compartment's wall and its floor takes `r` of floor from every wall — so a compartment is its stated size at mid height and `r` smaller all round where the object sits. At the worked example's `fillet_radius` 2.5 against `clearance` 0.5 every object sank **1.98 mm into the blend on all four sides**, and the packing was self-consistent the whole time: nothing that re-derived the compartment from the same margin could see it. It subsumes the corner rounding too — a compartment corner of radius `rc` bulges in by `rc(1 − 1/√2)` ≈ `0.3·rc`, and `buildable_floor_fillet` never returns more than `rc − FILLET_CORNER_HEADROOM`. `optimize` passes `Spec::built_floor_fillet()`, which is `buildable_floor_fillet` asked exactly as `plan_cavities` will ask it, so the reservation is what the model builds and not what was requested. **Costly and deliberately so**: 2.5 mm of reservation is 5 mm off every compartment dimension, and the `optimize` fixture went from four 34 mm blocks in an 84 mm drawer to four 30 mm ones. `floor_fillet` is `serde(default)` 0.0, so the web app's `PackSearch` claims exactly what it always did — **Project mode is still unreserved**, and wiring it changes packed layouts, which is a user-visible call.

**`every_packed_object_fits_the_compartment_floor_the_model_built` is the gate, and it is deliberately not a restatement of the margin.** It reads the compartment floors off the *finished* solid — planar faces with a vertical normal at `BASE_TOTAL_HEIGHT + FLOOR_THICKNESS`, which is the one height nothing else in the model sits at, the same identification `floor_fillet_coverage` makes — and asks whether each object's four corners land inside one. That is the floor the blend has already trimmed, so a reservation that is too small fails there while the packing still agrees with itself. Verified to fail: with the packer's `floor_fillet` forced to 0 it reports `the object corner [2.55, 2.55] stands on no compartment floor`.

## Engine architecture

Pipeline: **`sketch` → `build` (features) → `topo` (B-rep solid) → `fillet` → `tess` → `mesh` → STL**, or the same B-rep straight out as Parasolid XT via **`xt`** — no tessellation on that path. Paths under `gridfinity-brep/src/` unless noted.

### The kernel models in f64

**`Vec2`/`Vec3` are `glam`'s `DVec2`/`DVec3`, and every coordinate, parameter and tolerance in `gridfinity-brep` and `gridfinity-model` is `f64`.** Four functions narrow to `f32`, all of them at the very end and all of them because their consumer is: `Mesh::flat_vertices`, `Mesh::to_stl_binary` (binary STL is `f32` by spec), `Tessellation::render_buffer` and `welded_render_buffer` (wgpu vertex buffers). Nothing upstream of those is `f32`.

**What it bought, precisely: the drawer's blend-chain kink.** The refusal was `edges 3832 and 3835 put the ball centre at vertex 2180 4.236e-2 mm apart`, a **1.0114°** turn where the two edges should be tangent. The configuration is a **tangency**: a divider's rounded end cap (circle centre `(80.85, 175.25)`, r 0.6) meets the neighbouring divider's face at `x = 80.85 + 0.6 = 81.45` in exactly one point. A tangency is where a line/circle solve **square-root-amplifies** representation error -- the crossings sit at `±sqrt(2·r·δ)` for `δ` the miss -- so `δ` of 9.35e-5 mm, about **12 f32 ulps at 81 mm**, came out as 0.0106 mm of offset and 1.01° of turn, two orders past the 0.5° `MAX_JOIN_KINK` allows. At f64 the same 12 ulps is 1.7e-13 mm and the turn is 4e-5°. Retired: the drawer landed **259 of 283** floor fillets where it had landed 175 of 204, and its first refusal became a different class entirely — the two-shared-face refusal above, since fixed, so it now lands all 283.

**What it did not buy: the fuzz backlog, which is structural.** `fuzz_inner_walls` 21/150 → **20/150**, `fuzz_params_broad` 7/400 → **8/400**. The largest classes are missing B-rep operators -- the ramp running out into a needle, runout onto a cylinder, three blended edges at a vertex -- and no precision reaches them. Do not expect a precision change to move a count that names a missing capability.

**The tolerances that only ever absorbed `f32` noise came down with it**, and the lib gate and all eight profiles were byte-identical across the change -- which is the evidence that they were allowance rather than judgement. `END_AGREE` 1e-4 → 1e-9 and `ON_EDGE` 1e-3 → 1e-8 (two derivations of one point, now bounded near the 1.4e-14 an `f64` ulp is at 100 mm); `EXTREME_TIE_MM` 1e-3 → 1e-9; `SAME_PLANE_DIST` 1e-4 → 1e-9 and `SAME_PLANE_SIN` 1e-5 → 1e-10; `PERP_TOL` 1e-4 → 1e-9; `audit`'s `GEO_TOL` 1e-3 → 1e-6.

**Two were deliberately left alone, and the reason is the rule.** `isect::TOL` (1e-5) separates a genuine tangency or parallel from a near one -- a statement about the *model's* scale, not the arithmetic's -- and `xt::validate::ON_GEOMETRY_M` is `res_linear` itself, because what it asks is whether a **reader** would accept the file and a tolerance the validator picks for itself is a number the reader has never heard of. Tighten a tolerance when it was standing in for the precision; leave it when it is standing for a feature size or someone else's contract. `SLIVER`/`COINCIDENT`, `BOX_TOL` and `weld_key`'s quantum are the same kind and are untouched.

**It cost one profile.** `fuzz_wall_openings` went green → **2/150**, one class: a 0.175 mm sliver edge at a reentrant corner left unpaired (`edge 416 used fwd=1 bwd=0`, from `(84.152, 42.0)` to `(84.066, 42.152)`). Not a tolerance -- 0.175 mm is far above `SLIVER` in either precision -- but a configuration the f32 geometry happened not to produce. Undiagnosed.

**Cost in time:** a fitted drawer builds in 0.67 s against 0.40 s and exports its STLs in 1.05 s against 0.83 s. `Tri` doubled to 144 bytes and the profile's note that tessellation is memory-bound is why that shows up in export more than anywhere else.

**`Dir` collapsed to a single vector.** It used to hold `exact: [f64; 3]` beside `approx: Vec3` because the kernel modelled in `f32` and a direction was the one quantity that could not afford to: an `f32` unit vector is unit only to about 6.7e-8 once widened, six times the `res_linear` of 1e-8 a transmit file declares, and Onshape faulted every peg chamfer on it. With the kernel in `f64` the two views are the same number, so `Dir` is a newtype over `Vec3`, `components()` reads it out for the writer, and `dot_exact`/`cross_exact` -- named apart precisely *because* the two precisions differed -- are gone; `Deref`'s own `dot` is the same arithmetic, and `cross_dir` is the one that returns a `Dir`. `Dir::new` still normalises and asserts against `UNIT_RESIDUE`, because a direction being unit is a property worth establishing once wherever the value is made, independent of precision.

**The wasm boundary widened too**, and that removed a conversion rather than adding one: a JavaScript number *is* an IEEE double, so `gridfinity-wasm`'s `f32` parameters were narrowing one on the way in. Its vertex buffers stay `f32` (they are `Float32Array` views and wgpu uploads). Same for the packer: `project/` was always `f64`, so `Wall::to_inner_wall` and `optimize`'s `drawer_params` no longer cast at all.

**`gridfinity-app` is the one crate that stays mixed**, because egui screen space is `f32` and the kernel is `f64`. `main.rs` imports `glam::Vec3` (every use of it there is render-side), `wireframe.rs` imports the kernel's and narrows where points reach the line buffer, and `editor.rs` narrows an `InnerWall`'s millimetres where they reach the painter. `render_point` is the one named crossing.

### `geom.rs`### `geom.rs`

Analytic `Surface` (`Plane`/`Cylinder`/`Cone`/`Torus`/`Sphere`) and `Curve` (`Line`/`Circle`/`Ellipse`/`TorusSection`). `TorusSection` = torus cut by a plane **parallel to its axis** — implicitly a quartic, which is why a plane split through a floor-fillet corner blend used to be inexpressible. Not solved numerically: fixing minor angle `t` fixes ring radius `major + minor·cos t`, hence `cos u = offset / rad`, so the section parameterises exactly in `t` with `branch = ±1` picking the half. `torus_section_exists` reports where `|offset| <= rad` bounds the domain; outside it the section does not exist and the caller must not sample.

Every radial surface and `Circle` carries an explicit `axis` (arbitrary direction); `*_z` convenience constructors (`cylinder_z`, `cone_z`, `torus_z`, `Curve::circle_z`) cover the common +Z case. All closed-form. Each surface has `point`/`normal`/`project(uv)`; partial surfaces set `ref_dir` to their arc start so `project` angles stay wrap-free. `u` enters a rotational surface only as `cos u · d0 + sin u · d1`, so `Prepared` exposes that `radial` plus `point_at`/`normal_at` taking it pre-computed — `point`/`normal` are thin wrappers over those, keeping the two forms from drifting. `normal_ignores_v` says when a whole grid column shares one normal; every surface but torus and sphere qualifies now, a cone being one nappe.

**The surface set *is* Parasolid's surface set, in Parasolid's own terms.** Not a coincidence and not for the writer's convenience — it is what lets `xt/surf` be a transcription with no second copy of the geometry (see `xt/`). Three restatements got it there:

- **A cone is one nappe.** `Cone { pvec, axis, radius, half_angle, ref_dir }`, `axis` pointing *at* the apex as a CONE node carries it, `radius` positive at `pvec`. Was a double cone about an apex, which left the face to say which half it was on — and nothing did, so the writer sampled the face's points and refused one reaching the apex. `cone_apex`/`cone_open` derive what the kernel's own arithmetic wants; nothing stores the apex twice. `build::cone_or_cylinder` names the face at its wider end, where the radius is positive, so a downward-widening cone takes `open` = -Z rather than sitting at negative `v`.
- **A torus's major radius is signed, and the sign names the spindle sheet.** A spindle (`minor_r > major_r`, every corner blend) meets itself on the axis and has two sheets; negative major turns the inner one into the node's own outer one. `torus_through(.., on)` reads the sheet off a point of the face where the blend is solved and asserts the point lies on the sheet it chose — the model does build inner-sheet faces, which is how `runout_torus`'s spine assertion caught the sign. `signed_distance` no longer picks the nearer of two branches; the sheet is stated. **Anything comparing a distance-from-axis against `major_r` must take `.abs()`** — the magnitude is the spine's radius, the sign is only the sheet.
- **An ellipse is a principal pair.** `Ellipse { center, axis, x_axis, major, minor }`, longer axis first. `ellipse_from_conjugate(centre, a, b, t0, t1)` does the rotation once, at the one producer of a conjugate pair (`fillet/section::runout_cyl`, a plane slicing a blend cylinder), and **returns the parameter range with the curve** — the rotation shifts every parameter by the same angle, so handing back the curve alone moves both ends of the caller's arc. It asserts exactly that neither end moved. `conjugate_axes()` is the inverse view, for the callers that state a question as `a cos t + b sin t`.

`Edge::runs_with_curve` (`t1 > t0`) is the bit a consumer carrying no parameter range of its own needs beside the curve.

**Both of a torus's parameters are angles**, and `tessellate` unwrapped only `u` for years — a blend patch crossing the `v` seam reached the triangulator as a torn polygon. `dist_to_surface` had the matching bug the other way: it duplicated the ring-torus distance formula, whose `perp` is unsigned, so on a **spindle** torus (`major_r < minor_r`, every corner blend) a point with a negative radial coefficient measured exactly `2·major_r` off a surface it sat on. `Surface::signed_distance` takes the nearer of the two radial branches for spindles now, and the auditor delegates to it instead of keeping a copy.

### `topo.rs`

The B-rep: `Vertex`/`Edge`/`Loop`/`Face`/`Solid`. **Not** half-edge with next/prev — loops are explicit ordered `(EdgeId, forward)` lists, edges shared. Storage is **flat CSR, not nested `Vec`s**: one `loop_edges` arena + a `loops` offset table; a `Face` is `{ surface, sense, loop0, n_loops }` naming a contiguous loop range (outer first). `Loop` survives only as a *transient* input to `Builder::face`; read loops off the solid via `outer_edges`/`face_loops`/`inner_loops`/`n_inners`. Cloning a `Solid` (which `fillet_edges` does repeatedly) is a few flat `memcpy`s.

**`shells()` and `fins()` are views, computed on demand, not stored.** `Shell { faces, encloses_material }` walks the face adjacency graph (connected components over shared used edges) and reads the material side at the shell's furthest point along +x, where an outward normal cannot point back along -x if the shell encloses its material. `Fin` is one directed edge use — loop ring neighbours, edge partner, and the chain of uses meeting at a vertex — which is what Parasolid stores as topology and the kernel derives. **Loop storage is unchanged and stays unchanged**: ordered `(EdgeId, forward)` lists in flat CSR, not linked half-edges. Both are recomputed rather than cached because they would otherwise have to survive `resume`, `copy_face`, `compact_edges` and `reverse_loop` without going stale, and an export pays for them once.


`Builder` interns vertices and edges (edge key = sorted endpoints **+ welded midpoint**, so a circle's two semicircle arcs don't collapse into one edge). Both lookups are **exact bucket first, then the 26 neighbours within `WELD_NEAR`**. The exact bucket must win unconditionally: a point may sit most of a bucket diagonal from its bucket's representative, so distance-testing the exact hit splits vertices the old lookup shared. The neighbour scan catches the opposite failure — two solves of one corner landing 4e-6 mm apart on either side of a bucket boundary, interning as two vertices and leaving the solid non-manifold at an edge nothing paired with.

`Solid::validate()` enforces the manifold invariant: **every edge used exactly twice, once in each direction**. `Builder::build` asserts it itself via `validate_ignoring_unused_edges` — the interning arena can outlive edges no face kept and only `compact_edges` drops them, so orphans are the one tolerated deviation. Three callers legitimately build something not yet a closed manifold and say so by name: `fillet_edges` and `chamfer_edges` build a candidate speculatively and reject it on failed `validate` (`build_compact_unvalidated` / `build_unvalidated`), and `program::run_all` emits partial open shells for the step-through debugger. Everything else goes through `build`, so a construction bug panics at the builder that caused it instead of surfacing as a leak far downstream.

Alternation is not the whole story — it holds just as well for a consistently-inverted shell — so `Builder::build` additionally establishes the **orientation invariant** via `orient::normalize`. Loop directions off a built `Solid` are therefore material-consistent and may be relied on; the modules that emit loops (`slab`, `region2d`, `build`) still author in their own conventions and are re-wound at `build`.

**A resumed builder strands vertices as well as edges, and `build_compact_unvalidated` drops both.** `resume` carries the whole vertex and edge arena forward on purpose -- ids resolved before a rebuild, which is how blends are selected, must survive it -- so a local rewrite leaves behind the edges it replaced *and* the vertices those edges were the last to name. `compact_edges` had always dropped the first; `compact_vertices` now drops the second, in the same place and only there, so plain `build` still compacts nothing. `orphan_vertices()` / `orphan_edges()` name them. Measured before the fix: **8 orphan vertices on a 1x1 bin, 16 on a 2x2, 20 on a 3x2**, and a prefix scan of the program puts **every one of them at one op -- `floor fillet`**, every earlier prefix clean. Two producers inside it: the cavity corner arc's old tangent points at the floor (`(1.45, 4.0)` and `(4.0, 1.45)` about a corner centre at `(4.0, 4.0)`, z 8.2), which the blend retreats past, and at the rim the junctions `fuse_collinear_edges` dissolved -- the case the `Builder::resume` note above already records from the other side. `a_built_bin_carries_no_vertex_or_edge_that_nothing_names` is the guard.

`Solid::validate()` is the cheap topology check; `audit` is the heavy *geometric* soundness checker, also confirming each edge's curve lands on its vertices and lies on every face surface referencing it. **Mesh leaks but `validate` passes → run `audit` first**: it pins the failure to a specific edge/face if the B-rep is at fault and rules the B-rep out otherwise (pointing at the tessellator).

**Local rewrites:** `Builder::resume(solid, seed)` continues on top of an existing solid's vertex/edge arenas, keeping every id valid, and interns *only* the faces flagged in `seed`. Everything else is re-filed by `copy_face`, which copies a face's loop spans verbatim — what makes a blend cost its own neighbourhood instead of the whole model. Interning the whole solid in `resume` would cost exactly what rebuilding it did. Two load-bearing gotchas: `resume` must re-derive each edge's index key **the way the constructor that made it did** — `line` averages the two vertex positions, and evaluating the curve at mid-parameter is the same point in exact arithmetic but can land one weld quantum away in f32, silently duplicating the edge and showing up as `edge N used fwd=1 bwd=0`. And a resumed builder strands the edges it replaced, so it must finish through `build_compact`, not `build`. **Plain `build` must never compact:** callers pick blend and chamfer edges by id *before* building, and renumbering would silently repoint those selections.

### `sketch.rs`

2D profiles as closed loops of `Line`/`Arc` segments (`rectangle`, `rounded_rect`, `circle`). Corner radii are real arcs. Outer loops CCW.

**A 2D loop given as *points* is `&[Vec2]`, and `sketch.rs` owns what you ask of one.** `polygon_area` (shoelace, positive CCW) and `point_in_polygon` (even-odd, +x ray) sit beside the seg-based `loop_area` and `point_in_segs` they mirror. Three copies of each before: `rectregion::TracedLoop::{signed_area, contains}`, the deleted `region.rs`'s `poly_area`, and `split.rs`'s own `polygon_area`/`point_inside` plus the loop open-coded inside `Prism::contains`.

`split.rs` carried its 2D loops as `Vec<(f32, f32)>`, which is why it could not call anyone: the tuple is a genuine uv *pair* where `Surface::project` returns one, but in `Prism`, `unwrap_u`, `loop_encloses` and `emit_trimmed_faces` it is a plain 2D point. `Cut::prism` takes `&[Vec<Vec2>]` now, and the payoff is at the caller — `gridfinity/pieces.rs` was unpacking `TracedLoop::pts`, already a `Vec<Vec2>`, into tuples for no reason but that signature. `Prism::contains` also states what it relies on that the open-coded version left implicit: parity is taken over **all** the loops together, so a point inside an outer *and* inside one of its holes crosses evenly and is correctly outside.

### `build.rs`

Features. Three primitives write into a shared `Builder`: `ring` (profile at a height), `wall_between` (side faces between two rings), `cap`/`loop_of` (planar caps). `extrude`/`prism`/`loft` wrap them. **Orientation convention:** author loops CCW; an `outward` flag says whether material is inside the loop (`true`) or it is a hole/cavity (`false`). `loft` turns arcs whose radius changes with height into `Cone` faces; a straight segment on a loft becomes a *slanted* `Plane`, its normal computed from the actual 3D quad, not assumed vertical.

**An arc lifted onto a tilted plane is an ellipse, and `ring_on_plane` built a circle.** Its axes are the arc's radius along x and y, each carrying the plane's gradient in that direction — `a = (r, 0, r·gx)`, `b = (0, r, r·gy)` for `g = (−n.x/n.z, −n.y/n.z)` — so `point(t)` at the arc's *own* angle lands on both the cylinder over the arc and the plane, and the parameter range carries over untouched. A Z-axis circle at the centre's height puts the whole arc at one z, and its ends then miss the vertices the ring already placed by the ramp's rise across the arc: `EdgeVertexGeometry`, 0.594 mm on a 9° ramp. That single defect is why every rounded feature of a sloped bin had to be squared, and why an opened sloped bin dropped its slope altogether. The assertion states the fix rather than the code: each end of the emitted ellipse is checked against the vertex the ring put there.

### Nine files, one phase each; `fillet_edges_with` is the sequence and nothing else. `chain` — request → chains, terminating vertices, `salvage`. `corner` — rolling-ball solve + `reconcile_shared_ends`. `blend` — `Fillet`, cyl/torus surfaces, `connect_arc`, `circle_span`, and the per-corner build that runs each end out. `runout` — `RunoutEnd`/`Runout`, the Absorb→Cap→Flat ladder, `absorb_fits`. `section` — `runout_on`/`_cyl`/`_torus`, `respan`. `rebuild` — loop rewrite, blend faces, caps, `move_vertex`. `query` — `as_cyl`, `coplanar`, `across_at`, `dist_to_curve`. `mod` — the three public items and the three shared tolerances (`END_AGREE`, `ON_EDGE`, `MAX_JOIN_KINK`). `feasible` — what a blend can be *asked* for, decided in 2D before any of it is built: `max_inward_radius`, `island_clears`, `blendable_segs`, `blend_radius_along`, `MIN_TORUS_MAJOR`. `fillet_edges` reports a refusal only after trying to build the surface, by which point the message names a face rather than the impossible request; these answer the same questions from the profile the caller is about to extrude, as upper bounds erring towards allowing it.

`CurvEdge`, `as_plane`, `loop_edge_dir`, `emit_curv` moved to **`kernel/curvedge.rs`**; `chamfer.rs` carried byte-identical copies and uses them now.

**`emit_edge` is the one place that knows which `Builder` constructor each `Curve` variant is built by**, in `curvedge.rs` beside `emit_curv`. Moved there from `split.rs`, which had the only named copy; `fillet/rebuild.rs` and `chamfer.rs` open-coded the same four-arm match inside their `rebuild_loop`s, and `emit_curv` repeated it **four times** — once per arm — because it re-decided `(t0, t1)` in each. `emit_curv` is now the endpoint bookkeeping plus one `emit_edge` call, 45 lines to 6. Adding a fifth `Curve` variant is a one-file change. Evaluating `emit_curv`'s `forward` eagerly rather than in a closure is free: `Builder::line` ignores the range, which is the only arm that skipped it.

Split was behaviour-preserving by construction and verified as such: lib gate 212/212, and `fuzz_inner_walls` 23/150 · `fuzz_wall_openings` green · `fuzz_stripped_polyominoes` 15/150 · `fuzz_openings_and_inner_walls` 6/150, i.e. the table above unmoved in both directions. Hold any future move to that bar — a count that improves is as much a signal that the move was not a move as one that worsens.

`fillet_edges(&solid, &[(EdgeId, r)])` — true rolling-ball edge blending as a B-rep operator. Plane/plane edges → `Cylinder` blends; plane/coaxial-cylinder circle edges → `Torus` blends. Adjacent faces trimmed back to exact tangent curves, quarter-circle connect arcs join neighbouring blends. A vertex with **two** blended edges continues the chain; **one** is a *runout* — chain terminates against a third face and the blend is trimmed by it: tangent curves extend to meet the plane and the exact section of the blend surface by that plane becomes the trim curve, spliced into the runout face's loop where its sharp corner was. Section is `Curve::Ellipse` for a cylindrical blend, `Curve::TorusSection` for a torus blend against a plane parallel to its axis. Runout face found by adjacency, skipping faces coplanar with the blended pair (a coplanar neighbour continues the surface rather than terminating the blend); where no face can take the curve the blend is closed flat. **Three or more blended edges at a vertex** needs a spherical corner patch → `Err`. The partial-height inner wall's top ramp is built this way.

Rebuild is **local**: an edge changes if blended or if either endpoint moves, a face changes if it names such an edge, everything else re-filed verbatim through `Builder::resume`/`copy_face`. Sound because an edge's endpoints are the same from either side, so the two faces sharing a changed edge always agree that they changed. Matters because a blend touches almost nothing: a floor fillet on a 370-cell bin moves **219 of 9889 faces**, and rebuilding all of them was ~90% of `fillet_edges`. Result still goes through full `validate()` — the manifold gate is not narrowed to the neighbourhood, only the *work* is. Gotcha: re-emitting an arc reversed must swap the angle range too — `Builder::arc` trusts that its first vertex sits at the first angle.

`fillet_edges` is all-or-nothing; `fillet_best_effort` wraps it for callers preferring an ugly fillet to none: groups edges into connected chains, adds them one at a time while the result still blends, bisects a failing chain (depth 3) to salvage contiguous runs — a dropped run just leaves runouts, ordinary geometry. Returns the edges left sharp, and **errs only when the input is at fault** (a blended edge missing or not shared by exactly two faces means the solid was already non-manifold, and degrading there would swap a loud error for a silently broken part). `program::run` applies blends through it, which is what lets a compartment-splitting divider keep the fillet on the corners that *do* close.

**How far along an edge a blend reaches belongs to the edge, not to the face asking.** Both faces sharing an edge rebuild independently and the results must weld; disagreement interns two edges and the solid opens along the seam, surfacing far away as `edge N used fwd=1 bwd=0`. `move_vertex` decided it by distance to the *asking face's* surface — a partial-height inner wall meeting the perimeter puts **both** tangent points on the wall's side plane, so that face's test is a tie while the cavity-wall face across the same edge sees only `ta` on itself and picks it. Measures against the edge's own supporting curve now (`dist_to_curve`, closed form for `Line` and `Circle`), which both faces compute identically because the curve belongs to neither.

The assertion is the real deliverable, not the fix: `rebuild_loop` records every edge's terminal point keyed by `(edge, vertex)` and fails naming the two faces that differ. The quantity must be the point where the edge *stops being wall and becomes blend*, because a face reaches it two ways — one retreats its endpoint there, the other keeps the corner and splits the edge there — and comparing raw endpoints calls that legitimate pair a defect. Fires nowhere across all eight profiles now.

### `xt/` — Parasolid transmit writer, reader and validator

Analytic B-rep out as a `.x_t` text file (schema `SCH_1200000_12006`, manual at repo root): the format every major CAD system imports, carrying exactly what the kernel holds — exact planes/cylinders/cones/spheres/tori, exact lines/circles/ellipses. `to_xt_text(&[&Solid])` is the whole public surface, re-exported at the crate root and called by `gridfinity-wasm`'s `export_parasolid` (same `build_bin_solid`/`carve_to_cells` pairing as `generate_geometry`, zero tessellation). Six files. Writing: `text` — index allocation, field encoding, record splitting, unit crossing; `surf` — `Surface`/`Curve` written as their nodes, a transcription; `isect` — `Curve::TorusSection` → INTERSECTION + CHART + two LIMITs, the one kernel curve with no analytic node; `topo` — one `Solid` → BODY/REGION/SHELL/FACE/LOOP/FIN/EDGE/VERTEX/POINT. Reading back: `reader` — the text → a node graph, schema-driven and character-level, with a lossless `render()`; `validate` — `validate_xt(&str) -> Vec<Finding>`, every way a file is not a transmit file of this schema.

**The writer transcribes; it does not translate.** This is the design rule the `xt/` files are held to, and every departure from it has been closed by changing the *kernel* rather than by adding cleverness here. A kernel `Surface` carries field for field what a PLANE/CYLINDER/CONE/SPHERE/TORUS node carries and a `Curve` what a LINE/CIRCLE/ELLIPSE carries (see `geom.rs`), so `write_surface` takes a `&Surface` and writes its fields in schema order. There is **no `XtSurface`** — the shadow type that used to hold the translation, and with it a second copy of every implicit form and every `dP/du × dP/dv`, which had to be kept in step with `geom.rs` by hand. `distance` is `Surface::signed_distance`; the natural normal is `gradient`, negated for exactly one variant.

**Only a cone's natural normal opposes the kernel's gradient**, and `natural_normal_opposes_gradient` says so in one `matches!`. The format's natural normal is `dP/du × dP/dv`; for a cone that is `-(cos·radial + sin·axis)` against the kernel's `cos·radial - sin·open`, and `axis = -open`, so they are exact negatives at every point of every cone. It is a property of the *variant*, not of the face, so the per-face surface sense is no longer sampled out of the face's own points — the old dot product survives only as the assertion that the variant's answer and the geometry's agree.

**What the writer still owns is the file, and only the file:** index allocation, field encoding, record splitting, the mm→m crossing, the chain and ring plumbing, the double-writing of each shell into its solid region and the void region, and the four refusals. What it no longer owns: which nappe of a cone a face is on, which sheet of a spindle, an ellipse's principal axes, which faces form a shell and which side their material is on, the fins, and whether an edge runs with its curve. Those are properties of the B-rep and live in `geom.rs` and `topo.rs`. Measured: the four writing files went **2222 → 1755 lines**, `surf.rs` alone 687 → 400.

`face_points`, `Solid::shells` and `Solid::fins` are the kernel-side names the writer reads; `check_surface` is what is left of `of_surface`, which now only asserts the format's positive-radius requirement and that the face's own points lie on it.

**Metres, converted in exactly one place.** Transmit files carry no units; every Parasolid application reads them as metres (`res_size` 1000, `res_linear` 1e-8). `text::Writer::dist`/`pos` divide by `MM_PER_M`; `real`/`dir` do not — ratios and directions carry no length. Measured f32 deviation of kernel points from the emitted analytic forms: **3.1e-9 m** surface, 2.4e-9 m curve, on `rect(1,1)` — *inside* the declared 1e-8 m, so no tolerant-vertex machinery is needed; if a real reader ever rejects on tolerance, the spec-blessed fix is TRIMMED_CURVE edge curves, a follow-up.

**A solid body's boundary appears twice.** One REGION per connected shell (material inside) plus one infinite void REGION; each shell is written twice — into its solid region with faces as back-faces, into the void region with the same faces as front-faces. That is what FACE.shell/front_shell and SHELL.face/front_face are for. `encloses_material` decides which way a shell faces by reading the outward normal at the shell's +x extreme: positive → material inside, negative → the shell bounds a void (refused — needs containment analysis). Its tie tolerance is `EXTREME_TIE_MM = 1e-3`: an `f32` ulp at 42 mm is 3.8e-6, and the first version's `1e-6` epsilon rounded away entirely, so every sample at the extreme compared `x > x` and a split L read as a void.

**Edge curves carry no parameter range** — the two vertices bound them, and the curve node's `sense` says whether the edge runs with the curve's own parameter. A `TorusSection` edge becomes INTERSECTION: the two meeting faces' surfaces, a chart of `curve.point` samples ordered along the natural tangent (cross product of the *sensed* surface normals), and an `'L'` limit at each end. `base_parameter` 0 / `base_scale` 1; the C1 chordal parameterisation is the reader's to recompute — only pvecs are transmitted. Both referenced surfaces need GEOMETRIC_OWNER ring nodes back to the intersection, doubly-linked per shared surface.

**A writer checked by its own parser proves nothing, so the reader is written from the manual and the validator restates the spec independently.** `reader::parse` is character-level and schema-driven — a char or null takes no trailing space, so the next number runs hard against it (`?10`, `+0` in the manual's own example) and whitespace tokenization desyncs. `validate_xt` then holds the graph to: the lexical rules (ASCII, no interior adjacent spaces), the header's cross-references, indices 1..=n unique and complete, every pointer resolving *and* of the class the schema names for its slot, every chain a reader walks plus its coverage, and geometry recomputed from the node's own fields in metres — directions unit, radii positive, a cone's sin/cos one angle, every chart point on both surfaces, every edge end on its curve. `mod.rs`'s tests keep only what needs the `Solid`: the per-type node counts against the kernel's own face/loop/used-edge/reached-vertex counts, the INTERSECTION structure walk, and the deviation report. Fixtures for both test modules live in `xt::fixtures`.

Every corruption test in `validate` mutates a *good file as a file* — `Parsed::render` re-emits the token stream, so flipping one sense character or moving one chart point is exactly the byte-level damage a real defect would do, and the test asserts the validator names it rather than something incidental.

**Three of the validator's own first findings were the validator, not the writer**, which is the shape to expect from an instrument that has never run: a `pointer0` slot read as non-nullable (a solid region's shell legitimately has no front-faces and a void region's none behind), a **ring** walked as a null-terminated chain, and `owned_by` reading slot 1 as an owner on node types where it is something else or absent. The distinction the manual draws and the validator now draws: **all chains are doubly-linked and null-terminated unless stated otherwise (p.78); a loop's fins, an edge's fins and a geometric owner's members are rings** (pp. 89-90, 76).

**A body's extreme vertex does not bound its material, so the obvious orientation check is unsound.** Every face's normal must point out of the solid (p.23), and the tempting way to test that from the file alone is at the body's maximum-x vertex, where no outward normal may lean back in. Written and run, it fires on the split L: faces 184 (CYLINDER) and 214 (TORUS) at `x = 42 mm`, `n·x = −0.415`. Both are correct — that is the reentrant corner fillet, whose arc **overhangs the grid line** (`REENTRANT_FILLET_OVERHANG`), so material genuinely exists past the extreme *vertex* and the supporting-halfspace argument the check rests on is false. The rigorous statement needs a point interior to a face attaining the body's true maximum, which the file does not hand over. Removed rather than kept as a proxy. Orientation is currently checked only structurally, through FACE.shell/front_shell and the dual region/shell chains.

`a_split_l_shaped_bin_writes_its_torus_sections_as_exact_intersections` pins the INTERSECTION path — straight rectangular splits never produce a `TorusSection`; the carve planes only cross the reentrant corner's fillet torus on L-shaped pieces.

**The import ladder is the only signal a real Parasolid reader gives us, and Onshape now accepts all five clean.** Nothing here can run one, so `writes_the_import_ladder` (`#[ignore]`d, `XT_LADDER_DIR`) writes five files that differ by one thing each — `1-cube` (planes and lines, BODY root), `2-bin-nofillet` (cylinders, cones, circles), `3-bin` (the blend torus), `4-two-bodies` (POINTER_LIS_BLOCK root), `5-split-l` (INTERSECTION/CHART/LIMIT/GEOMETRIC_OWNER) — so a CAD system that refuses one names the node class at fault by which one it is. Measured at the current writer: none of the five carries an ELLIPSE, so the manual's `struct ELLIPSE_s` (p.31) omitting the `sense` its `LINE_s`/`CIRCLE_s` carry — probably a typo in the document, since it declares `ELLIPSE_s == ANY_CURVE_s` — cannot be what a bin's file trips on.

**Verified against the manual, table by table, so it need not be redone:** the flag sequence and header (p.13, byte-identical in form to the manual's example), the terminator, and the field order of BODY (p.83), REGION (p.86), SHELL (p.87), FACE (p.88), LOOP (p.89), FIN (p.90 — no `node_id`), VERTEX (p.91), EDGE (p.92), POINT (p.6), POINTER_LIS_BLOCK (p.95), PLANE (p.50), CYLINDER (p.52), CONE (p.53), SPHERE (p.55), TORUS (p.56), LINE (p.27), CIRCLE (p.29). Also right: `body_type` 1 = `SCH_solid_body` (p.84 — the manual's worked example reads 3 because it is a *sheet*), `state` 1 and a null `key`, the BODY region chain headed by the infinite void region, a root list free of the 20-entry limit (p.96), node-ids present and distinct. INTERSECTION/CHART/LIMIT (pp. 40-43) are the tables still unaudited.

**And verified a second time against a real Parasolid file**, which is a stronger oracle than the manual because it is what a reader actually accepts: a schema-25.0 `.x_t` written by Onshape (Parasolid 37.1). Node for node, SHELL, FACE, LOOP, FIN, EDGE, VERTEX, POINT, LINE and CYLINDER carry the **same fields in the same order** at 25.0 as the writer emits at 12.0, and REGION's `'S'`/`'V'` and BODY's chain heads agree; only BODY differs, by six trailing fields 25.0 added. Two conventions the manual states only in prose are confirmed exactly as written: a solid body's boundary shell appears as `SHELL.face` + `SHELL.body = body` on the solid region and `SHELL.front_face` + `SHELL.body = null` on the void region, and each face names them as `shell` and `front_shell`. So the 1-cube ladder file is **not structurally wrong**, and the remaining differences from a Parasolid-written file are: the schema/modeller version claimed (12.0 vs 25.0), the record wrapping (76 columns broken between tokens vs 80 broken mid-token), the spelling of doubles (`0.005` / `0.00000001` vs `.005` / `1e-8`), and the absence of any attribute machinery (ATTRIBUTE / ATTRIB_DEF / ATT_DEF_ID / LIST / POINTER_LIS_BLOCK, and a null `attributes_groups` / `attribute_chains`). All four are spec-legal. **None of these was why Onshape refused the file** -- that was the header padding, and then the f64 direction defect below.

**The human header is padded to `HEADER_RECORD_WIDTH` = 80 and carries the full PART1 keyword set**, one keyword per record like Onshape's own writer, because the preamble is what a frustrum compares against its expected form to detect transport corruption and it is the only part of the file a reader inspects before parsing anything. The manual calls every PART1 keyword optional (p.10) and its own example pads to 65, so nothing about the 65-column header was a spec violation and the file was structurally sound at the time — Onshape refused it anyway, and padding to 80 is what got all five ladder files to load. A reader's preamble check is not in the document.

**Every direction the file carries is normalised in f64, not in the kernel's f32**, and that was the fault Onshape reported. An f32 unit vector is unit to about **6.7e-8** once widened to f64 — six times the `res_linear` of 1e-8 the file itself declares — so a Parasolid frustrum measures it as non-unit and marks the face. Only *tilted* directions are affected: an axis-aligned one is exactly +-1 in both precisions, which is why `1-cube` imported clean while `2`..`5` each faulted on a **peg chamfer**, whose slanted planes and cones are the model's first non-axis-aligned normals. That is now the **kernel's** invariant, not the writer's: every direction is a `Dir`, unit in f64 at construction, and every reference direction perpendicular to its axis by the same (see `Dir`, above). So `Writer::dir` writes the three components the `Dir` already holds and `unit64` and `Writer::dir_perp` are **gone** — a direction reaching the writer still needing repair would be one the kernel had already got wrong. `Surface::Cone` still carries the **half-angle** rather than a precomputed f32 sine/cosine pair, so `write_surface` derives the pair with one `f64::sin_cos` and their squares sum to one exactly, asserted against `UNIT_RESIDUE` = 1e-15, which lives in `math.rs` with `Dir`.

**The validator's tolerances are the reader's, not the validator's own.** They were `1e-4` unit, `1e-3` orthogonality, `1e-5` cone identity, `1e-6` m on-geometry — four numbers picked to be comfortable, every one of them looser than the 1e-8 the file declares, so the defect above was invisible to a battery that had always been green. `UNIT_TOL`/`ORTHO_TOL`/`CONE_IDENTITY_TOL` are 1e-12 now (the writer guarantees f64 exactness, so there is no f32 residue left to allow for) and `ON_GEOMETRY_M` is **`res_linear` itself**, 1e-8, against a measured f32 deviation of ~3e-9 m. A tolerance a validator picks for itself is a number the reader has never heard of; the point of these four is to fail here rather than in someone's CAD system. `a_tilted_direction_reaches_the_file_unit_to_f64_not_to_f32` is the direct regression guard, and it asserts its fixture is a direction f32 *cannot* make unit so it cannot pass vacuously.

Refusals (all `Err`, surfaced with bin/body context by the wasm boundary): a surface carrying a non-positive radius, a face whose own points do not lie on it, a torus-section edge not meeting two distinct faces, a shell bounding a void. The first two used to be *four* -- a cone face spanning its apex and a spindle-torus face crossing the axis its sheets meet on were refusals only because the kernel's cone and torus left those questions open; naming the nappe and the sheet in `geom.rs` makes both unrepresentable rather than rejected. Body naming (SDL/TYSA_NAME attributes) deliberately out of scope.

### `tess.rs`

Analytic faces → triangles. **Watertight by construction:** each edge sampled once (cached by `EdgeId`), so the two faces sharing it emit identical boundary points.

**`tessellate` states the watertight postcondition; `tessellate_shell` is for an input that cannot hold it.** Both are `tess_faces` + a check. `tessellate` asserts `tessellation_leaks` empty — a statement about a *closed* solid. `program::run` emits partial open shells on purpose (the step-through debugger), and an open shell's mesh leaks along its boundary by construction: a boundary edge is sampled by the one face that has it, so nothing pairs it. `tessellate_shell` exempts exactly that case and no other — closed input (`validate_ignoring_unused_edges`) still routes through `tessellate` and is held to the same mesh. Not a "skip the check" flag: a blanket one would let a closed solid through unchecked the first time a caller reached for it. `tess_faces` asserts its own postcondition, `face_of_tri` parallel to `tris`, which is what lets a leak report name the faces at the leaking edge.

**Winding comes from the loop; only the normals are voted on.** `triangulate` answers in the caller's loop order — `planar` re-winds every loop to outer-CCW/holes-CW for its sweep and un-winds on the way out, and the 3- and 4-vertex fast paths already emit in input order — so a face wound like its loop closes against its neighbours by construction. Deciding *winding* per face instead, by an area-weighted vote of emitted triangles' geometric normals against the analytic ones, was a survival from before `orient::normalize` and is strictly less informed: it sees one face at a time. Where it disagreed with the topology it inverted that face alone and the mesh leaked along **every** one of its edges. That is what the free-form-wall leaks were — a partial-height wall's 4-vertex top cap took the fast path while its neighbours went through `planar`, and the vote resolved the two conventions differently. Never decide winding per triangle either, or curved faces get inconsistent internal edges. `a_partial_height_walls_top_cap_is_wound_like_its_neighbours` pins the repro; seeds 7 and 42 went to 0/150 and seed 1 from 5 to 2 on this.

The vote survives for the **normals**. `orient::normalize` guarantees consistency per connected component, not per face, so one face's `sense` can still oppose the loops around it — and there the analytic normal must give, not the winding that just closed the shell. Negating it keeps shading and the STL facet normal pointing out. (Flipping such a face's `sense` in `normalize` instead was tried and is wrong: breaks `fuzz_bin_shapes`, `fuzz_inner_walls`, `fuzz_split_pieces`, because the per-component decision is what keeps edge alternation intact.) The vote is literal, not the `uv_area · uv_orientation · sign` proxy it used to be — the proxy assumes a face's uv handedness is constant, which a **spindle torus** (floor-fillet blend, `major_r < minor_r`) violates, and it silently inverted those faces once loop winding was normalised.

The structured-grid path tries **both edge rotations** when matching a quad's loop to its iso-u/iso-v roles, since which of the four edges comes first depends on where the loop starts; without the retry a normalised loop falls through to the planar path, which chords straight across a curved patch (a floor-fillet blend came out 0.6 mm off its own cylinder). `Edge::seg_count` subtracts `1e-3` slack before `ceil`, so an arc whose sweep is a hair over an exact multiple of a quarter — which a connector's `TAU`-wrapped advance always is — does not gain a spurious segment; when it did, the two arcs bounding a trimmed patch disagreed on sample count and the grid path rejected the face.

Non-planar 4-sided faces whose loop follows iso-u/iso-v lines (cylinder walls, cone chamfers, blend patches) take the structured-grid path (cheaper, predictable quad-strip diagonal); everything else including planar-with-holes goes to `planar`. The only triangles dropped are ones a weld would collapse anyway (two vertices on the same weld key) — a flat triangle with three *distinct* vertices still has its edges paired against neighbours, so discarding on area alone punches a slit in the mesh.

`triangulate` asserts its postcondition: `assert_tiles_the_loops` requires every loop edge in exactly one triangle and every other edge in exactly two. Neither the quad fast path nor `planar` can satisfy that for a loop **not simple in uv**, and before the assert they answered anyway — a self-intersecting wall-top quad came back as six triangles including a literal duplicate, surfacing only as a `tessellation_leaks` report on a face far from the trim that authored the bad loop. The assert is where a bowtie loop is caught, not where it is *fixed*: **a firing is a defect in whoever built the face**, not in the triangulator.

### `planar.rs`

Planar polygon-with-holes triangulation: **monotone decomposition** (sweep top to bottom, diagonals at split/merge vertices) then stack triangulation of each y-monotone piece. Chosen over ear clipping for what it guarantees, not speed: **every boundary vertex the caller supplies appears in the output** (so the neighbouring face's samples still line up and nothing has to be fanned back in), holes handled by the sweep rather than by bridging, each interior edge shared by exactly two triangles by construction.

Degeneracy is the whole difficulty, because cavity floors are rectilinear and full of exactly-equal coordinates. Sweep order is lexicographic (decreasing y, then increasing x), which *is* an infinitesimal shear, so no two distinct vertices tie and no edge is horizontal in the sweep's frame; the orientation predicate is shear invariant, so the same cross product decides left-of-edge in both frames; and the face tracer names the edge it came in on **by index, through an explicit twin**, never by angle, which is what a diagonal lying along a boundary edge would break. Tests assert exact area, full edge pairing, no dropped vertex, over rectilinear, many-hole, collinear-staircase and random inputs.

### `split.rs`

`trim(solid, &Cut)`; `trim_half_space(solid, plane, keep)` is the one-plane convenience. Every face classified, straddling faces trimmed to their section curves, gaps closed with connectors along `face ∩ plane`, connectors chained into cap loops. All analytic parts closed form: `curve_plane_params` (line by ratio, circle/ellipse by `a·cos t + b·sin t = c`, `TorusSection` below) and `param_of`, inverting a point back to a parameter — **never by sampling**, the approximation the kernel forbids.

**A `TorusSection` never crosses the plane that cut it out, and `curve_plane_params` answered every plane with that one fact.** It is false for any *other* plane of a multi-plane cut, and the case is ordinary: `fuzz_split_pieces`'s last defect, `no closed-form section curve for a face the cut crosses`, was an L-piece's prism turning its corner at `x=84` while a connector ran along the reentrant floor fillet's section in `y=42`. The section existed and had the point on it — nothing reported where it handed over, so `close_chains` found no connector and blamed the curve set. Substituting `rad·cos u = offset` into `point(t)` gives `center + offset·d0 + branch·√(rad²−offset²)·d1 + minor·sin t·axis`, so against `x·n = c`

```
A·√(rad² − offset²) + B·sin t = K       rad = major + minor·cos t
A = branch·(d1·n)   B = minor·(axis·n)   K = c − center·n − offset·(d0·n)
```

— closed form in each of the two families the kernel produces, a quartic in `cos t` in between. `n` ⊥ axis (`B = 0`, every plane of a `Cut::prism` swept along the torus's own axis) forces `rad² = offset² + (K/A)²`, so `cos t = (R − major)/minor` for that one `R ≥ 0`; **only `+R`**, since `torus_section_exists` bounds the curve to `rad > 0`. `n` along the axis (`A = 0`) is `sin t = K/B`. The square root is non-negative, so `K/A < 0` means the *other* branch crosses and this one does not — no root, rather than a root of the squared equation the original does not have. An oblique plane **panics** naming the quartic: returning nothing is what hid this for a release, and production makes only vertical prism cuts against Z-axis floor-fillet tori, so the perpendicular family covers all of it.

**The refusal at the end of `close_chains` names the surface pair now.** `no closed-form section curve` was one of two things reaching that `None` — a pair the curve set cannot name, and a section that exists but led nowhere — which want opposite fixes (a new `Curve` variant, versus a bug in the walk) and were indistinguishable from the message. It prints the chain end, the face's surface, and per plane of the cut at that point what the two meet in; that alone turned this defect from undiagnosed into a one-line read.

A `Cut` is a list of oriented planes, each `discard_normal` pointing into the material it removes, and it owns the three things previously hard-coded to a single plane: classification (`Cut::side_of`, where `On` means *on the cut surface*, not on one plane), crossings (`Cut::crossings`, tagging each parameter with the plane it crosses), cap grouping (per plane).

Two load-bearing conventions, each a bug first. Connector direction is `winding_normal × discard_normal` using the face's **true outward** normal (raw normal flipped by `sense`), well defined only because every loop satisfies the orientation invariant — before that invariant existed this used the raw normal and a cavity wall sent the connector the wrong way. And trimmed pieces take end positions from the solid's **stored vertices**, not `curve.point(t)` — the same point in exact arithmetic, an f32 ulp away, duplicating the edge as the `resume` note describes.

A connector's arc is emitted as `(t0, t0 + signed_advance)`, never `(param_of(from), param_of(to))`: `param_of` returns a principal value, so the raw pair can name the *other* way round the circle. `advance_along` computes the correct directed advance (wrapping by `TAU` until positive) and that signed value is what the edge is built from. Getting it wrong put a floor-fillet blend's quarter-arc on the 3/4 path — same endpoints, wrong surface — and cost 83 mm³ of double-counted material on a 2×1 bin.

**A trimmed face may be several faces.** A cut can break one face into disjoint regions — trimming a bin's rim to its middle cell leaves the strip either side of the cavity with no path between them; trimming a corner fillet leaves an arc either side of the removed span. `emit_trimmed_faces` groups surviving loops by winding into outers and the holes each outer contains, the way `emit_caps` already grouped cap loops; taking the first loop as outer and the rest as its holes made the second region a *hole of the first* — a self-intersecting face that audits `LoopContainment` and tessellates with leaks. Two things it must get right: the winding test is signed area **times the face's `sense`**, since an inverted face's outer loop measures negative; and on a rotational surface `u` is an angle, so each loop's `u` is **unwrapped** first (`unwrap_u`) — a seam-crossing arc otherwise reads as a near-full-turn band whose signed area is meaningless, which is how two disjoint arcs of a corner fillet measured as +137 and −8. A face whose loops do not classify cleanly falls back to first-loop-is-outer, the reading every uncut face already has, so the grouping can only improve on it.

**Multi-plane cuts work.** `Cut::prism(&loops, axis)` sweeps 2D loops into a prism of oriented planes — what carving an arbitrary polyomino needs. The missing piece was a connector terminating on a *cut-surface edge* rather than another chain: advancing along plane A must stop where A meets plane B and continue there. `window_exits` finds those stops, `runs_along_cut` recognises a section curve already lying in the cut surface, `nearest_along_shared_edge` picks the continuation. Classification, crossings and per-plane caps were already general.

**A split is a boolean applied last**, not each piece authored from its own cell set (which is why a divider seam used to yield two `wall_thickness + HALF_TOL` walls where the intact bin has one centred `wall_thickness` strip). `build_bin_solid` builds a logical bin once and `carve_to_cells` trims one printable piece out of it; every caller pairs them that way and builds each bin **once** — `try_build_pieces` for the GUI/STL path, `generate_geometry` for the web app, carving all of a bin's pieces off the one solid rather than rebuilding and re-filleting per piece. `build_piece` composes the two. Seam walls are *not* special-cased: the whole bin is built with its dividers and then cut, so a divider at a seam becomes a wall in both pieces and a plain seam cuts open — `split_seam_divider_walls_both_pieces` and `seam_edges_default_open`.

**A carved piece is held to what a printable body is, where it is produced.** `trim` establishes the manifold invariant and nothing more, so until `assert_piece_is_sound` the pieces that are actually *exported* were the one thing in the pipeline never audited -- `build_bin_solid_reporting` audits the whole bin, and the carve threw that away. Four properties, asserted in `carve_to_cells` on every return path: `validate()`; `audit()` clean; **one shell per island of the piece's cells, every one of them `encloses_material`**; and no orphan vertex or edge. The island count is `layout::compartments(piece_cells, &Default::default())` -- the production connected-components pass, not the fuzzer's mesh union-find, which stays in `tests/fuzz.rs` as the independent restatement. Assertions rather than `Err` because an unsound carve is the kernel's own defect; `carve_to_cells`' two existing `Err`s (enclosed piece, no boundary traced) are properties of the request and stay `Err`. Every consumer inherits it: `build_piece`, `try_build_pieces_reporting`, the GUI, and the web app's `generate_geometry` / `export_parasolid`. The shell half is what nothing else could see -- a detached lump of material tessellates and welds like any other closed surface, and only the X_T writer refused a void, by accident of needing to name regions. `two_separated_lumps_of_material_are_two_shells_that_both_enclose_it` and `a_void_sealed_inside_material_is_a_shell_that_encloses_none` are the negative fixtures; a gate that cannot fail is not a gate. Costs one `audit` per piece, which the crate's assertion policy is exactly the trade for. Measured green: lib gate 287/287, `fuzz_split_pieces` and `fuzz_bin_shapes` still 0, `fuzz_inner_walls` 21/150 and `fuzz_params_broad` 7/400 unmoved in both directions, and all four pieces of `examples/drawer.toml` pass.

**`carve_to_cells` trims to the piece's *cell set*, not its bounding box.** Traces the cells into boundary loops and trims to that prism, so a piece may be any connected polyomino. Bounding-box carving was exact only for grid slabs: `layout::partition_cells` guarantees those, but the web app's `web/src/lib/cuts.ts` `partitionCells` is a flood fill over severed edges, so two pieces' boxes could overlap and duplicate material — a 2×2 split into `{(1,0)}` and the L-shaped `{(0,0),(0,1),(1,1)}` gave back the L as the *whole bin*, the two summing to 125%. `a_staircase_piece_carves_to_its_cells_not_its_bounding_box` pins it. `trim` first classifies the solid's vertices, so a cut missing a piece's material is a no-op rather than an error — an L-shaped bin needs that.

It takes the **bin's** cells as well as the piece's, because the prism is not quite the cell set: a reentrant corner is filleted by `OUTER_R` and that arc **overhangs the grid** into the empty notch cell, only its two tangent points on the grid lines. Trimming to bare cell rectangles shaved the bulge off every piece — ~54 mm³ per reentrant corner, so a split L lost 0.1% and a split rectangle nothing. Each cell therefore reaches `REENTRANT_FILLET_OVERHANG` into a neighbouring cell **the bin does not occupy**, and reaches **only along y**. One axis is not a simplification, it is the correctness argument: a reentrant corner always has a vertical neighbour among its three occupied cells, so one reach always covers the bulge, while reaching along both axes lets two pieces meet inside the same empty cell and both claim it — measured **+186 mm³** over-count on a split T. `carving_a_reentrant_bin_keeps_the_corner_fillet_that_overhangs_the_grid` pins it. A ~7 mm³ residual remains, flat in height so it is in the base not the walls; not diagnosed.

**A piece enclosed on all four sides by the rest of the bin is refused up front** (`piece_is_enclosed`). Its cut runs through face *interiors* without crossing their loops, and `trim_loop` only inspects loop edges, so no chain and no connector is produced — the 3×3 centre cell reaches `trim` with 32 vertices inside, 312 outside, **0 connectors**. Supporting it means teaching `trim` to open a new interior section loop in a face, which it cannot do; until then the error says so instead of failing deep in the cap emitter with `cut section does not close into a loop`. Same capability a runout terminating in a face's interior needs.

### A blend chain across a kink is refused, not asserted against

`reconcile_shared_ends` derives each blend end's ball centre and touchdowns once and hands the answer to both edges, and it used to **assert** the two already agreed to within `join_agree`. That is a property of the chain the *caller* asked for, not of the kernel's own arithmetic — exactly like the shared-face count in the branch above it, which was already an `Err` — so it is an `Err` now. `fillet_best_effort` drops the chain and the user still gets a part; the fuzzer still counts the drop as `FILLET_FAILED`, so nothing is forgiven, only reported instead of crashed. A **closed** edge disagreeing with *itself* stays an assertion: both its ends came off the same faces and the same arithmetic.

Found by a packed drawer: 42 dividers, a T junction whose two floor-fillet edges put the ball centre 4.2e-2 mm apart against a 2.1e-2 mm bound. Radius-independent, layout-dependent — one of the `fuzz_inner_walls` class, undiagnosed. It cost 29 of that bin's 204 floor fillets, which is what the salvage drops with the chain.

`try_build_pieces_reporting` is how a caller sees that: `try_build_pieces` plus every bin's `BlendReport` summed, asserting `made + unresolved + dropped == requested`. Without it a caller cannot tell a drawer that kept its fillets from one that quietly gave them up, and the `optimize` report prints both the counts and the refusal.

### A feature timeline needs a laminar boolean, not a general one

**Measured, not assumed.** A 2x1 bin is **15 program steps**, and the model emits
face-by-face: `PlanarFace` x6, `Wall` x3, `SlopedWall` x5, `WallFaces` x1 against only
`Loft` x1, `Hole` x1, `Slabs` x2, `Fillet` x1. The step list for that bin reads
`peg 0 bot/mid/top` (3 sketches), `peg 0 loft`, `peg 0 bottom cap`, the same five for peg 1,
`outer wall 0`, `bridge underside`, `cavity 0: slab stack`, `rim face`, `floor fillet`. Only the
last three are features; the rest are one solid being co-authored a face at a time into one
`Builder`.

**The features it decomposes into meet only at horizontal planes and vertical prisms.**
`the_model_joins_at_planes_and_prisms_never_at_a_curved_intersection` is the check, over
1x1 / 2x1 / 2x2 / 3x2 at `floor_fillet: 0`: **no face straddles `PEG_HEIGHT`**, and **every
face above the cavity floor is prismatic** (a plane with a horizontal or vertical normal, or a
Z-axis cylinder). It also asserts it *found* curved faces below the interface, so a model
without chamfers could not pass it vacuously. Two consequences:

- **Base union body** is the 2D boolean of the two cross-sections at `z = PEG_HEIGHT`, plus
  caps. That is precisely what `bridge underside` already is -- `outline - union(peg tops)`,
  hand-stitched through `stitch_loops_2d`. `PEG_W_TOP` = 41.5 = `GRID_PITCH - 2*HALF_TOL` and
  both profiles carry `OUTER_R` corners, which is *why* `split_outline_at` and
  `split_peg_profile` can weld them by hand at all.
- **Body minus cavity** is prism against prism, so its intersection curves are vertical lines.
  Already `slab.rs`'s domain.

So a CAD-style timeline for this model needs **no surface-surface intersection and no general
boolean**. It needs `union`/`difference` between two `Solid`s restricted to operands whose
interaction is laminar -- confined to horizontal interface planes and vertical prisms -- which
is `slab.rs`'s existing band math lifted from "a list of 2D `Slab`s" to "two solids". The
generalisation `slab.rs` needs is that a band's cross-section may vary (`lower`/`upper` seg
loops, exactly what `build::wall_between` and `Op::Wall` already take) rather than being one
region, so a peg's chamfer bands are expressible; and the precondition that within any band at
most one operand is non-prismatic, which the check above says holds.

**The exceptions, both already exceptional.** A *sloped* bin's floor is a tilted plane, so it is
not prismatic and the ramp is outside this -- the same feature that already takes no inner
walls and no rounded cavity corners. And the *floor fillet's* tori are non-prismatic by
construction, which costs nothing: `fillet_edges` is already valid-solid-in, valid-solid-out and
needs no boolean. Run the check with `floor_fillet` on and it fails on the blend faces, correctly.

**What it would delete:** the reason `outline.rs`'s `split_outline_at` exists (436 lines of file),
`peg.rs`'s `split_peg_profile` and `SharedWithPegs` (182), the `stitch_loops_2d` bridge-underside
stitching, and the `presplit_regions` welding in `plan_cavities`. All of them are one hand-rolled
union. What it would *not* touch is the cavity walk and the opening machinery -- those author the
right 2D region, which a boolean still needs someone to do.

**What it would not fix:** the fuzz backlog. Its largest classes are blend-runout capabilities
(the ramp into a needle x13, runout onto a cylinder, three blended edges at a vertex). A boolean
reaches none of them; do not judge this work by that table.

### `orient.rs`

The **orientation invariant**: every loop is *material-consistent* — walking it with the face's true outward normal keeps material on the left (outer loops positive, holes negative). `Builder::build` establishes it, so every solid the kernel hands out satisfies it and `misoriented_loops` is empty. This is what makes a boolean expressible.

Was *not* true before: `region2d` emits loops material-on-the-left in 2D, `slab`'s cavity mode reuses that winding and flips only `Builder::face`'s `sense`, so a bin's whole cavity shell — plus the rim face's inner loop bounding it — traversed inverted relative to the outer shell. Edge alternation still held (an inverted shell paired with an inverted hole loop alternates fine), which is why `validate` never caught it and why **propagation across shared edges cannot detect it**: the material side has to be measured geometrically.

Two things make the measurement trustworthy. It uses the loop's **3D area vector** dotted with the analytic normal, not a signed area in uv — `uv_orientation()` assumes constant uv handedness over a face, and on the floor fillet's **spindle torus** (`major_r` 0.1 < `minor_r` 2.4) the ring radius `major + minor·cos v` changes sign inside the face, so uv area reports the wrong handedness. And the decision is **per connected component of loops sharing an edge, not per loop**: alternation forces the flip set to be closed under edge sharing, so a component flips as a unit by an area-weighted vote. Per loop instead strands any loop the measurement skips (a full-2π loop on a whole cylinder has no meaningful area vector) on the wrong side of its neighbours and breaks the manifold invariant — that was three fillet tests. Normalising is pure re-winding: never moves a vertex, `normalising_changes_no_geometry` pins that.

### `program.rs`

A model expressed as a **flat labelled list of ops** the kernel executes. A `Program` carries geometry (profiles, heights, `(seg, z)` blend selections), never builder handles, so `run(prog, |i| bool)` can execute *any subset*: prefixes step through the construction, arbitrary masks toggle individual ops off. Blends collect during the run and apply once at the end (`fillet_edges` consumes and rebuilds the whole solid). A partial subset is generally not manifold, by design — that is what makes the debugger useful. `Op::Custom` is the escape hatch for geometry with no kernel primitive (Gridfinity's bridge-underside stitching): it must re-derive every handle when it runs, cheap because `ring`/`seg_edge` intern.

### `region2d.rs`

Exact 2D boolean algebra on seg-loop regions (outers CCW, holes CW): `region_union`/`region_difference`/`region_intersection`. All four Line/Arc intersection pairs closed form (line/line by determinant, line/circle by the quadratic, circle/circle by the radical line); cut points computed once, for an *unordered* segment pair, pushed verbatim into both sides' cut lists so selected pieces chain exactly (see the shared-cut-point note under Determinism).

`presplit_regions` gives several booleans over the same inputs one common segmentation — required whenever their results must weld. `split_regions` exposes the classified pieces with caller-supplied provenance tags, which is how the inner-wall planner names contact runs without ever comparing coordinates.

Both sweeps are all-pairs over segments and **reject a pair on its bounding boxes** before solving. Boxes grown by `BOX_TOL`, which must stay above the 1e-3 that `on_seg` accepts, or a real crossing gets pruned and the boolean silently loses a cut. A verification pass re-solves every rejected pair and fails if it finds one — that guard is the reason to trust the prune, since the failure mode is wrong topology rather than a crash. Gated on `set_verify_prune`, a relaxed atomic checked **once per sweep**, so it costs a predictable branch when off and re-solves quadratically only when a test asks. It was a `debug_assert!` per rejected pair until the suite moved to `--release`, which compiled it out entirely.

`loops_within(a, b, limit)` is the clearance predicate: callers wanting a verdict must use it rather than thresholding `min_loop_distance`, whose only early exit is an exact zero and which therefore always paid the full `|a|·|b|`.

**Coincident boundary runs are classified explicitly**, not by the inside/outside point test: where the two boundaries run together the midpoint lies exactly *on* the other boundary, where even–odd is undefined. Those pieces go to `on_same`/`on_opposite` by relative traversal direction (A's copy only, so a shared run is represented once), and each boolean states which it keeps — union and intersection take `on_same`, difference takes `on_opposite`. Getting this wrong made `A − (A − N)` return *empty* whenever the operands shared most of their boundary, which is exactly the shape of a slab band interface, so a partial-height inner wall got no top cap and the solid was non-manifold.

### `slab.rs`

The **restricted boolean**: `build_slabs(&[(Op, Slab)])`, a `Slab` being a 2D region swept over a z-range. z endpoints cut the stack into bands, each band's cross-section is the 2D boolean of the slabs covering it, and the solid is assembled band by band — walls per band (bands delimited by *all* breakpoints, so nothing changes inside one and verticals need no splitting), plus caps at each interface from `below − above` (facing up) and `above − below` (facing down), treating outside the stack as empty.

**Loop directions are never reoriented**: the boolean emits every run material-on-the-left, exactly what both wall and cap need, and a loop can be a cap's hole *and* the outer of the band wall above it (a shoulder under a tower) — reversing it for one role breaks the other. Both operands being z-prisms keeps every intersection curve vertical or horizontal, which keeps this inside the analytic curve set (a general cylinder/cylinder boolean would need a quartic). Cones/spheres/tori are not expressible: a chamfered peg stays a `loft`, a rolling blend stays `fillet`.

`emit_slabs` writes into an existing `Builder` so a stack can share edges with hand-built geometry; `SlabOpts::cavity` emits the stack as a void (material outside); `open_at` skips the cap at an interface the caller closes itself. **Gotcha:** `wall_seg`'s `outward` flips only the surface normal, never the loop direction, so a cavity's walls traverse exactly like a solid's — `slab::emit_cap` therefore keeps solid-mode winding and flips only `Builder::face`'s `sense`. Using `build::cap` there instead would flip winding too and break wall/cap pairing. That holds *during* emission; `Builder::build` then re-winds the finished cavity shell for the orientation invariant, a pure re-winding changing no geometry.

Both cavity builders are stacks. `build_cavity_flat` = compartment void minus one slab per island tower; `build_cavity_banded` = the same plus one slab per partial-height inner wall (floor → that wall's top). A wall reaching the loop boundary, one fully inside it and one crossing it are all just differences — the band machinery caps each where its slab ends. The stack's returned top band **is** the rim opening, which the caller closes. Only the ramp blend still needs the planner: the contact runs name those edges by provenance rather than by coordinate.

### `round.rs`

Reading and reshaping a closed 2D seg loop **at its corners**, nothing about what it bounds. Tangency (`seg_tangent`, `sharp_between`, `has_sharp_corner`, `TANGENT_DOT` = 0.9995 ≈ 1.8°) is what every blend chain and every rounding asks first. `round_sharp_corners` inscribes an arc at each line/line corner, `convex_r` where the loop turns away from its material and `concave_r` where it turns into it, both read off the winding — and **honours neither blindly**: two corners of one run each trim it by `r·tan(φ/2)`, so an over-long pair is scaled to fit (`USABLE` 0.98), which can take a radius under `MIN_ARC_R` and revert that corner to sharp, freeing its neighbour again — hence a fixed point, swept until nothing changes. It asserts its own postcondition, that the rounded loop is still closed. `corners_of`/`loop_of_points` convert between segs and points; `seg_mid`, `seg_samples` (true line/true circle, never a chord), `drop_degenerate`, `is_convex_arc`, `short_arc`, `v2_eq` are the rest.

`region2d` and `rectregion` each carried a byte-identical private copy of `seg_mid` and `short_arc`; both call this now. The deleted `region.rs` (the model layer's polyomino tracer) carried a third copy and called this too.

**`short_arc` is `wrap_pi` and nothing else**, `(a0, a0 + wrap_pi(a1 - a0))`.

### One wrap, in `math.rs`

`wrap_pi(a)` — `a` shifted by whole turns into `(-PI, PI]` — is what every *difference* of two angles goes through: a sweep against its source (`fillet/section::respan`), a candidate against the angle it wants (`fillet/blend`), a sample's drift from the last (`orient::wraps`), a corner's turn (`round::short_arc`). Four private copies before, three of which differed from the fourth **at exactly -PI**: `while d < -PI` keeps it, `while a <= -PI` maps it to `+PI`. Unified on the closed end at `+PI`, so an exact half turn sweeps positive and two diametrically opposite angles are a turn apart in a *definite* direction rather than an arbitrary one. `blend`'s use is inside `.abs()` and cannot see the difference; `orient`'s is a per-sample drift orders below PI. All eight profiles at their table counts across it.

Distinct from `wrap_angle_into(angle, lo, hi, slack)`, which shifts into a range **the caller owns** — what matching a point's `atan2` angle to an arc's stored parameter range needs. `wrap_pi` owns its range; `wrap_angle_into` is given one.

### `nesting.rs`

`stitch_loops_2d(free) -> [(outer, holes)]`: chain loose segments into loops, decide which contains which, read nesting depth's parity as outer or hole — so a loop inside a hole is an outer again, and a hole attaches to the *innermost* outer containing it. `containment` is the pairing alone. Sound only because the loops brought here are disjoint except for nesting; two that properly cross are not a face and it says nothing useful about them. The bucketing (uniform grid, wide loops held aside and their segments bucketed by row) is a prune only — it changes no answer, and exists because a bin's bridge underside stitches one same-sized loop per cell, where ordering by area prunes nothing and the scan is quadratic in cells.

### `rectregion.rs`

Rectilinear region engine: unions/differences of axis-aligned rects resolved on a compressed coordinate grid, traced material-on-the-left (outer CCW, holes CW), then per-corner arc rounding with clamping (`trace_rects`, `shape_loop`). The baseplate outline is built on it. `shape_loop` rounds a loop given as *points*; `kernel/round.rs`'s `round_sharp_corners` rounds one given as segments, which is what a loop a boolean already cut into pieces needs.

### `gridfinity/` — the model

Twelve modules, dividing by what part of a bin they author. `mod` = wiring + `build`/`try_build`/`try_build_reporting`/`program`/`build_piece`/`build_bin_solid*`. `spec` = the normative dimensions and every clamp the model holds itself to (`buildable_wall_thickness`, `buildable_floor_fillet`, and one named const per tolerance — no bare epsilons). `params` = `Params`/`LogicalBin`/`InnerWall`, plain data, no validation. `outline` = the boundary walk + `OuterLoops`/`split_outline_at`. `cavity` = `cavity_inset`/`compartment_corners`/`finger_strips`/`walked_cavity`/`shape_cavity_loop`. `cavity` also holds `pocket_cavity`, the stated-compartment way in. `opening` = `OpenSpan`/`CavityLoop`/`clip_cavity_to_outline`. `wall` = `Island`/`Notch`/`Banded`/`inner_wall_quad`. `peg` = the three ring profiles + `split_peg_profile`. `stack` = `plan_cavity_flat`/`plan_cavity_banded` + the slope arithmetic. `plan` = `plan_piece`. `pieces` = `carve_to_cells`/`carve_baseplate_to_cells`/`try_build_pieces`. `baseplate`.

Each submodule names its own kernel imports and reaches its siblings through `use super::*`, so everything shared between them is `pub(super)` and `mod.rs` globs each back in. The public surface is `mod.rs`'s `pub use` and is what `gridfinity-app`, `gridfinity-wasm` and `tests/fuzz.rs` see — moving an item between submodules changes nothing outside.

Parametric model + spec constants + `Params`, a faithful port of the TS reference's `BinConfig`. `Params.bins: Vec<LogicalBin>` holds polyomino cell sets (plus optional floor slope); `Params::rect(gx,gy)` is the rectangular convenience. **Each bin is built in one `Builder`** so interface edges are shared automatically — there is *no general boolean*.

- **The cell pitch is `Params::pitch`, not a constant.** `GRID_PITCH` is the standard and the default; a `Params` may name another and every cell-to-millimetre step in the model takes it from there. `spec.rs` holds what the standard measures *from the cell edge* as functions of it -- `peg_widths` (insets 0.25 / 2.15 / 0.8 per side, which is the standard's 35.6 / 37.2 / 41.5 at 42 mm), `fastener_inset` (half the cell less `FASTENER_EDGE_INSET` 8.0, = 13 at 42 mm), `baseplate_prism_reach` (half a pitch) -- and everything absolute stays a constant. `MIN_GRID_PITCH` = `2 * (PEG_INSET_TOP + OUTER_R) + MIN_QUAD_ROUND` is where the top profile stops having a straight run, asserted by `assert_buildable_pitch` at each of those three; `MIN_FASTENER_GRID_PITCH` = `2 * (FASTENER_EDGE_INSET + MAGNET_RADIUS)` is where the four bores start running into one another, asserted in `fastener_inset`, which is called only when a bin actually asks for fasteners. `carve_to_cells`, `carve_baseplate_to_cells`, `check_bed_fit`, `compute_auto_split_lines`, `compute_staggered_split_lines`, `GridFootprint::mm`, `drawer_grid`, `packing_area` and `max_drawer_mm`/`min_drawer_mm` all take the pitch as an argument -- none of them sees a `Params`. `optimize`'s `settings.grid_size` is the only caller that states one; `gridfinity-wasm` passes `GRID_PITCH`, so the web app is unchanged, and `web/src/lib/project/drawer.ts` still has its own 42.
- **Outer profile**: a boundary walk traces each bin's cells into loops; profile = pitch lines inset `HALF_TOL=0.25` with `OUTER_R=3.75` corners — convex ones welding with the corner cell's peg top, concave (reentrant) ones unshared — split at `PEG_TANGENT=4.0` (`= HALF_TOL + OUTER_R`, exactly what leaves a straight stub either side of a reentrant fillet) so peg-top edges weld with the wall's bottom ring.
- **Reentrant corners must be rounded**: the cavity rounds its own concave corners by fillet radius `fr`, and a sharp outer one pokes out through that arc once `fr > wall_thickness · (2 + √2)`, leaving the rim strip between them a face whose hole crosses its own outer boundary. (Except where both edges are open — see `corner_walled`.)
- **Base** = one chamfered connector peg per cell (three lofted profiles, 0 → `PEG_HEIGHT=4.75`; `PEG_R_MID=1.6` so all three corner arcs share an axis and the chamfers are coaxial cones). Peg ring segments that don't weld to the wall, plus non-shared outer pieces, are `nesting::stitch_loops_2d`ed into planar bridge-underside faces at `PEG_HEIGHT` — loops geometrically contained in another become holes of that face (an interior peg's ring must be a hole, not a disk).
- **Cavity**: authored by the walk (above), **or stated outright**. `LogicalBin::pockets` is a list of rectangles; non-empty means `plan_cavities` calls `pocket_cavity` and the walk never runs, so the bin is solid everywhere a pocket is not. `trace_rects` unions them, so overlapping pockets are one compartment (how a multi-box object gets an L), and outers pair with holes by containment exactly as `walked_cavity`'s do. Downstream is untouched: same rounding, same blend chain, same stacks, same rim. `optimize` is the only caller — a pocket there is a placement's claim inset by `divider_thickness / 2`, landing the pocket wall where the generated divider's face stood, so the compartment is unchanged in size and only the *leftover* becomes material. It also takes a fitted drawer off the `InnerWall` path entirely. `rc` convex / `fr` concave rounding, so the floor-fillet blend stays tangent-continuous. Compartment cavities are built **sharp**; the concave floor fillet is applied afterwards as a true `fillet_edges` rolling-ball blend over each compartment's floor-wall edge loop (skipped when the clamped radius is 0 or the floor is sloped).
- Bins are `42·n − 0.5` mm. `Baseplate` is full `42·n` with a peg-shaped through-socket per cell. **It reads no fastener setting** — `magnet_holes`/`screw_holes` are the bin's, and the counterbore under a socket is unbuilt; the module doc claimed otherwise for a while.

**A baseplate is split and carved like a bin.** `try_build_pieces_reporting`'s baseplate branch used to return **one** `BinPiece` — no `partition_cells`, no carve, no printer consulted — so a drawer plate came back at 378 × 294 mm, fitting no bed, and as the one exported body in the pipeline never held to `assert_piece_is_sound`. `baseplate_pieces` builds once and carves per part, on the union of every `LogicalBin::split_lines` (a `Params` with one bin, which is what `optimize` builds, is just that bin's lines). Authored per piece instead would round the convex corners at the seam, where the cut is meant to leave them square — the same reason a bin is a boolean applied last.

**`carve_baseplate_to_cells` differs from `carve_to_cells` in exactly one thing, and it is the plate's outline.** A plate is the full `GRID_PITCH` rectangle where a bin is inset `HALF_TOL`, so a prism traced from bare cell rectangles puts its **outer** planes exactly in the plate's own outer faces — a coincident-plane cut `trim` is never handed on the bin path. Each cell rect grows `BASEPLATE_PRISM_REACH` (half a pitch) outward on every side whose neighbour is not in `bin_cells`, moving those planes clear while every interior seam plane stays exactly on its split line. Sound because a baseplate's material lies wholly inside the union of the bin's cell rectangles — there is no `REENTRANT_FILLET_OVERHANG` bulge to share — so the reach only ever covers empty ground; half a pitch is what keeps it there, the nearest material across an empty cell being a whole pitch away. The two asserts state it: the prism covers every cell of its own piece and no cell of another. Each rectangle starts from `plate_cell_rect` rather than the bare cell, so a plate margin is in the prism before the reach is. `a_drawer_sized_baseplate_carves_into_printable_pieces` is the gate, and its sharp half is **volume conservation** against the intact plate, which per-piece manifoldness walks straight past.

**A plate may be wider than its grid: `Params::plate_margin_x`/`_y`.** Totals per axis, split evenly, so the outline stands half of each outside the cell set's **bounding rectangle** on that axis's two sides and the grid stays centred. Read only in `Mode::Baseplate`; 0 by default, so every existing caller builds what it always did. `optimize` is the only one that states them — a drawer floors to whole cells and the leftover is slop the whole stack slides in, so the plate, which is the body touching the drawer walls, spans it and the bin is untouched. Bounding rectangle and not "every side with no neighbour": an interior notch must **not** grow, or two pieces of one plate meet inside the same empty cell. `plate_cell_overhang` decides the four sides, `plate_cell_rect` applies them, and `carve_baseplate_to_cells` calls the **same** function for its prism, so outline and cut cannot disagree; a flange side always has no neighbour, hence is also a reach side, and both of the carve's asserts stand. `a_plate_margin_grows_the_outline_around_a_centred_grid` pins the extents, `a_flanged_baseplate_carves_into_pieces_that_keep_the_flange` the conservation.

**A flanged plate is planned in millimetres, over its own footprint.** `compute_staggered_split_lines(cells, printer, pitch, overhang, avoid)` is `compute_auto_split_lines` with the two things a *second* body needs: chunks measured as `cells * pitch` plus half of `overhang` at each end of the run it touches (`optimize` passes `DrawerGrid`'s leftover margin), and a set of lines to keep off. A DP over cut positions (`chunk_cover` / `cover_cuts`, min chunks then nearest an even division) makes it exact rather than a nudge of the bin's plan, and `widest_clearance` stands each seam as far from the bin's as the minimum piece count allows. `None` means no plan both prints and avoids -- one cell already overruns the bed, or the only dividing line is the bin's. This is what retired *A flanged plate can outgrow the bed its seams were placed for*: the plan is no longer measured in whole cells. `PrinterProfile::bed_fit_mm` still answers the bed question in millimetres and `optimize`'s Printing table still measures every piece off its own finished solid (a bin is inset from its cells, a fitted plate spans past them — neither is its cell count). `check_bed_fit` is the same call from a cell set.

**A body prints if it fits the bed at *any angle*, and both planners choose their chunking on that.** `bed_fit_mm` asks three questions now -- flat, turned a quarter, laid between the two -- and `BedFitResult::tilt_deg` carries **the angle**, at most one of `rotated`/`tilt_deg` ever set. `BedFitResult` gives up `Eq` for it; nothing compared two.

**The angle window is the mechanism, and it is closed form.** Turning a `p` x `q` body by `t` gives it a bounding box of `p cos t + q sin t` by `p sin t + q cos t`, and each of those is `R cos(t - phase)` for `R = hypot(p, q)` and phases `atan2(q, p)` / `atan2(p, q)` -- so each bed side admits the angles *outside* one arc (`cosine_runs`) and `tilt_window` intersects the two. **Up to two runs, not one**: an oblong bed constrains the two sides differently, so the body may lean either way and only one lean fit. Measured: 92 of 3000 random cases have a second run, so dropping it would be a real defect, not a tidy-up. Wetzel's closed-form criterion (`b >= (2pqa + (p^2-q^2)*sqrt(p^2+q^2-a^2))/(p^2+q^2)`) was the first implementation and is **equivalent** -- verified against the window and against a 200k-step rotation sweep on 4000 random cases, 0 disagreements -- but it answers yes/no and cannot name an angle, so the window replaced it. One mechanism decides and reports; `the_window_is_exactly_the_angles_that_put_a_body_on_the_bed` is the restatement, sweeping 900 angles per case against the raw bounding box.

**`tilt_angle` tries the round angles first.** 45 degrees, then 22.5 and 67.5, then halfway again for `TILT_LADDER_DEPTH` (8) halvings, and only a window too narrow for the ladder falls through to its midpoint. That decides nothing -- `tilt_window` has already settled whether the body prints -- it picks *which* of the angles to report, because a piece that needs an angle needs it typed into a slicer's rotation box and 45.0 is a better answer than 44.87. The level bin of `examples/ikea-alex-drawer-1.toml` has a window of 44.41 to 45.59 degrees and is reported as **45.0**.

**The consequence is that the two axes can no longer be planned apart.** Whether a chunk prints is a question about *both* of its dimensions at once, so `compute_auto_split_lines` no longer derives a per-axis cell cap: it searches chunk **counts** `(nx, ny)` over `1..=span_x x 1..=span_y` (`even_cuts` / `widest_chunk` / `even_plan`) and keeps the fewest pieces, then fewest lines, then smallest worst piece. One `bed_fit_mm` decides each candidate, on its widest chunk against its deepest -- that pair *is* one of the chunks, the chunks of a grid being every pairing of an x range with a y range, and the fit predicate is **monotone**, so the single test covers all of them. A body no division prints falls back to one chunk per cell, which is what a cap of zero used to produce. `compute_staggered_split_lines` keeps `chunk_cover`/`cover_cuts`/`plan_axis`/`widest_clearance` untouched and changes only what bounds them: the old two-bed-orientation loop is gone (both orientations live inside `bed_fit_mm`) and a sweep over `candidate_limits(span_y, ..)` takes its place, each depth paired with the **longest `candidate_limits(span_x, ..)` entry that prints against it**.

**The limit is picked from the lengths a chunk can actually measure, never solved for as a real number.** `max_width_for_depth` by bisection was written first and is wrong in a way worth recording: the supremum it converges to sits a hair *under* the true one, so a chunk exactly as wide as the bed is refused -- `a_run_with_no_line_left_to_take_has_no_staggered_plan`'s 42 mm cell against a 42 mm bed failed on 1e-6 mm. `candidate_limits` is `chunk_mm` over every cell range of the run, deduplicated: finite, exact, and the only lengths anything is ever compared against, so a limit drawn from it admits or refuses outright. Same reasoning as `Rect::right` quantising in `project/rects.rs` -- make the two sides of a comparison the same number rather than tolerating the gap.

Sharp tests: `a_bin_that_only_prints_at_an_angle_is_not_cut` (a 7 x 1 run at 40 mm pitch, 280 mm against a 246 mm usable bed, uncut for the bin *and* the plate), `a_chunk_that_only_prints_at_an_angle_is_not_divided_further` (13 cells in **2** chunks where an axis-aligned cap asks 3), `a_body_that_prints_still_prints_when_it_shrinks` (the monotonicity the per-axis limits stand on), and `a_long_thin_body_lies_across_a_bed_a_shorter_wide_one_cannot` (300 x 40 yes, 280 x 100 no, so the rule is not "shorter than the diagonal").

**`BED_MARGIN` is 0.** A bed's stated size is the size of it; a caller wanting clearance states a smaller `bed` in the file, which is the same number arrived at where the person who knows the machine can see it. It was 5 mm on every side, and on the worked drawer that silent 10 mm was the whole difference: the level's bin is 280 x 80 mm, sweeps `(280 + 80)/sqrt(2)` = **254.56 mm** at 45 degrees, and so misses a 246 mm usable square by 8.6 mm while clearing the real 256 mm bed by 1.4. The report's printer line says *used whole* rather than naming a zero margin.

**Measured on `examples/ikea-alex-drawer-1.toml`, at the whole bed:** `hybrid`/`auto` go **7 bin pieces to 6** -- the level's bin drops its one cut line and prints uncut, laid at 45 degrees -- and `walls` is unmoved at 6 + 6, its drawer-wide bin being 280 x 520 mm and its chunks already square-on. The diagonal pays for long thin bodies, which is a `bins`/`hybrid` shape and not a drawer-wide one: a 256 mm square takes ~362 mm of length only at vanishing width, and by 100 mm wide it takes nothing the flat placement did not already.

**Every island gets its own caps.** `build_baseplate` kept `first_outer_top`/`first_outer_bot` and hung *every* hole loop on that one face, so a second disjoint outer got its walls, no cap, and `Builder::build`'s manifold assert. `island_of` pairs each traced hole and each cell's socket ring with the innermost outer loop containing it (`nesting::containment` over the outline loops, `point_in_segs` for a cell centre), and a top and bottom face is emitted per island. `a_baseplate_of_two_islands_caps_each_of_them` is the guard.

**The outer cavity loop's convex radius is clamped up to `OUTER_R − wt`.** A convex outer corner is an arc of `OUTER_R` about a centre `HALF_TOL + OUTER_R` in from the pitch corner, so a cavity corner of radius `rc` leaves a wall of `wt − (OUTER_R − wt − rc)(√2 − 1)`: below `OUTER_R − wt` the wall thins at the corner, and below `wt ≈ 1.1` mm a sharp cavity **escapes the outer arc entirely**, at which point it is no longer inside the rim face it is a hole of and `plan_piece` panicked `total_h hole without a containing face`. Clamping makes the two arcs concentric, keeping the wall its own thickness the whole way round. Moves the default bin's cavity corner 2.5 → 2.55 mm and the corner wall 1.179 → 1.2 mm. `a_thin_walled_bin_keeps_its_cavity_inside_the_rounded_corner` sweeps the pair. **A sloped floor is left square** — no rounding at all, and clamping there breaks `sloped_bin_is_watertight_and_outward`, so thin-walled *sloped* bins can still hit the panic.

**`plan_piece` is five phases with two values between them.** `author_outline` settles the outside of the piece into a `PieceOutline` (profile, peg cuts, open spans, `wt`, `total_h`/`floor_z`); `plan_cavities` authors each compartment against it into `PlannedCavity`s plus the standing wall's loops; `emit_cavity_ops` turns those into stacks and blend requests; `emit_pegs` and `emit_base_and_rim` write the `Program`. The four `perf::scope` metrics (`PlanOuter`/`PlanCavity`/`PlanOps`/`PlanStitch`) sit inside the phases, so the profile table is unmoved. **Op order is the debugger's contract**: pegs, outer walls, bridge undersides, cavities, wall sectors, rim faces, fillet.

Exposed both imperatively (`build(&p)`) and as a kernel **`Program`** (`program(&p)`): same construction sequence, inspectable and subset-runnable. The GUI's construction debugger drives that.

When adding geometry, keep the manifold invariant: any edge a new face introduces must be paired by exactly one other face traversing it the opposite way. `Params` drives grid size, height, wall/corner/fillet, magnet/screw holes, compartments/divider edges, floor slope, Bin/Baseplate mode. (Open-edges intentionally not implemented in the constructive model.)

## Known limitations

- **A sloped bin takes no inner walls.** Cavity is not a z-prism, so the island a free-form wall is carved as cannot meet the tilted floor; walls dropped, bin builds without them. Full-height and partial-height alike, and the partial-height guard is `band_partial_walls`'s first statement so *both* of its branches are covered.
- **A sloped bin's cavity corners are square**, and its wall is clamped to `SLOPED_MIN_WALL`. `ring_on_plane` can express the rounding now (an arc on a tilted plane is an ellipse); re-rounding the sloped cavity on that is untried.
- **An opened compartment takes no inner wall**, full-height or partial. Both guards are load-bearing; see above.
- **A reentrant corner is rounded only when both its edges are walled.** See `corner_walled`.
- **A wall opening onto an enclosed hole's boundary is ignored.** `layout::effective_walls` drops it.
- **A baseplate carries no magnet or screw holes.** `build_baseplate` reads neither flag; the counterbore is `plan.rs`'s, on the bin path only.
- **A piece enclosed on all four sides is refused**, not mangled.
- **An insert (`subbin.rs`) holds one box and is never split for the bed.** Both `optimize`-side; the body itself would carve like any other.
- **Runout onto a cylinder, and torus runout onto a plane not parallel to the torus axis** — both quartics, outside the analytic curve set.
- **Three or more blended edges at one vertex** → `Err` (needs a spherical corner patch).

## GUI notes (important API gotcha)

Pins **egui/eframe/egui-wgpu 0.35, a redesigned API**, not mainstream egui:

- `eframe::App::ui(&mut self, ui: &mut egui::Ui, frame)` — you get a root **`Ui`**, not a `Context`. No `update(ctx, ...)`.
- Panels shown *inside* that root ui: `egui::Panel::left(id).show(ui, ...)` / `Panel::right` / `CentralPanel::default().show(ui, ...)`. **No `SidePanel`.**
- Scroll delta is `input.smooth_scroll_delta` (no `raw_scroll_delta`).
- `NativeOptions` still has `renderer`/`viewport`. **Leave `depth_buffer` at 0** — every depth-tested pass is offscreen, and a depth attachment on egui's own pass makes the depth-less blit pipeline incompatible with it: a `set_pipeline` validation panic.

**The window is the web app's shell, deliberately.** `App::ui` is header + `Panel::left` + `Panel::right` + `CentralPanel`, matching `web/src/App.tsx`'s `AppShell`: a 48 px header carrying the app name, a *Bin editor | Debugger* switch and the exports; the left panel's `Shape | Walls | Cuts` tabs over `Editor::canvas`; the right panel's `Dimensions / Features / Printer fit / Display` `CollapsingHeader`s, replaced wholesale by `Debugger::panel` in the other workspace; the 3D view with *Show gaps* / *Reset view* over its top-right corner (`.viewer-tools`). Colours, type scale and control metrics come from `theme.rs` and nowhere else -- Mantine's own dark scale read out of `@mantine/core`'s stylesheet, so a bin, a divider, an opening and a warning banner are the same colour in both front ends -- and `theme::install_fonts` registers Segoe UI where the platform has it, keeping egui's bundled face where it does not.

**Three tabs, not four tools.** `Tab::Walls` merges what were `Tool::Edges` and `Tool::Walls`: a click within `nearest_edge`'s band toggles that edge, a drag starting anywhere else draws an inner wall, which is `WallsTab.tsx`'s one canvas. `Tab::Cuts` also draws every candidate split faintly, from `candidate_splits` -- the same set `toggle_split` accepts, so what is drawn is what a click can take.

**`Show gaps` is a rebuild, not a uniform.** `Explosion::collapsed()` zeroes the band offsets and `explode()` applies it to the bin, the plate and the object boxes together, so the pieces are still carved -- a collapsed explosion is the split body closed up, not the unsplit solid. The web viewer eases a displacement per frame because its explode is a shader uniform; here the pieces are carved on the CPU, so the toggle costs one rebuild and is binary.

`viewport.rs` is a thin egui adapter over the shared `gridfinity-render` crate, implementing `egui_wgpu::CallbackTrait`: `prepare` runs the whole offscreen chain and returns its command buffer, `paint` blits the finished image into egui's render pass. The callback carries the panel rect and converts to pixels itself, so `prepare` and `paint` cannot disagree about the viewport — the renderer stores what it presented and the blit reads it back. The settings panel's *Display* section owns a Low/Medium/High row calling `Renderer::set_quality`; quality is pinned, defaulting to `High`. **`prepare` also sets the render scale from the display's `pixels_per_point`**, capping the 3D view at `MAX_RENDER_PIXELS_PER_POINT` = 1.5 physical pixels per point: the renderer rasterises into a correspondingly smaller offscreen and the blit stretches it over the same rectangle, so a HiDPI screen costs a HiDPI screen's pixels only up to that ceiling, and only the 3D view softens -- egui draws the panels at the display's own density. It is a property of the display, not a user setting, and it is not adaptive: nothing about a frame's cost feeds back into it.

**Medium and High checkerboard.** `Quality::checkerboard()` (false at Low). Each accumulation frame shades one parity of `(floor(x) + floor(y)) & 1` in the offscreen's grid and reads the other out of the accumulation buffer; sample 0 primes both, so no frame is ever half black. `checker_mode` = the parity, `accumulation_weight` = `1/((n+1)/2 + 1)` because the running mean's divisor is that parity's write count, not the frame count. Budgets unchanged: High converges to 24 samples/pixel, Medium to 8 -- the trade is time, not final quality. Checkerboarded: scene draw, reflection draw, both occlusion passes, accumulate. Full rate: shadow map (cached anyway), depth/normal prepass (`fs_occlusion` samples it at arbitrary offsets), bloom, resolve, FXAA, blit (all read complete buffers). A blur over a checkerboarded source steps by `CHECKER_BLUR_STRIDE` = 2 and halves its sigma -- same physical blur, one parity. Mask is an early `return vec4<f32>(0.0)`, **never `discard`**: a discard writes no depth and `fs_resolve` reads scene depth for DoF. `fs_accumulate` is the sole `discard`, its target being blended. Guard sits **after** `fwidth` -- the checkerboard splits every quad two ways, so a derivative after it reads lanes that never ran. Derived from the pinned level; never adaptive.

Both consumers compile the **same WGSL through naga**, so the class of bug where the debugger accepted a shader the browser rejected is gone. `cargo test -p gridfinity-render` parses and validates every module — where a shader error surfaces. Still smoke-test browser-facing changes with `npm run test:e2e`; validation does not catch a wrong picture.

**Upload before the paint callback is queued, not after.** `Panel::show` only *queues* the callback; it runs later inside `paint_primitives`. `ui()` used to call `regenerate` after the central panel had been shown, so a frame that changed geometry drew the new mesh against the previous frame's camera snapshot — and since the debugger repaints on demand, that mismatched frame stayed on screen until the next input event. `regenerate` now runs before `CentralPanel::show`.

The web app drives the identical `Renderer` and the identical `append_smooth_shaded` staging from `gridfinity-wasm`'s `Viewer`. Shading path shared; the two consumers differ only in what they upload (GUI adds a wireframe pass and the `bad` flag; web app adds per-bin colour, the explode displacement, and `FLAG_CUT` on triangles lying in a split's cut plane). Back-face culling relies on the engine's outward winding (`meshes_have_outward_consistent_winding`). `main.rs` binds `Params` to widgets, regenerates (build → tessellate → upload vertex buffer) on change, exports STL via `rfd` + `Mesh::to_stl_binary`.

**Invalid geometry must never crash the app.** `main.rs` builds **one logical bin at a time** (`gridfinity::build_piece` per `Params::bins` entry, not one `build` over the layout), so a bin the model cannot produce is isolated. Each build goes through `catch`, converting an `Err` *and* an unwind into a message — the model layer still panics on some degenerate parameter combinations (e.g. `height_units: 1` with `wall_thickness: 0.4`) and an unwind out of `regenerate` would take the window with it. `catch` also swaps in a silent panic hook for the duration, since the message is shown in the UI and a slider dragged through a bad range would print a backtrace per frame. A failed bin gets **placeholder geometry** (one plain rounded box per cell at the real footprint and height — featureless, so it can't be mistaken for a real build), and every vertex carries a `bad` flag in the last of `MESH_STRIDE`'s ten floats (position, analytic normal, colour, flag — `MESH_STRIDE` aliases `gridfinity_render::VERTEX_STRIDE`, and `append_smooth_shaded` expands the kernel's six-float `render_buffer` into it). The fragment shader gives flagged vertices a pulsing red rim-lit glow; `paint_error_banner` names the bin and prints why. Export refuses while any bin is failing rather than panicking on the way out.

`debugger.rs` is the construction debugger (right panel, reached from the header's *Bin editor | Debugger* switch, which swaps that panel the way the web app's header swaps both panels between bin and project mode): calls `gridfinity::program(&p)` for the op list, caches per-prefix face counts, rebuilds via `program::run(&prog, |i| enabled[i])` on step/toggle. `regenerate` switches between `gridfinity::build(&p)` (debug off) and the debugger's subset build. Its **Profile rebuilds** checkbox enables `perf` around one `build_solid` and shows wall time, the per-metric table (heaviest first, bar scaled to the heaviest row since timings nest) and allocation count / churn / peak.

**A rolled-back subset goes through `tessellate_shell`, and the whole viewer payload for one goes through `debug_view`.** Vertices + sketch wireframe + B-rep edges in one function, under `catch` in `regenerate` like every other build. It was `tessellate` and unguarded, so **rolling back crashed the app at essentially every step** — one step back from a default bin leaks 72 edges and the assert unwound straight out of `regenerate`. Not a kernel defect: the subset is open by design and `tessellate` promised watertight.

The panel's ◀ / ▶ / `all` / `none` are `Debugger::step_back` / `step_forward` / `set_all`, extracted from the button handlers so a test drives the same code. ◀ stops at op 0 rather than disabling it; `none` is the only way to all-off. `rolling_back_the_construction_never_crashes_the_viewer` (in `debugger.rs`, 60 seeded cases, ~1 s) rolls each case from the end to op 0, through `none`, and forward again, building the full viewer payload at every stop. It is **not** routed through `catch` — the app keeps that net so the window survives, and a fuzzer behind it passes on a viewer that panics at every step, which is exactly the bug it found. It also asserts it visited every op, so a rollback that stops early cannot pass vacuously. `a_rolled_back_subset_still_reaches_the_viewer_as_geometry` is the companion: prefixes of the default bin are open shells *and* upload triangles, so the sweep is not sweeping over nothing.

## Performance

`perf.rs` is the instrumentation. Fixed `Metric` set (region booleans, seg/seg solve, builder interning, blending, tessellation, slabs) over global relaxed atomics, plus a `CountingAlloc<A>` the *binary* installs as `#[global_allocator]` — a library must not choose the allocator for its dependents; the GUI installs it, and each crate's `lib.rs` installs it `cfg(test)` so `perf_report` reads churn headlessly. `A` is **mimalloc**, not `System` (below); it is a dev-dependency only, target-gated away from wasm, so benchmarks measure the allocator the shipping binary uses.

**`Metric` names kernel scopes only; a crate built on the kernel claims a `user` slot.** `USER_SLOTS` (8) rows sit after the kernel's own thirteen, addressed by `perf::user(i)` and named once with `perf::name_user(i, name)` — which panics on a second, different name, a slot claimed twice being two scopes in one row. `scope`/`count` take `impl Into<Scoped>`, so every existing `perf::scope(Metric::FilletEdges)` is unchanged. `gridfinity-model/src/perf.rs` is the one consumer: `Scope::{PlanPiece, PlanOuter, PlanCavity, PlanOps, PlanStitch}` claim slots 0..4 and name themselves on the way in. They share the kernel's table rather than keeping one of their own **because `CountingAlloc` attributes an allocation to whatever scope is innermost on one thread-local stack** — a second table means a second stack, and each crate's allocations landing in the other's rows. `perf_counters_see_a_real_build` asserts the model's rows reach `snapshot()` beside the kernel's, and that an unclaimed slot yields no row at all.

**Off by default** — every entry point starts with one relaxed load, so an uninstrumented build pays a predictable branch and nothing else. `count()` for leaves too hot to time (`point_in_segs` runs millions of times; two `Instant::now()` would cost more than the function), `scope()` for everything else. **Timings nest** (`split_regions` includes the `seg_seg_points` beneath it), so the column does not sum to wall time. **Allocations attribute to the innermost open scope** — an allocation-free fixed-depth `Copy` scope stack in a thread-local `Cell`, never a `Vec`, so pushing a scope can't re-enter the allocator. That attribution is *exclusive*, unlike the nesting time column; the shortfall against the global total is unscoped construction churn. `perf_report` reports the **2nd** rebuild (the slider-drag case).

Scaling harness = `tests/scale.rs`, every test `#[ignore]`d: `scale_report` (cost curve), `scale_features` (what optional features cost), `scale_profile` (per-metric table at `SCALE_WH=48x48`), `tess_bench` (tessellator alone).

Churn-first data-oriented pass: `Solid` → flat CSR arenas (`loop_edges` + `loops` offsets, compact `Face { loop0, n_loops }`), so cloning is a few `memcpy`s; `Solid::edge_faces` returns a two-pass CSR (`EdgeFaces`, `ef[e]` slices) instead of a `Vec` per edge; `fillet`/`chamfer`'s `rebuild_loop` takes that `edge_faces` as a borrow rather than recomputing per face. Cut a default rebuild's allocation churn ~77% (`fillet_edges` ~92%).

Work-first pass, biggest first:

- **`fillet_edges` rebuilds only the faces the blend touches.** `Builder::vertex` 112836 → 25452 calls, `Builder::face` 19994 (≈2× over-emission) → 10324 on a 370-cell bin. Emitting each blend patch through `face_from` off the stack rather than `Loop`/`face` (which heap-allocated three `Vec`s per patch) took a 1476-cell blend 19.4 → 12.2 ms.
- **`region2d` rejects segment pairs on bounding boxes** before the exact solve, and `island_clears` asks `loops_within` instead of minimising with `min_loop_distance`. That function 3.96 ms → 64 µs on a 660-cell bin; `plan_piece` 11.7 → 4.8 ms. These sweeps were the last quadratics in the pipeline.
- **Tessellator**: `u`-dependent trig hoisted out of the inner loop, four duplicated `project` calls per grid face removed, one weld key per boundary point instead of three per triangle, pre-sized output buffer. 16.2 → 12.4 ms on a 660-cell bin.

No superlinear cost remains. Everything scales linearly or better with cell count; items above `plan_piece` in the profile grow only through more compartments = more calls, not more work per call.

**Measure with `tess_bench`/`build_bench`, never a single rebuild.** This machine's single-shot spread is ±30% — wide enough to hide a 10% change and to invent one. Two of the tessellator changes above were first recorded as null results on single-shot evidence; best-of-25 resolves them as ~1.08×. **Always A/B by alternating** stash/unstash within one session, several rounds: a single before/after pair here drifts enough to invent a 2.5 ms improvement that alternating shows to be 0.5 ms.

**Scalar micro-optimisation in `tess` is exhausted.** Three plausible ones measured flat against `tess_bench` because LLVM already hoists them: a `Curve::prepare` mirroring `Surface::prepare` (the per-sample `radial_frame` is loop-invariant), hoisting the four `EdgeSamples` slices out of `tess_grid_face`'s grid fill, and batching `copy_face` into one `memcpy` per run of untouched faces (1.8% at 1476 cells, and it would have made `Solid` promise that a face's loops are contiguous *and* that faces' loop ranges are ordered — not part of its contract, a trap for any future operator emitting faces out of order). What remains is memory traffic: the boundary-sample gather and writing 120724 × 72-byte `Tri`s (~8.7 MB). The next real gain is the output format, not the arithmetic.

**`plan_piece` was investigated and left alone.** At 1476 cells: `pegemit` 3.7 ms / `stitch_loops_2d` 3.9 ms / peg profiles 1.3 ms / outer+cavity 2.2 ms. Removing the loop clones in `stitch_loops_2d` and moving sketch names into their `Op::Sketch` both measured *neutral* — a few hundred bytes each, under noise. Keying `Program`'s `sketches` map by step index instead of storing a second copy made planning slightly cheaper and the **whole build ~3 ms slower**, because `Program::sketch` then chases into the large `steps` vec on every loft lookup during `run`; reverted. Only real cost found is the ~5 per-cell `format!` labels, ~1 ms of 11.9 (consistent across four alternating rounds) — display-only text the construction debugger needs, and removing the per-label allocation means giving `Program` a string arena and changing `Step`'s API for ~1.6% of a rebuild. Not taken.

### The allocator is the thing to watch, not the allocation sites

A 1476-cell rebuild makes **132794 allocations / 187 MB of churn**, averaging ~1.4 kB. On Windows' `System` allocator that was ~12.5 ms of a ~118 ms rebuild, and the expensive half was **free**, not `malloc` (13.4 ms vs 7.7 ms measured inside the allocator). Wrapping **mimalloc** in the binary's `CountingAlloc` took a 1476-cell build 69.5 → 44.9 ms and tessellation 12.8 → 9.6 ms, three runs of three — one line, and by a wide margin the largest single win in this file's history.

**Chasing individual allocation sites here is not worth it.** `plan: peg loop` alone makes 69474 of those allocations (47 per cell, over half the total), and every targeted fix that removed hundreds measured flat. The count is spread thin across `Vec<Seg>` loops, sketch wrappers and label `String`s, none a hotspot. `alloc_report` (`SCALE_WH=48x48 cargo test -p gridfinity-model alloc_report -- --nocapture`) prints the per-scope table — use it to confirm churn has not regressed, not to hunt sites.

`perf_counters_see_a_real_build` needs an inner wall that *crosses* the compartment boundary. With box rejection in place a free-standing wall yields no crossing pair at all, so `seg_seg_points` legitimately never gets called and the metric never fires.
